## 3. ファイル別の具体差分

### SKILL.md

工程3へ次の判断だけを追加する。

- 低評価を本文の深刻度・確認状況・業種リスクでL1〜L4へ分ける。
- 明確な不備は、対象を示した直接謝罪を使う。
- 「真摯」を使うなら、見直す対象と確認・改善行動を続ける。
- 低評価は原則、意見への感謝または確認済み窓口で閉じる。
- 責任者、共有、点検、改善済みは確認済み材料だけに限定する。

工程4へ次の検査を追加する。

- 不自然な「機会」「日」の歓迎締めがない。
- 「申し訳なく思っております」で直接謝罪を代用していない。
- 「真摯」だけで終わらず、対象と行動がある。
- 「時間」「勇気」等の内部背景を公開文へ漏らしていない。
- 第三者に対し、問題の軽視、反論、架空対応、自己宣伝に見えない。

### reply-rules.md

既存の順序を壊さず、以下の節を追加または補強する。

1. 自然な日本語と不自然な言い換え
2. 低評価severity matrix
3. 謝罪の直接性
4. 真摯な受け止めの後続要件
5. 具体的改善の条件
6. 低評価の感謝
7. 背景理解と公開文言の分離
8. 公開上の安心形成

既存冒頭の「評価へ時間を割いた投稿者」は、意味を失わず「評価・意見を寄せた投稿者」へ改める。時間への感謝を定型化しない。

### evidence.md

出典カードを増やすこと自体を目的にしない。追加または再分類する場合は次を明記する。

| MHLW | 医療広告の最新版確認先 | 個別GBP返信への法的適用断定 |
| HHS | 口コミ返信で患者情報を開示した米国処分例 | HIPAAの日本直接適用 |

## 6. 適用順序

1. 現行版とExcel・clientの差分監査を確定する。
2. iteration-3のold_skill基準値を保存する。
3. candidate-skillとcandidate-clientだけを実装担当が編集する。
4. 同じ34ケースをcandidateへ実行する。
5. 実装担当と別の採点担当が比較する。
6. 独立QAとskill-checker全項目を実施する。
7. 統括が差分、比較、QA、4承認事項をユーザーへ提示する。
8. ユーザー承認後に共通スキルの戻しポイントを作り、本番へ反映する。
9. client変更は共通スキルと別変更単位で反映する。
10. 本番反映後に回帰、skill-checker、Git差分、hashを再確認する。
