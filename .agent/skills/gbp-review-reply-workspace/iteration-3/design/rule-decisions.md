## 3. 判断原則

```text
自然さ > 表現の珍しさ
```

```text
具体性は本文で示す。
感謝は締めで素直に伝える。
```

```text
低評価は謝罪語だけで終えない。
深刻度、受け止め、実行可能な行動、意見への敬意を分けて確認する。
```

```text
安心や信頼を自己宣伝しない。
対応内容そのもので、公開文を読む第三者の不安を減らす。
```

上位の事実性・安全性を、自然さ、温度、歓迎、改善表現のために壊さない。責任者、共有先、窓口、研修、点検、改善済み事実は、実在と実行意向を確認できた場合だけ使う。

## 5. A: 自然な日本語の具体境界

### 飲食の標準歓迎

第一候補:

```text
またのご来店をお待ちしております。
```

温度の高い詳細な高評価等では次を使える。

```text
またのご来店を心よりお待ちしております。
```

次も自然な選択肢として使えるが、違う表現にする目的で交互使用しない。

```text
またのお越しをお待ちしております。
```

標準締めは、同じバッチで文脈に合えば連続使用してよい。個別性は口コミ固有点、店側の反応、文の有無で出す。頻度だけを理由に言い換えない。

### confirmed-ngの歓迎締め

```text
またお迎えできる機会を、心よりお待ちしております。
またお越しいただける日を、心よりお待ちしております。
またお食事を楽しんでいただける機会を、心よりお待ちしております。
またお迎えできる日を、心よりお待ちしております。
```

理由は、バリエーションを作るための抽象名詞化、作文調、一般飲食店の接客会話としての不自然さである。

### 冷淡な終止

次の表現は語そのものを全面禁止しないが、肯定的な口コミへの返信をこれだけで終えない。

```text
拝見しました。
確認しました。
触れてくださいました。
ありがたく拝見しました。
```

使用する場合も、相手への感謝、店側の自然な反応、今後の姿勢、歓迎のいずれかへつなぐ。受領報告は返信の最終機能にならない。

### 地域文脈

`京都駅にお越しの際は、またお立ち寄りいただけますと幸いです。` は、一般的な歓迎とは分離し、regional/promotional CTAとして扱う候補とする。鰻profileでは本iterationの候補版で `pending-user-reapproval` とし、ユーザーの再承認なしに現役標準へ残さない。

## 6. B: 低評価severityと責任対応

severityは星数だけでなく、本文の被害、明確な不備、複数工程、衛生・安全、事実確認状況、業種リスクで決める。

| レベル | 典型状況 | 謝罪 | 受け止め・行動 | 締め・制約 |
|:---|:---|:---|:---|:---|
| L1 軽微・主観的 | 小さな不便、好みに近い不満、軽い待ち | 必要な場合だけ直接謝罪。過剰に重大事故扱いしない | 論点を受け止め、確認対象を1つ | 文脈に合えば「率直なご意見」への感謝 |
| L2 明確な不備 | 長い待ち、説明不足、明確な接客不備 | 原則「誠に申し訳ございませんでした」 | 何について謝るかを明示し、見直す対象と行動を示す | 「貴重なご意見」への感謝。再来店営業で上書きしない |
| L3 重大・複数不備 | 注文放置、声掛け後も未対応、衛生・安全、複数工程の失敗 | 深刻度に応じ「心よりお詫び申し上げます」 | 問題全体を認識し、確認済みの共有先・対象・行動だけを書く | 再来店誘導なし。「貴重なご意見」への感謝 |
| L4 高リスク・未確認 | 医療、士業、費用、契約、個人情報、事実争い | 不安・不満は受け止めるが、未確認事実や過失を認めすぎない | 守秘・プライバシー優先。profileに確認済み窓口がある場合だけ非公開確認 | no-replyまたは中立返信も選択肢。詳細を公開しない |

### 謝罪の直接性

明確な不備に対する顧客対応で、次を原則使わない。

```text
申し訳なく思っております。
```

これは話者の内心説明であり、相手への直接謝罪を弱める。確認済みの明確な不備では、深刻度に応じて次を使う。

```text
申し訳ございません。
誠に申し訳ございませんでした。
心よりお詫び申し上げます。
```

謝罪の強度と事実認定を混同しない。L4や未確認案件では、直接謝罪を置くために過失を捏造しない。

### 「真摯」の後続要件

```text
真摯に受け止めております。
```

だけで終えない。同じ返信内で最低限、次の2点を示す。

1. 見直す対象
2. 実施する確認または改善行動

共有先・責任主体は、実在と実行意向が確認済みの場合だけ追加する。機械的に「責任者」と書かず、未確認の研修、処分、制度変更を作らない。

### 低評価の感謝

標準候補:

```text
貴重なご意見をお寄せくださり、ありがとうございました。
```

文脈により使用:

```text
率直なご意見をお寄せくださり、ありがとうございました。
```

limited-use:

```text
具体的な状況をお知らせくださり、ありがとうございました。
```

最後の表現は、個別確認で追加経緯を提供してもらった場合など、詳細提供そのものへ謝意を伝える時だけ使う。通常GBP締めの標準にはしない。

confirmed-ng:

```text
貴重なお時間を割いて
勇気をもってご指摘くださり
大切なお時間を使って
```

「時間を使った」「心理的負担があり得る」は内部理解であり、公開文へ漏らさない。確認できる意見、指摘、投稿行為だけに感謝する。

### 公開上の安心形成

低評価返信は宣伝ではない。ただし第三者が読んだ時、対応内容から次が分かる必要がある。

- 問題を軽視していない
- 投稿者へ反論していない
- 改善対象を理解している
- 実行可能な確認・改善を行う
- 同様の問題への不安が下がる

「当店は安心です」「誠実な店です」「信頼してください」のような自己宣伝は禁止する。

## 7. C: 例文と境界の状態管理

- A35は、詳細高評価から2点へ絞る `active-conditional` の境界として維持候補。
- A36は、投稿済み事実と本文を保持するが、最新基準では直接謝罪と意見への感謝が不足する。ユーザー承認後に `historical` へ降格し、現役模倣元から外すことを推奨する。

- Excel候補30件は、個別選定後も現行ルール、profile、業種安全、旧版比較で再審査してから昇格を判断する。

## 11. 矛盾・要注意点

1. `評価基準!B7` の「時間・言葉・具体点へ感謝」と `温度設計!A7/B7` の労力・時間説明は、公開NGの「貴重なお時間を割いて」と混線する。実装時は「記述内容・具体点への感謝」に改め、時間を公開文へ出さない。
2. `温度設計!A18:D18` は「またのご来店を心より…」を「弱い歓迎」とするが、実際は温度を強める表現である。このラベルをコピーしない。
3. `ルール改訂案!E9` は対象・共有・行動のうち2点だが、今回の確定条件は「見直す対象+確認・改善行動」である。共有先は確認時だけ使う。
4. `低評価設計!D8/G8` と候補返信の「責任者」は、未確認の責任主体を作る危険がある。一般ルールへ固定しない。
5. 候補C10の「ご期待に沿えなかった可能性」は、星1本文なしの原因推測に寄る。候補状態のままとする。
6. 候補C02/C04等の安心・事前説明、候補R03の「一つひとつ気に入った」、各候補の責任者・窓口は、入力またはprofileで確認できなければ使えない。
7. 現行 `reply-rules.md` と `changelog.md` の「評価へ時間を割いた」は、公開文への漏入を誘発した。履歴は削除せず、現役説明を「評価・意見を寄せた投稿者」に変え、iteration-3追補でsupersededを明記する。
8. `出典監査!H8〜H15` の運用記事・テンプレ集から新しい規則を採る場合は、その箇所の原文を再確認する。候補30件のN/O列URLは全文候補の権威付けに使わない。
