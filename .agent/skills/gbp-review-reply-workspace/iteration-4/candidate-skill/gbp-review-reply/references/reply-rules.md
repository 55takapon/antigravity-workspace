# 口コミ返信ルール

## 目的

このファイルは、全文例より先に適用する共通安全核と、例を選ぶための最小分岐だけを定義する。自然な日本語、文のつながり、感謝、締め方は、該当する確認済み全文例とclient profileから学ぶ。語句の珍しさや禁止項目の多さを品質としない。

## 最小安全核K1〜K6

| ID | 共通ルール | 不合格となる結果 |
|:---|:---|:---|
| K1 | 口コミにない事実・感情・効果を作らず、明記された評価・感情の強度も上げない | 体験、内心、満足、原因を補う。曖昧語を正負どちらかへ変える。原文より強く言う |
| K2 | センシティブ情報を反復・拡張しない。利用・受診・治療の一般語は口コミ本人が公開文に明記した範囲だけを扱い、口コミにない関係を追加しない。症状、効果、診断、処置、具体的受診情報は反復しない | 口コミにない利用・受診・治療関係を追加する。センシティブ情報や効果・結果、具体的な症状・処置を反復・保証する |
| K3 | 未確認の原因、責任主体、共有、研修、点検、改善、対応済み事実を断定しない | 実在・実行意向・時制を確認せず、行動を約束または完了扱いする |
| K4 | 反論、言い訳、責任転嫁、口コミの変更・削除、星変更、見返りを要求しない | 投稿者と公開で争う。特典と評価を結びつける |
| K5 | profile未許可の販促CTA、SEO、地域名、店名、別商品、固定フッターを足さない | knowledgeや外部記事の販促情報を口コミと無関係に追加する |
| K6 | 返信済み状態と公開リスクを無視しない | 二重返信する。公開前確認が必要な高リスク案件を通常案件として断定する |

下位のprofile、業種ルール、全文例、過去承認文はK1〜K6を上書きできない。

## 生成前に整理する項目

通常は内部で次だけを整理し、ユーザーへ分類名を表示しない。

- 本文あり/なし、評価帯、返信済み状態
- 口コミに明記された事実、項目別の肯定・不満・不明
- 原文の評価・感情の強さ
- 個人情報、医療・法務・契約、事実争い等の公開リスク
- client profileのvoice、締め、販促、外国語、窓口、staff-sharing、knowledge参照条件

## 軽量router

1. [../examples/case-index.md](../examples/case-index.md)を読む。
2. 次の1カテゴリだけを選ぶ。

| 条件 | 参照先 |
|:---|:---|
| 本文なし | `../examples/star-only.md` |
| 短い肯定本文 | `../examples/positive-short.md` |
| 情報量の多い肯定本文 | `../examples/positive-detailed.md` |
| 肯定と不満の混合、または低評価 | `../examples/mixed-low-rating.md` |
| 医療・福祉・美容施術、士業、BtoB、外国語、事実争い等 | `../examples/high-risk-special.md` |

3. カテゴリ内で入力条件が近い例を最大2〜3件だけ読む。26件全読込、別カテゴリの総当たり、表現差のための例追加をしない。
4. 適用条件が合わない例は使わない。近い例がなくてもK1〜K6とprofileだけで作れる場合は、無理に例を当てない。
5. 例の全文コピーを目的にせず、拾う焦点、文の役割、温度、完結方法を参考にする。
6. A35は`router-eligible: false`のためユーザー確認まで参照しない。W10・W11は`confirmed-good`として通常参照できるが、各例の適用条件・不適用条件とK1〜K6を守る。

- `positive-short`の確認済み例に店側の方針文が含まれていても、その方針がclient profileで確認できる場合だけ転用する。profileに同方針の提示がなければ、口コミに明記された肯定点への感謝と、許可済みの標準歓迎だけで完結させる。
- 高リスクでは公開範囲を絞るが、公開可能な主要論点まで消さない。投稿者が明記した複数の懸念は、事実認定にならない「〜についてのご懸念」「〜とのご指摘」等で必要十分に受け止める。

## profileと業種の境界

- 共通skillへクライアント固有の名称、地域、商品、窓口、固定文、voiceを持ち込まない。
- profileがない時は丁寧で簡潔にし、販促CTA・SEO・地域名・未確認窓口を使わない。
- 接客上の自然な歓迎は販促CTAと同一視しない。使用可否と強さは、業種、評価内容、profile、active例で判断する。
- 飲食・宿泊・一般サービスは、本文にある料理、接客、設備等の公開可能な主要点を選べる。
- 医療・福祉・美容施術では、症状、診断、処置、担当者、効果を反復しない。利用・受診・治療の一般語は、口コミ本人が公開文に明記した範囲に限り扱い、口コミにない関係を追加しない。
- 士業・金融・BtoBでは、相談・依頼・契約の成立、条項、具体的金額、案件、相手方、成果、顧客名を事業者側から確認・反復しない。ただし、投稿者が公開した「費用」と「契約時の説明」等の主要な懸念は、請求・契約・過失を認定せず、抽象化して両方受け止める。守秘を理由に「費用」だけへ縮めたり、説明への懸念を脱落させたりしない。
- 外国語はprofileを優先し、安全に書ける場合は原文言語だけで返す。参考訳や内部説明は通常出力へ付けない。

## 低評価と対応行動

- 星数だけで自動謝罪しない。本文の論点、確認状況、被害・安全性、業種リスクに合わせる。
- 主観評価や未確認事項は、投稿者の評価として受け止め、断定可能な確認・見直しだけを書く。
- 明確な不備へお詫びする場合は対象を具体的にする。謝罪語だけで責任対応を終えない。
- 「冷たく感じた」等の主観評価と、「質問の途中で話を遮られた」「案内がなかった」「清掃が行き届いていなかった」等の具体的行為・状態が明記された不備を区別する。後者は謝罪を機械必須にはしないが、profile、確認状況、深刻度に合う時は、対象を明示した「お詫び申し上げます」「心よりお詫び申し上げます」等を選び、受け止めだけで終えない。「申し訳ございません」系列へは戻さない。
- W05-LAは主観的な接客印象の受け止め方を参照する例である。具体的な接客不備にはW05だけを当てず、対象明示のお詫びと確認・見直しの役割参考としてW04-LWまたはW09-LHも候補にできる。ただし各例の固有事実・業種を移植しない。
- 衛生・安全、複数不備、事実争い、高リスク内容は、通常案件より公開範囲と事実確認を優先する。
- 再来店営業や褒め言葉で不満を上書きしない。

## staff-sharing

profileの `staff-sharing` は次のいずれかで管理する。

| 値 | 扱い |
|:---|:---|
| `allowed` | 実在する共有先と実行意向があり、公開可能な範囲で共有を述べられる |
| `disallowed` | 共有表現を使わず、事業者本人の確認・見直し等で表す |
| `conditional` | 論点、privacy、共有範囲、実行可能性等のprofile条件を満たす時だけ使う |
| `unknown` | 勝手に共有を断定しない。共有の有無が返信を左右する時だけ確認用2案を示す |

- `unknown`または案件判断が分かれる時だけ、共有あり/なしの2案を示せる。選択後はprofileへ保存し、通常1案へ戻す。
- 「共有しました」は共有済み確認がある時だけ使い、これから行うなら未来時制にする。
- 単独事業者や共有先が存在しない場合は、スタッフ・チーム共有を書かない。
- 医療、福祉、士業、BtoBでは、共有表現を使っても機微情報を公開返信へ反復しない。
- 共有先の実在、必要性、実行可能性が不明なら、共有なしで成立する返信を優先する。

## 情報量と完結性

- 文字数の最低値や固定3段構成を設けない。
- 星だけでは体験や原因を補わず、該当する星だけ例とprofileで自然に完結させる。
- 短文は焦点を増やさず、詳細文でも全要素を列挙しない。
- 感謝、受け止め、固有点、姿勢、案内、締めのうち、入力に必要な機能だけを使う。
- 受領報告や店側感情だけで返信を終えず、例の完結方法を参照する。
- 標準的な自然表現は文脈に合えば繰り返せる。違う言葉を使うためだけに不自然な言い換えを作らない。

## 返信済み・修正・出力

- 返信済みで修正・状況変化による追記依頼がなければ、G06-RPとして新規返信を作らない。
- 修正時は直前案へ局所パッチせず、元の口コミ、現行profile、確定指摘から全文を作り直す。
- 通常は投稿可能な最終返信案だけを出す。内部分類、参照ID、調整意図、自己チェック、記録テンプレを表示しない。
- 事実確認・公開前確認・規約報告が必要な時だけ、返信本文と分けた短い注意メモを出す。

## 最終検査

1. K1〜K6違反がない。
2. profileと業種の公開範囲に合う。
3. 参照例は最大3件で、適用条件に合う。
4. 役割のない文、機械的な水増し、販促漏入がない。
5. 通常出力が最終返信案だけである。

公式・行政・研究・運用記事の根拠は [evidence.md](evidence.md) で管理する。phrase-levelの確定履歴は [../examples/quality-boundaries.md](../examples/quality-boundaries.md) に保持するが、通常生成で必読しない。
