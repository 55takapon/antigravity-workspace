# GBP口コミ返信

口コミ主へ感謝や受け止めを自然に返し、第三者が読んでも違和感のない公開返信を作る。禁止語の列挙ではなく、最小安全核を先に固定し、該当する確認済み全文例だけを少数参照する。

## 作業手順

- [ ] **1. 入力と参照範囲を確定する**
  - 入力: 星評価、口コミ本文、業種、返信済み状態、既存返信、特定できるクライアント。
  - 操作: クライアントが特定できる時は `clients\<client>\gbp-review\profile.md` と、`log.md` の `posted` / `final_approved` 直近5件を読む。knowledgeはprofileが許可した節だけに限定する。
  - 完了条件: 使用できる材料、profile制約、返信済み状態が確定している。返信済みで修正・追記依頼がなければ、新規返信を作らない。

- [ ] **2. 最小安全核K1〜K6を確定する**
  - 必ず [references/reply-rules.md](references/reply-rules.md) のK1〜K6を先に適用する。
  - K1: 口コミにない事実・感情・効果を作らず、評価・感情の強度を上げない。
  - K2: 個人情報、診療、相談、契約情報を反復・拡張しない。
  - K3: 未確認の原因、改善、共有、対応済み事実を断定しない。
  - K4: 反論、責任転嫁、評価変更・削除・見返り要求をしない。
  - K5: profile未許可の販促、SEO、地域名、別商品を足さない。
  - K6: 返信済み状態と公開リスクを無視しない。
  - 完了条件: 触れられる事実、強度の上限、公開しない情報、実行可能な対応が確定している。

- [ ] **3. 軽量routerで該当例だけを選ぶ**
  - [examples/case-index.md](examples/case-index.md) で `star-only / positive-short / positive-detailed / mixed-low-rating / high-risk-special` の1カテゴリを選ぶ。装飾的なスタイル名は付けない。
  - 選んだカテゴリファイルのうち、本文量、評価帯、業種、論点、risk、profile条件が近いIDを最大2〜3件だけ読む。全26例の一括読込を禁止する。
  - 例は語句のコピーテンプレートではなく、焦点、文の役割、温度、完結方法の参考にする。例とK1〜K6が衝突する場合は必ずK1〜K6を優先する。
  - G06-RPは全文例ではなく工程制御であり、返信済みなら生成を停止する。
  - 完了条件: 参照IDが0〜3件に絞られ、適用条件・不適用条件とprofileが一致している。

- [ ] **4. 返信を生成し、全文検査して提出する**
  - 口コミの情報量に合わせ、感謝または受け止め、固有点への反応、必要な姿勢・案内・締めを自然につなぐ。全要素を毎回埋めない。
  - 通常は投稿可能な最終返信案1つだけを出す。複数口コミは番号対応する。重要な意味差の判断が必要な場合だけ代替案を出す。
  - staff-sharingが`unknown`、または案件ごとに共有の適否が分かれる時だけ、共有あり/なしの2案をクライアント確認用に示せる。選択後はprofileへ方針を保存し、以後は通常1案に戻す。
  - K1〜K6、profile、参照例の不適用条件を全文検査する。事実確認・公開前確認・規約報告が必要な時だけ、返信本文と分けた短い注意メモを付ける。
  - 完了条件: そのまま投稿でき、役割のない文や機械的な水増しがなく、K1〜K6違反が0件である。

- [ ] **5. 修正と確定結果を処理する**
  - 修正時は `元の口コミ + 現行profile + 確定済み指摘` から全文を再構成し、工程2〜4をやり直す。
  - 採用・修正・不採用・投稿済みの結果が分かった時だけ [references/feedback-loop.md](references/feedback-loop.md) を読み、client `log.md` へ記録する。未確定結果や承認状態を作らない。
  - 完了条件: 修正版も全検査済みで、結果連絡がある場合だけ状態を正しく記録している。

## 出力

- 通常: 最終返信案だけ。
- 複数件: 番号 + 各最終返信案。
- 返信済み: 新規返信を作らず、その旨を短く伝える。
- 公開前確認が必要: 最終返信案と分けて、確認対象を1〜2文で示す。

## 完了確認

- K1〜K6を例より先に適用し、例で上書きしていない。
- 該当例の参照が最大3件で、全例を読んでいない。
- profile、業種リスク、返信済み状態を反映した。
- 通常出力が投稿可能な最終返信案だけになっている。
- 修正時は全文再構成し、結果未確定ならlogへ記録していない。

変更履歴は [references/changelog.md](references/changelog.md) に分離する。
