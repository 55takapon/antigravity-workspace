# 口コミ返信ルール

## 目的と優先順位

返信は事業者名義で公開され、口コミ主以外の第三者にも読まれる。文章の巧さや販促性より、事実性、評価強度、安全性、情報量との一致を優先する。同時に、評価や意見を寄せた投稿者へ感謝を返す接客であり、店側の感情や受領報告だけで終えてはならない。投稿に時間や勇気を要したという内部理解を、確認できない公開文へ変換しない。

判断順序は次のとおり。下位条件のために上位条件を壊さない。

1. 口コミ本文に明記された事実
2. 項目ごとの評価と感情の強さ
3. 個人情報、法規、規約、公開リスク
4. クライアント `profile.md`
5. 業種別ルール
6. `posted` / `final_approved` の最終返信との自然な重複確認
7. profileで検証済みの名称・地域文脈。SEO・販促は原則使わない

公開記事の例文はコピーせず、判断境界だけを使う。根拠資料は [evidence.md](evidence.md) を参照する。通常生成では全文例台帳の [../examples/approved-replies.md](../examples/approved-replies.md) と `good-output.md` を読まない。採用・不採用結果を記録する時、またはユーザーが実例や例の状態確認を明示的に求めた時だけ必要箇所を参照する。

## 生成前の内部整理

次だけを内部で整理し、通常はユーザーへ表示しない。

| 項目 | 整理内容 |
|:---|:---|
| 本文 | あり / なし |
| 評価帯 | 高評価 / 混合・中立 / 低評価。星数だけで本文の不満を上書きしない |
| 明記事実 | 口コミに書かれた対象、出来事、数値、感想 |
| 項目別評価 | 肯定 / 中立 / 不満 / 不明。曖昧なら不明のまま |
| 強さ | 原文の形容詞・副詞を越えない上限 |
| 禁止する推測 | 来店内容、内心、原因、担当者、対応状況など本文から確定できないもの |
| 公開リスク | 個人情報、医療・法務・契約、効果保証、規約違反疑い |
| 状態 | 未返信 / 返信済み / 修正依頼あり |
| profile制約 | トーン、長さ傾向、販促CTA、接客上の締め、地域文脈、SEO、外国語、窓口、knowledge参照範囲 |

事業者側の感情も自動では足さない。「嬉しい」「励みになる」「スタッフ一同」は、口コミの温度とprofileに合い、別の文と機能重複しない場合だけ使う。評価の受領報告や店側感情だけで返信を終えず、評価帯に応じた歓迎または姿勢まで含めて公開返信として成立させる。

## 情報量に合わせる

基本形は次の3要素だが、すべて埋める必要はない。

```text
感謝または受け止め
+ 口コミ固有点への反応
+ 必要な場合だけ締めを0〜1個
```

| 入力 | 既定の作り方 |
|:---|:---|
| ★5・本文なし | 評価行為への十分な感謝1文 + 接客上の自然な歓迎1文。体験や満足を補わない |
| ★4・本文なし | 評価行為への十分な感謝1文 + より満足してもらえるよう努める姿勢1文。原因推測や謝罪をしない |
| 星だけ低評価 | 原因や失敗事実を推測せず、評価を受け止める短い1文を基本にする |
| 一言の高評価 | 感謝と固有点1つ + 自然な歓迎締め。販促へ広げない |
| ★5・肯定的な本文あり | 主要点1つ、必要なら副題1つ + 自然な歓迎締めを原則入れる |
| ★4・肯定的な本文あり | 感謝だけで切らず、本文の温度と改善余地に応じて自然な歓迎締めまたは節度ある改善姿勢を選ぶ |
| 詳細な高評価 | 最大2テーマ + 自然な歓迎締め。全要素を逐語的に言い直さない |
| 良い点と不満の混合 | 良い点だけを拾わず、不満・要望を同等以上の明瞭さで受け止める |
| 明確な低評価 | 論点の受け止め、必要な確認・対応姿勢。反論や再来店営業で上書きしない |

文字数の最低値は設けない。ただし★5・★4の本文なしは受領通知のような1文で終えず、上表の2機能を2文で示す。本文ありは全枠を機械的に埋めず、詳細でも焦点を最大2つに絞る。

星と本文が食い違う時は、星から全体感情を推測せず、本文の項目別評価を優先する。「量が多かった」のように正負が不明な表現を、「食べ応えがあった」「多すぎた」のどちらにも変換しない。

## 自然な日本語と不自然な言い換え

自然さを表現の珍しさより優先する。飲食の標準候補は「またのご来店をお待ちしております。」とし、温度の高い詳細な高評価では「心より」を加えられる。「またのお越しをお待ちしております。」も使えるが、差別化目的で交互使用しない。

次は抽象名詞化した作文調の締めであり、生成案に使わない。

- またお迎えできる機会を、心よりお待ちしております。
- またお越しいただける日を、心よりお待ちしております。
- またお食事を楽しんでいただける機会を、心よりお待ちしております。
- またお迎えできる日を、心よりお待ちしております。

「拝見しました」「確認しました」「触れてくださいました」「ありがたく拝見しました」は全面禁止語ではないが、肯定的な返信を受領報告だけで終えない。使うなら、相手への感謝、自然な反応、今後の姿勢、歓迎のいずれかへつなぐ。

## ハードエラー

次を1つでも含む案は不合格。言い換えで隠さず、該当箇所を削るか全文を組み直す。

- 口コミにない事実、体験、原因、対応済み事実の追加
- 原文より強い形容・感情への水増し
- 投稿者の内心、満足、様子、意図の推測
- 曖昧な表現の肯定・不満への勝手な変換
- knowledgeにあるだけのSEO、固定フッター、競合分析、重点商品、ブランド表現の追加
- 星だけレビューへの利用内容、来店日時、接客、商品、症状等の補充
- 感謝、反応、対応、必要な案内のどれでもない空虚文
- 再来店の約束化、念押し、同伴形態・利用場面の指定
- コメントを書かなかったことへの言及
- 個人情報、診療・相談・契約関係、効果・成果の再掲・拡張・保証
- 低評価への長文反論、言い訳、責任転嫁
- 口コミの修正、削除、星変更、見返りの要求
- 同じ機能の文、同じ意味の感謝・姿勢・締めの重複
- ★4・★5を「うれしく思います」「励みになります」「ありがたく拝見しました」等の店側感情・受領報告だけで終えること
- 同時バッチで同一・ほぼ同形の感情文、または同じ感謝→感情→締め等の機能骨格を連続させること。ただし標準的な歓迎締めの自然な偶発重複だけでは不合格にしない
- 指摘箇所だけを継ぎ足し、全文の別箇所に回帰を残すこと

## クライアントprofileとknowledgeの境界

クライアントが特定できる時だけ `clients\<client>\gbp-review\profile.md` を読む。共通ルールにクライアント固有の名称、地域、メニュー、固定文、文体を持ち込まない。

profileで扱う項目:

- 正式名称、業種、返信者の立場
- トーン、敬語、絵文字、感嘆符、文数・長さの傾向
- CTA、店舗名・地域名・SEOの許可条件
- 「スタッフ一同」等の使用条件とクライアント固有NG
- 外国語返信方針、低評価時の確認窓口
- 参照可能なknowledgeファイルと節
- 再審査済みの実投稿例

knowledgeはprofileが許可した節だけを、必要な事実確認のために読む。投稿用SEO、固定フッター、競合分析、重点メニュー、販促上の強みは、口コミが触れているだけでは自動採用しない。共通ルールとprofileが衝突する場合、事実性・安全性・規約を優先する。

profileがない時は共通既定を使う。トーンは丁寧で簡潔、販促CTA・SEO・ブランド表現はOFF、未確認の窓口や署名は追加しない。一般的な接客上の締めは共通既定として使えるが、地域名入り締めは使わない。

## 販促CTA、接客上の歓迎締め、SEO

- 販促CTAとは、他商品・別メニュー、予約・購入、割引・キャンペーンの提案、来店の約束化、同伴者・同行形態や次回用途の指定を指す。口コミ返信では原則禁止する。表現を柔らかくしても販促性は消えない。
- 「またのご来店をお待ちしております」「またお立ち寄りいただけますと幸いです」等は、売り込みではなく感謝と歓迎を返す接客上の締めとして販促CTAと分ける。
- ★5の肯定的な本文では自然な歓迎締めを原則入れる。再来店意思が明記された時は好意を自然に受け止め、約束化、念押し、予約・商品への誘導を足さない。
- 肯定的な★4本文は、改善余地が読み取れない場合は感謝と自然な締め、改善余地が読み取れる場合は感謝と節度あるサービス向上姿勢を基本にする。
- ★5本文なしでは一般的な歓迎を使う。医療・法務等の高リスク業種では再訪・再相談を促さず、歓迎の代わりにサービス向上へ努める姿勢を置く。
- profileが検証済み地域名と使用条件を明示し、現在の状態が許可済みの場合だけ、肯定的な口コミで地域文脈付き締めを0〜1回使える。`pending-user-selection` / `pending-user-reapproval` は許可ではない。一般歓迎から分離し、自動SEO化、全件使用、地域名の反復を禁止する。
- 低評価では歓迎や販促で不満を上書きしない。個別確認が必要な場合だけ、profileに登録された非公開窓口を1つ示せる。
- SEOは既定OFF。返信文へのキーワード挿入を順位施策として扱わない。

## 重複管理

- `log.md` の `posted` または `final_approved` だけを対象に、直近5件の最終返信を確認する。draft、rejected、代替案、翻訳、参考訳、修正履歴は数えない。
- 同時バッチと直近finalを横断し、「大変うれしく思います」等の同一・ほぼ同形の感情文を連続使用しない。感謝→感情→締めの同じ機能構造も機械反復しない。
- 標準の歓迎締め自体は文脈に合えば連続使用してよい。頻度だけで言い換えず、焦点・文の役割・文の有無を調整する。
- 複数件では、各口コミの事実を混ぜず、番号対応を確認する。語彙を珍しくするためだけに大げさな表現へ変えない。

## 低評価severityと責任対応

severityは星数だけで決めず、本文の被害、明確な不備、複数工程、衛生・安全、事実確認状況、業種リスクで決める。低評価というだけで謝罪を自動挿入しない。基本は口コミの具体的論点を受け止める姿勢と、実行可能な確認・改善である。

| レベル | 典型状況 | 謝罪 | 対象・行動 | 締め・制約 |
|:---|:---|:---|:---|:---|
| L1 軽微・主観的 | 小さな不便、好みに近い不満、軽い待ち | 自動謝罪しない。明記された論点を受け止める | 論点と実行可能な確認対象を1つ | 文脈に合えば率直な意見への感謝 |
| L2 明確な不備 | 長い待ち、説明不足、明確な接客不備 | 事実確認後、必要な時だけ対象を示して「お詫び申し上げます」 | 見直す対象と確認・改善行動 | 貴重な意見への感謝。再来店営業で上書きしない |
| L3 重大・複数不備 | 注文放置、声掛け後も未対応、衛生・安全、複数工程の失敗 | 深刻度に応じ「心よりお詫び申し上げます」 | 問題全体を認識し、確認済みの共有先・対象・行動だけを書く | 再来店誘導なし。貴重な意見への感謝 |
| L4 高リスク・未確認 | 医療、士業、費用、契約、個人情報、事実争い | 自動謝罪せず、公開可能な具体的論点だけを受け止める | 守秘優先。profileに確認済み窓口がある時だけ非公開確認 | 中立返信またはno-replyも検討し、公開で詳細を求めない |

### 謝罪の条件とNG

謝罪は低評価へ自動挿入しない。主観的または未確認の論点は、具体的に受け止めて確認へ進める。明確で確認済みの不備に謝罪が必要な時だけ、対象を示して「お詫び申し上げます」または「心よりお詫び申し上げます」を使える。

confirmed-ngは「申し訳ございません」「誠に申し訳ございませんでした」「ご不快な思いをおかけし」「残念なお気持ちにさせてしまい」「ご不快な経験の中」とする。対象のない定型謝罪や、口コミにない感情・状態の補充を避ける。「申し訳なく思っております」も話者の内心説明になるため使わない。余分な店側感情文を足さない。

使用できる謝罪例:

- 「長くお待たせしましたことを、お詫び申し上げます。」
- 「当日の対応について、お詫び申し上げます。」
- 「ご注文品の提供が遅れ、お声がけにもすぐ対応できなかったことを、心よりお詫び申し上げます。」

### 受け止める姿勢と具体行動

「真摯に受け止めております」を定型必須にせず、口コミの論点と行動に合う自然なpatternを選ぶ。見直す対象と、実施する確認または改善行動を同じ返信内で明確にする。共有先・責任主体・窓口・研修・点検・制度変更・改善済み事実は、実在と実行意向を確認できた場合だけ書く。「改善に活かす」「努める」だけで具体行動の代わりにしない。

良好pattern:

- 「ご指摘を真摯に受け止め、提供までの流れを見直します。」
- 「今回のお声を受け、ご案内方法を改めて確認いたします。」
- 「いただいたご意見を踏まえ、提供前の確認を徹底してまいります。」
- 「ご指摘を重く受け止め、注文確認と対応手順を見直します。」

### 低評価の感謝

標準候補は「貴重なご意見をお寄せくださり、ありがとうございました。」とする。文脈に合えば「率直なご意見をお寄せくださり、ありがとうございました。」も使える。「具体的な状況をお知らせくださり、ありがとうございました。」は、個別確認で追加経緯を提供してもらった場合だけのlimited-useとし、通常のGBP締めにしない。

「貴重なお時間を割いて」「大切なお時間を使って」「勇気をもってご指摘くださり」は使わない。厳しい指摘に心理的負担があり得ることは内部姿勢として理解しても、投稿者の時間や心理を公開文で代弁しない。確認できる意見・指摘に感謝する。

### 公開上の安心形成

低評価返信は宣伝ではない。ただし第三者が読んだ時、対応内容から、問題を軽視せず、反論せず、改善対象を理解し、実行可能な確認・改善を行うことが分かるようにする。「当店は安心です」「誠実な店です」「信頼してください」と自己宣伝せず、対応内容そのもので不安を減らす。

## 業種別の追加ルール

共通ルールを先に適用し、必要な業種節だけ追加する。業種ルールは、触れてよい事実を増やす許可ではない。

### 医療・福祉・介護

- 氏名、家族関係、年齢、診断、症状、服薬、通院・利用、担当者、治療・支援内容を事業者側から確認しない。
- 投稿者が書いていても、センシティブ情報や個別の診療関係は反復しない。効果、改善、将来結果を喜ぶ・保証する表現を避ける。
- 一般的な評価への感謝とサービス向上へ努める姿勢で成立させる。再受診・再相談を促さず、個別対応が必要な時も公開返信で詳細を求めない。

### 飲食・宿泊

- 本文にある料理、客室、接客、設備、立地等から主要点を選べるが、来店・滞在日時、同行者、注文・宿泊内容を広げない。
- 味、量、清潔さ等の評価強度を上げない。低評価では好みの問題として矮小化しない。

### 美容・施術・ヘルスケア

- 本文にある説明や接客は拾えるが、施術、身体状態、来店履歴、担当者、効果を拡張しない。
- 効果実感を一般化せず、医療に近いセンシティブ情報は反復しない。

### 法律・税務・金融・士業

- 相談、受任、契約、金額、相手方、担当者、案件内容、結果を事業者側から確認しない。
- 成果、法的判断、節税、勝敗、解決を保証・一般化しない。一般的な評価や信頼への感謝に留める。
- 新たな相談・契約を促さず、一般的な感謝とサービス向上へ努める姿勢で成立させる。

### BtoB・専門サービス

- 顧客名、契約、案件、社内事情、数値、担当者、成果を公開しない。
- 具体情報を再掲せず、説明、対応、信頼など公開可能な評価軸だけを扱う。

### 店舗・小売・一般サービス

- 本文にある品揃え、案内、接客等を拾えるが、在庫、価格、保証、購入内容を追加しない。
- 曖昧な感想を販促上都合のよい意味に変えない。

## 低評価・返信済み・外国語

- 混合・低評価は不満・要望を先に明瞭に受け止める。確認できない原因を説明せず、既に調査・共有・改善した事実は、ユーザーが確認済み材料として与えた時だけ書く。
- 事実確認、公開前承認、規約違反報告が必要なら、返信本文と分けた短い注意メモを出す。注意メモを自己正当化の長文にしない。
- 返信済みは、ユーザーが修正または状況変化による追記を求めた場合だけ案を作る。それ以外は追加対応不要と短く伝える。
- 外国語レビューはprofileの方針を優先する。安全に書ける場合は原文言語のみで返し、日本語訳や内部説明を通常出力へ足さない。正確性に不安がある高リスク内容は公開前確認を促す。

## 修正時の全文再構成

修正指示を受けたら、直前案へ局所パッチを当てない。`元の口コミ + 現行profile + 確定済みの指摘` から全文を作り直し、このファイルの全検査を最初から行う。直前案にあった文は、再検査で必要と判断した場合だけ残す。

## 投稿前チェック

- 明記事実だけを使い、原文の評価強度を越えていない。
- 本文のない体験、曖昧な感情、原因、対応状況を補っていない。
- 情報量に合わない文と、役割のない文を削った。
- 混合評価の不満、低評価の論点を販促や褒め言葉で隠していない。
- 低評価のseverityと確認状況に対し、謝罪が自動・過剰・過少でなく、必要な場合だけ対象を示すお詫びを使っている。
- 具体的論点、見直す対象、実行可能な確認・改善が一致し、「真摯」を定型必須または空の姿勢文にしていない。
- 「時間」「勇気」等や、口コミにない感情・状態、余分な店側感情を公開文へ漏らさず、自己宣伝で安心を演出していない。
- 個人情報、医療・法務・契約情報を再掲・拡張していない。
- 販促CTAを入れず、歓迎締め・地域文脈・knowledgeの利用がprofileの許可範囲内である。
- ★5本文なしが誠実な感謝と自然な歓迎の2文、★4本文なしが誠実な感謝と節度ある改善姿勢の2文で、体験や原因を補っていない。
- ★4・★5を店側感情・受領報告だけで終えず、肯定的な★4本文では内容に合う締めまたは姿勢を選んだ。
- 同時バッチと直近の最終返信を横断し、同一感情文・同一機能骨格の連続反復を避け、強制的な類語置換をしていない。
- 返信済み状態と外国語方針を守った。
- 通常出力が投稿可能な最終返信案だけになっている。
