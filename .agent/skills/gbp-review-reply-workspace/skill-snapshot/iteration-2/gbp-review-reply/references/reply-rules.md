# 口コミ返信ルール

## 目的と優先順位

返信は事業者名義で公開され、口コミ主以外の第三者にも読まれる。文章の巧さや販促性より、事実性、評価強度、安全性、情報量との一致を優先する。

判断順序は次のとおり。下位条件のために上位条件を壊さない。

1. 口コミ本文に明記された事実
2. 項目ごとの評価と感情の強さ
3. 個人情報、法規、規約、公開リスク
4. クライアント `profile.md`
5. 業種別ルール
6. `posted` / `final_approved` の最終返信との自然な重複確認
7. ユーザーとprofileが明示的に許可したSEO・販促

公開記事の例文はコピーせず、判断境界だけを使う。根拠資料は [evidence.md](evidence.md)、実運用例の状態は [../examples/approved-replies.md](../examples/approved-replies.md) を参照する。

## 生成前の内部整理

次だけを内部で整理し、通常はユーザーへ表示しない。

| 項目 | 整理内容 |
|:---|:---|
| 本文 | あり / なし |
| 評価帯 | 高評価 / 混合・中立 / 低評価。星数だけで本文の不満を上書きしない |
| 明記事実 | 口コミに書かれた対象、出来事、数値、感想 |
| 項目別評価 | 肯定 / 中立 / 不満 / 不明。曖昧なら不明のまま |
| 強さ | 原文の形容詞・副詞を越えない上限 |
| 禁止する推測 | 来店内容、内心、原因、担当者、対応状況など本文から確定できないもの |
| 公開リスク | 個人情報、医療・法務・契約、効果保証、規約違反疑い |
| 状態 | 未返信 / 返信済み / 修正依頼あり |
| profile制約 | トーン、長さ傾向、CTA、SEO、外国語、窓口、knowledge参照範囲 |

事業者側の感情も自動では足さない。「嬉しい」「励みになる」「スタッフ一同」は、口コミの温度とprofileに合い、別の文と機能重複しない場合だけ使う。

## 情報量に合わせる

基本形は次の3要素だが、すべて埋める必要はない。

```text
感謝または受け止め
+ 口コミ固有点への反応
+ 必要な場合だけ締めを0〜1個
```

| 入力 | 既定の作り方 |
|:---|:---|
| 星だけ高評価 | 評価への短い感謝1文。第二文はprofileとユーザーが明示許可した場合のみ |
| 星だけ低評価 | 原因や失敗事実を推測せず、評価を受け止める短い1文を基本にする |
| 一言の高評価 | 1〜2文。感謝と固有点1つまで |
| 通常の高評価 | 2文前後。主要点1つ、必要なら副題1つ |
| 詳細な高評価 | 最大2テーマ。全要素の逐語的な言い直しをしない |
| 良い点と不満の混合 | 良い点だけを拾わず、不満・要望を同等以上の明瞭さで受け止める |
| 明確な低評価 | 論点の受け止め、必要な確認・対応姿勢。反論や再来店営業で上書きしない |

文字数の最低値は設けない。必要十分な1文を未完成扱いせず、感謝、固有点、姿勢、締めの枠を埋めるためだけの文を作らない。詳細口コミでも、1文に列挙しすぎず焦点を選ぶ。

星と本文が食い違う時は、星から全体感情を推測せず、本文の項目別評価を優先する。「量が多かった」のように正負が不明な表現を、「食べ応えがあった」「多すぎた」のどちらにも変換しない。

## ハードエラー

次を1つでも含む案は不合格。言い換えで隠さず、該当箇所を削るか全文を組み直す。

- 口コミにない事実、体験、原因、対応済み事実の追加
- 原文より強い形容・感情への水増し
- 投稿者の内心、満足、様子、意図の推測
- 曖昧な表現の肯定・不満への勝手な変換
- knowledgeにあるだけのSEO、固定フッター、競合分析、重点商品、ブランド表現の追加
- 星だけレビューへの利用内容、来店日時、接客、商品、症状等の補充
- 感謝、反応、対応、必要な案内のどれでもない空虚文
- 再来店の約束化、念押し、同伴形態・利用場面の指定
- コメントを書かなかったことへの言及
- 個人情報、診療・相談・契約関係、効果・成果の再掲・拡張・保証
- 低評価への長文反論、言い訳、責任転嫁
- 口コミの修正、削除、星変更、見返りの要求
- 同じ機能の文、同じ意味の感謝・姿勢・締めの重複
- 指摘箇所だけを継ぎ足し、全文の別箇所に回帰を残すこと

## クライアントprofileとknowledgeの境界

クライアントが特定できる時だけ `clients\<client>\gbp-review\profile.md` を読む。共通ルールにクライアント固有の名称、地域、メニュー、固定文、文体を持ち込まない。

profileで扱う項目:

- 正式名称、業種、返信者の立場
- トーン、敬語、絵文字、感嘆符、文数・長さの傾向
- CTA、店舗名・地域名・SEOの許可条件
- 「スタッフ一同」等の使用条件とクライアント固有NG
- 外国語返信方針、低評価時の確認窓口
- 参照可能なknowledgeファイルと節
- 再審査済みの実投稿例

knowledgeはprofileが許可した節だけを、必要な事実確認のために読む。投稿用SEO、固定フッター、競合分析、重点メニュー、販促上の強みは、口コミが触れているだけでは自動採用しない。共通ルールとprofileが衝突する場合、事実性・安全性・規約を優先する。

profileがない時は共通既定を使う。トーンは丁寧で簡潔、CTA・SEO・ブランド表現はOFF、未確認の窓口や署名は追加しない。

## CTAとSEO

- CTAは必須ではない。ユーザーが希望し、profileも許可する場合だけ0〜1個を検討する。
- 星だけ、短文、口コミ側に再来店意思がある時は、催促感を優先して原則省く。
- 低評価では営業CTAを使わない。個別確認が必要な場合だけ、profileに登録された非公開窓口を1つ示せる。
- SEOは既定OFF。ユーザーの明示希望とprofileの許可が両方ある場合だけ検討する。
- 星だけ、低評価、医療・福祉、法律・税務・金融の高リスク内容には原則入れない。
- 返信文中のキーワードが検索順位を直接上げるとは説明しない。

## 重複管理

- `log.md` の `posted` または `final_approved` だけを対象に、直近5件の最終返信を確認する。draft、rejected、代替案、翻訳、参考訳、修正履歴は数えない。
- 単語の違いではなく、冒頭、焦点、文の役割、締め、CTAが毎回同じ機能構造になっていないかを見る。
- 定型句の使用割合だけで強制的に類語へ変更しない。自然な同じ語は許容し、不要なら文ごと削る。
- 複数件では、各口コミの事実を混ぜず、番号対応を確認する。語彙を珍しくするためだけに大げさな表現へ変えない。

## 業種別の追加ルール

共通ルールを先に適用し、必要な業種節だけ追加する。業種ルールは、触れてよい事実を増やす許可ではない。

### 医療・福祉・介護

- 氏名、家族関係、年齢、診断、症状、服薬、通院・利用、担当者、治療・支援内容を事業者側から確認しない。
- 投稿者が書いていても、センシティブ情報や個別の診療関係は反復しない。効果、改善、将来結果を喜ぶ・保証する表現を避ける。
- 一般的な評価への感謝で成立させる。個別対応が必要な時も公開返信で詳細を求めない。

### 飲食・宿泊

- 本文にある料理、客室、接客、設備、立地等から主要点を選べるが、来店・滞在日時、同行者、注文・宿泊内容を広げない。
- 味、量、清潔さ等の評価強度を上げない。低評価では好みの問題として矮小化しない。

### 美容・施術・ヘルスケア

- 本文にある説明や接客は拾えるが、施術、身体状態、来店履歴、担当者、効果を拡張しない。
- 効果実感を一般化せず、医療に近いセンシティブ情報は反復しない。

### 法律・税務・金融・士業

- 相談、受任、契約、金額、相手方、担当者、案件内容、結果を事業者側から確認しない。
- 成果、法的判断、節税、勝敗、解決を保証・一般化しない。一般的な評価や信頼への感謝に留める。

### BtoB・専門サービス

- 顧客名、契約、案件、社内事情、数値、担当者、成果を公開しない。
- 具体情報を再掲せず、説明、対応、信頼など公開可能な評価軸だけを扱う。

### 店舗・小売・一般サービス

- 本文にある品揃え、案内、接客等を拾えるが、在庫、価格、保証、購入内容を追加しない。
- 曖昧な感想を販促上都合のよい意味に変えない。

## 低評価・返信済み・外国語

- 低評価は、確認できない原因を説明しない。既に調査・共有・改善した事実は、ユーザーが確認済み材料として与えた時だけ書く。
- 事実確認、公開前承認、規約違反報告が必要なら、返信本文と分けた短い注意メモを出す。注意メモを自己正当化の長文にしない。
- 返信済みは、ユーザーが修正または状況変化による追記を求めた場合だけ案を作る。それ以外は追加対応不要と短く伝える。
- 外国語レビューはprofileの方針を優先する。安全に書ける場合は原文言語のみで返し、日本語訳や内部説明を通常出力へ足さない。正確性に不安がある高リスク内容は公開前確認を促す。

## 修正時の全文再構成

修正指示を受けたら、直前案へ局所パッチを当てない。`元の口コミ + 現行profile + 確定済みの指摘` から全文を作り直し、このファイルの全検査を最初から行う。直前案にあった文は、再検査で必要と判断した場合だけ残す。

## 投稿前チェック

- 明記事実だけを使い、原文の評価強度を越えていない。
- 本文のない体験、曖昧な感情、原因、対応状況を補っていない。
- 情報量に合わない文と、役割のない文を削った。
- 混合評価の不満、低評価の論点を販促や褒め言葉で隠していない。
- 個人情報、医療・法務・契約情報を再掲・拡張していない。
- CTA・SEO・knowledgeの利用が、ユーザーとprofileの許可範囲内である。
- 重複確認の対象が最終返信だけで、強制的な類語置換をしていない。
- 返信済み状態と外国語方針を守った。
- 通常出力が投稿可能な最終返信案だけになっている。
