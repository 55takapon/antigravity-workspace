# GBP口コミ返信

Googleビジネスプロフィールに投稿された口コミへ、事業者名義で公開しても不自然でない返信文を作る。感謝、事実確認、改善姿勢、再来訪・相談導線を、口コミ本文の温度に合わせて短く整える。
共通の返信品質を基本にし、医療・福祉、飲食、店舗サービスなどの業種別ルールは追加条件として扱う。
GBP管理画面にAI返信候補が表示される場合や汎用AI文を使う場合との差別化として、同じ定型句を連続使用せず、口コミ本文固有の具体点と業種別の法規・個人情報リスクを踏まえて返信を組み立てる。

## 作業手順

- [ ] **入力を整理する**
   必ず口コミ本文、星評価、業種、店舗・事業所名、返信済みかどうか、SEO語・差別化ポイントを入れる希望の有無を確認すること。任意で、返信者の立場（院長、店長、スタッフ一同など）と直近の自店返信を受け取る。不足していても推測で個別事実を足さず、分かる範囲で作る。
   クライアントフォルダ、既存口コミ履歴、過去の返信案集が分かっている案件では、ユーザーに言われなくても必ず直前2件の自店返信を確認し、冒頭、感謝語、具体点の拾い方、締め、再来訪導線、文末表現の重複を把握すること。履歴ファイルを読めない場合だけ、その旨を短く伝えて手元情報で重複を避ける。
   返信済みの場合は、新規返信を重ねず、既存返信の修正版を作るのか、状況変化を反映した追記・再返信が必要なのかを先に判定する。単なる言い換えなら既存返信の編集案を出し、同内容の重複返信は作らない。
   入力: 口コミ本文、星評価、事業者情報。
   出力: 返信方針メモ。既存履歴がある案件では直前2件との重複回避メモも含める。
   完了条件: 高評価、低評価、星だけ、事実誤認、個人情報含みのどれに近いか、共通ルールだけでよいか業種別追加が必要かを判断した。既存履歴がある案件では、直前2件の返信と重なる表現を把握した。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **リスクを確認する**
   返信方針を決める前に、必ず [references/reply-rules.md](references/reply-rules.md) をこの工程で読むこと。低評価、医療・福祉、個人情報、規約違反疑い、外部事例の根拠確認が必要な場合は、必ず [references/pro-review-response-evidence.md](references/pro-review-response-evidence.md) も読むこと。
   入力: 口コミ本文と返信方針メモ。
   出力: 返信で触れる範囲、触れない範囲。
   完了条件: 個人情報、診断・効果保証、反論、謝罪のしすぎ、口コミ修正依頼を避ける方針が決まった。低評価、事実誤認、規約違反疑いは、投稿前に事業主の事実確認を経る方針が決まった。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **返信案を作る**
   必ず [references/reply-rules.md](references/reply-rules.md) の型を使い、口コミ本文にある事実だけを拾って作成すること。星5で本文があり、SEO語・差別化ポイント入りを希望する場合は「標準版」と「SEO語・差別化ポイント入り版」の2案を出す。希望しない場合は標準版1案だけを出す。品質境界に迷う場合は [examples/approved-replies.md](examples/approved-replies.md) をこの工程で読むこと。公開記事の例文を丸写しせず、出典から抽出した構成ルールだけを使うこと。
   既存履歴がある案件では、下書き後に必ず直前2件の返信と比較し、テンプレ感が出る連続表現を修正すること。特に「このたびはご来店いただき」「温かい口コミをありがとうございます」「大変嬉しく思っております」「これからも料理と空間づくり」「またのお越しを心よりお待ちしております」のような汎用文が続く場合は、同じ意味でも語順、焦点、締め方を変える。
   入力: 返信方針、触れる範囲、触れない範囲。
   出力: そのまま投稿できる返信案。基本は標準版1案。星5で本文があり、SEO語・差別化ポイント入りを希望する場合だけ2案。
   完了条件: 公開返信として自然で、口コミ主以外が読んでも過度に内情が分からない文になっている。既存履歴がある案件では、直前2件とテンプレ感・言い回し・締めが重複していない。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **確認メモと自己完了確認を添える**
   出力形式に迷う場合は [examples/good-output.md](examples/good-output.md) をこの工程で読むこと。合格例との差分を説明する必要がある場合は [examples/approved-replies.md](examples/approved-replies.md) をこの工程で読むこと。
   入力: 返信案。
   出力: 返信案、調整意図、投稿前確認。
   自己完了確認:
   - [ ] 入力整理を実施した。
   - [ ] リスク確認を実施した。
   - [ ] 既存履歴がある場合、直前2件との重複・テンプレ感確認を実施した。
   - [ ] 返信案作成を実施した。
   - [ ] 投稿前確認を実施した。
   完了条件: そのまま貼れる本文と、修正した方がよい箇所が分かれている。全手順を確認済みである。この完了条件を全て満たすまで、完了報告してはならない。

## エッジケース

| 状況 | 対応 |
|:---|:---|
| 星だけで本文がない | 具体的な利用内容を推測せず、評価への感謝だけを短く返す |
| 低評価で事実関係が不明 | 公開上は受け止めと確認導線に留め、詳細反論は書かない |
| 個人名、症状、利用歴が含まれる | 本文の詳細を繰り返さず、個別対応は非公開窓口へ誘導する |
| 明らかな規約違反が疑われる | 返信案とは別に、Google側で報告検討とだけメモする |
| 口コミ本文が攻撃的 | 同じ温度で返さず、簡潔に受け止めて確認導線へ寄せる |
| 返信済み | 同内容の新規返信を重ねず、既存返信の修正版か、状況変化がある場合の追記案として作る |
| 外国語レビュー | 原文言語で自然かつ正確に返せる場合は原文言語を優先する。誤解リスクがある場合は日本語と原文言語を併記し、医療・法務・低評価は公開前に内容確認を行う |

## 禁止事項

- 口コミ本文に投稿者本人が明記していない利用歴、症状、家族事情、来店・来所日時を公開返信で認めてはならない。本文に明記された事実は、詳細を広げず、効果保証や将来保証に寄せない範囲で受け止めてよい。
- 「治ります」「必ず改善します」「地域一番」「満足度100%」のような効果保証・最上級表現を書いてはならない。
- 口コミの削除、修正、星評価変更、見返り提供を求めてはならない。
- 口コミ本文にない事実、スタッフ名、対応内容を作ってはならない。
- 低評価へ長文反論してはならない。必要な確認は非公開の連絡導線に移すこと。
- ユーザーが求めていない限り、Google管理画面の操作説明を長く書いてはならない。
- 公開記事やテンプレートサイトの返信例文を、そのまま、または軽い言い換えだけで出力してはならない。
