# gbp-review-reply

> GBP（Googleビジネスプロフィール）の口コミに対する返信案を、星評価×5つのトーンで生成するスキル。
> SEOキーワードを自然に含め、ローカル検索のランキングシグナルとして活用する。

**テスト運用**: ジェットプロデュースの口コミで運用開始 → チューニング → 全クライアント展開

---

## STEP 0：実行前確認

```
□ NG_RULES.md を読んだ（Pre-flight Check）
□ 対象クライアントの業種・地域・主力サービスを把握している
□ 埋め込むSEOキーワードを確認した（下記インプット情報で指定）
```

---

## 起動コマンド

以下の情報を提示してスキルを起動する：

```
/gbp-review-reply

■ クライアント情報
- 店舗名: （例：ジェットプロデュース）
- 業種: （例：MEO対策・Web集客支援）
- 地域: （例：加古川・姫路・明石・神戸）

■ 口コミ情報
- 投稿者名: （例：田中 太郎）
- 星評価: （1〜5）
- 口コミ本文:
  （ここに口コミ全文を貼り付け）

■ SEOキーワード（1〜3個）
- （例：加古川 MEO対策、Googleビジネスプロフィール 運用代行）
```

## 返信生成ルール

### ⚡ STEP 0：生成前に必ずスタイルを判定する

> **口コミの内容を分析してフレームを作るのではなく、口コミの「深さ・長さ・温度感」を先に読み取る。**

| スタイル | 判定基準 | 返信の特徴 |
|---------|---------|----------|
| **🪞 鏡返し型** | 短文・カジュアル・紹介推薦・感謝の言葉だけ | そのまま短く返す。分析しない。温度感・長さを合わせる |
| **🔁 エコーバック型** | 具体的な結果・感情・体験の報告（中程度の長さ） | 最も印象的なフレーズを「」でそのまま引用して返す |
| **🎓 専門家型** | プロセス・気づき・深い内省・長文 | コーチ・専門家視点で解説＋共感。意訳引用。5文程度 |

**判定の基本ルール:**
```
口コミが短い（3文以内）・カジュアル → 鏡返し型
口コミが中程度・感情的な結果報告   → エコーバック型
口コミが長い・プロセスや気づきに言及 → 専門家型
```

> ⚠️ スタイルを誤ると「言葉だけ拾って分析で返した」と感じさせる。
> **まず判定、それから生成。**

---

### ルール1：絶対遵守事項


| # | ルール | 理由 |
|---|-------|------|
| R-01 | **投稿者名で呼びかける** | コピペ感を消し、個別対応を示す |
| R-02 | **口コミ内容に具体的に触れる** | 読んでいることを証明する |
| R-03 | **SEOキーワードを1〜2個自然に含める** | ローカル検索のランキングシグナル |
| R-04 | **3〜5文で収める** | 長すぎると読まれない |
| R-05 | **返信は24時間以内（低評価は4時間以内推奨）** | 返信速度はGoogleのエンゲージメント指標 |
| R-06 | **個人情報を書かない** | 顧客の取引内容・金額・連絡先などNG |
| R-07 | **インセンティブを提示しない** | 「割引」「特典」と引き換えの評価変更はGoogle規約違反 |

### ルール2：SEOキーワードの埋め込み方

```
✅ 自然な埋め込み例:
「加古川でのMEO対策のお手伝いができ、大変嬉しく思います」
「Googleビジネスプロフィールの運用改善にお役に立てたようで何よりです」

❌ 不自然な詰め込み（絶対NG）:
「加古川MEO対策の当社のGoogleビジネスプロフィール運用代行をご利用いただきありがとうございます」
→ キーワードを1文に複数詰めると逆効果（スパム判定リスク）
```

**配置の原則:**
- 1返信あたり **KWは最大2個**
- **別々の文に分散** させる
- サービス名や地域名として文脈に溶け込ませる

## 星評価別の返信戦略

### ⭐⭐⭐⭐⭐ 星5（大満足）

**目的**: 感謝 → 具体的に共感 → 再利用・紹介促進
**トーン**: ポジティブ、感謝を全面に
**KW配置**: サービス名 or 地域名を自然に入れやすい

```
構成:
1. 感謝の言葉（名前で呼びかけ）
2. 口コミの具体的内容に触れる
3. SEOキーワードを含む一文
4. 今後の利用・紹介への期待
```

---

### ⭐⭐⭐⭐ 星4（満足だが改善余地あり）

**目的**: 感謝 → 改善意欲の提示 → さらなる価値提供
**トーン**: 丁寧、向上心を見せる
**KW配置**: 星5と同様

```
構成:
1. 感謝の言葉
2. 口コミ内容に触れる + 高評価への喜び
3. 「さらに良いサービスを」の改善意欲
4. SEOキーワードを含む今後への一言
```

---

### ⭐⭐⭐ 星3（普通・期待に届かず）

**目的**: 感謝 → 具体的フィードバック確認 → 改善約束
**トーン**: 真摯、傾聴姿勢
**KW配置**: 改善テーマとしてサービス名を出す

```
構成:
1. 感謝の言葉
2. 率直なご意見への感謝
3. 改善への具体的姿勢
4. 再来時のより良い体験への約束
```

---

### ⭐⭐ / ⭐ 星1〜2（不満・クレーム）

**目的**: 謝罪 → 共感 → オフラインへ誘導
**トーン**: 謝罪・共感中心。**絶対に反論・言い訳をしない**
**KW配置**: 無理に入れない。入れるなら1個だけ

> ⚠️ **最重要**: この返信は、書いた本人ではなく「これから来るかもしれない100人の見込み客」が読む。
> 誠実な対応を見せることで、低評価の悪影響を最小化できる。

```
構成:
1. 謝罪 + 名前で呼びかけ
2. 不満内容への共感（否定しない）
3. 改善への具体的アクション表明
4. オフライン連絡先の提示（電話 or メール）
```

---

### 📝 コメントなし（星のみ）

**高評価（4〜5）の場合:**
```
構成: 感謝 → 次回のご利用への期待（2〜3文で簡潔に）
```

**低評価（1〜2）の場合:**
```
構成: 感謝 → 改善のためフィードバック依頼 → 連絡先提示（3文程度）
```

## 3つのトーン

すべての返信案は以下の3トーンで生成する。**クライアントはこの中から1つを選んで採用する。**

| # | トーン名 | 特徴 | 想定ユースケース |
|---|---------|------|----------------|
| A | 📝 **簡潔プロ** | ビジネスライク・3文以内・無駄なし | 忙しい経営者・大量返信時 |
| B | 🤝 **寄り添い** | 共感重視・温かみ・丁寧語 | 士業・医療・介護・コーチング系 |
| C | 🌟 **ポジティブ元気** | エネルギッシュ・感情豊か | 飲食・美容・スクール系 |

> ⚠️ **締め文言は現在チューニング中**。固定せず、各案ごとに自然な締めを生成する。
> 5件以上の採用データ蓄積後にパターンを分析して固定化を検討する。

## 品質チェック（生成後の自己検証）

```
□ 投稿者名で呼びかけているか（名前不明の場合は省略し記録にメモ）
□ 口コミの具体的内容に触れているか
□ SEOキーワードが自然に含まれているか（コーチング系は原則なし）
□ キーワードが同じ文に詰め込まれていないか
□ 3文以内に収まっているか
□ 個人情報（金額・取引内容・連絡先）を含んでいないか
□ インセンティブ（割引・特典）を提示していないか
□ 低評価の場合、反論・言い訳をしていないか
□ 低評価の場合、オフライン連絡先を案内しているか
□ A/B/C 3トーン全てで生成したか
□ 推奨トーンとその理由を記載したか
□ 【採用後】logs/{client-name}.md にログを記録したか
```

## NGパターン

- コピペテンプレートの使い回し（Googleに低品質シグナルを送る）
- 全返信で同じSEOキーワードを繰り返す（スパム判定リスク）
- 低評価口コミへの反論・言い訳・事実の暴露
- 「口コミを修正してください」という依頼（Google規約違反）
- 「次回割引します」等のインセンティブ提示（Google規約違反）
- キーワードを1文に3個以上詰め込む
- 投稿者名を無視して「お客様」で統一する
- 低評価を無視・放置する（返信率がランキングシグナル）

## データ蓄積設計

### 目的
- 口コミ原文 × 生成案 × 採用結果 を蓄積し、**クライアントごとの「効くトーン」を学習**する
- 蓄積データからスキル自体をチューニング（返信ルール・トーン定義の改善）
- 将来的に業種別・星別の「採用率が高いパターン」を分析可能にする

### ログファイル構成

```
gbp-review-reply/
├── SKILL.md                    ← このファイル
└── logs/
    ├── jet-produce.md          ← ジェットプロデュースの口コミ返信ログ
    ├── shibamoto-office.md     ← 芝本司法書士事務所（将来）
    └── {client-name}.md        ← クライアント追加時に作成
```

### ログファイルのフォーマット

各クライアントのログファイルに以下の形式で追記していく：

```markdown
# {クライアント名} 口コミ返信ログ

## 基本情報
- 業種: {業種}
- 地域: {地域}
- 主力KW: {KW1}, {KW2}, {KW3}

---

## #{通し番号} — {投稿日 or 対応日}

| 項目 | 内容 |
|------|------|
| 投稿者 | {名前} |
| 星評価 | ⭐×{N} |
| コメント有無 | あり / なし |

**口コミ原文:**
> {口コミ全文}

**生成した5案:**

| トーン | 返信案（冒頭30文字） | 採用 |
|--------|-------------------|------|
| A. 簡潔プロ | {冒頭30文字}... | |
| B. 寄り添い | {冒頭30文字}... | ✅ |
| C. ポジティブ元気 | {冒頭30文字}... | |
| D. 専門家知識共有 | {冒頭30文字}... | |
| E. 地域密着 | {冒頭30文字}... | |

**採用案**: B（寄り添い）
**採用理由**: {なぜこのトーンを選んだか}
**実際に投稿した返信文:**
> {最終的にGBPに投稿した返信文（微修正含む）}

**振り返り:**
- {気づき・改善点があれば記録}

---
```

### 運用ルール

| ルール | 内容 |
|-------|------|
| **記録タイミング** | 返信案を生成し、採用・投稿した後に記録 |
| **記録者** | スキル実行者（AI or 人間） |
| **必須記録** | 口コミ原文・星評価・採用トーン・採用理由 |
| **任意記録** | 5案の冒頭テキスト・振り返りメモ |
| **分析タイミング** | 10件蓄積ごとにトーン採用傾向を確認 |

### 蓄積データの活用方法

```
【10件蓄積時】
→ 各トーンの採用率を集計
→ クライアントの好みのトーンを特定
→ 次回から推奨トーンの精度を上げる

【30件蓄積時】
→ 星評価別×トーン別の採用傾向を分析
→ 業種ごとのパターンを抽出
→ SKILL.md の返信戦略・トーン定義を更新

【50件蓄積時】
→ 「このクライアントは基本Bトーン、低評価時のみA」のようなプリセットを定義
→ 5案→3案に絞って効率化
```
