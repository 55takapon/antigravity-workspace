# 自動修正ゲート

`skill-update` は毎回無条件では修正しない。
以下の条件を全て満たす場合のみ、自動修正を1回だけ許可する。

---

## 許可条件

1. 問題の種類が以下のいずれかであること
   - 構造
   - description
   - examples
   - references
   - 軽量スクリプト修正

2. 変更範囲が単一スキル配下に閉じること

3. benchmark で改善版の pass率が旧版より悪化していないこと

4. 改善版で以下が起きていないこと
   - 出力ファイルが消える
   - 期待出力が大きく崩れる
   - 旧版では通っていたアサーションが明確に落ちる

5. 主観評価だけでは判断できない重大変更ではないこと

6. `auto-fix-policy.json` で次に入っていないこと
   - `denylist`
   - `manual_only`
   - `high_risk`

---

## 停止条件

以下のいずれかに当てはまる場合は、自動修正を止めて改善レポートだけ返す。

- pass率が下がった
- 対象外ディレクトリまで巻き込む
- scripts/ の大規模改修が必要
- 外部API仕様の再確認が必要
- 主観判断が中心で、機械的比較だけでは危険
- `auto-fix-policy.json` で自動修正対象外になっている

---

## 失敗時の扱い

### 1回で止めるもの

- 構文エラー
- 許可外変更
- スキル外への変更
- benchmark 悪化
- 自動修正ゲート NG
- ファイル破損

### 最大3回までやり直してよいもの

- 一時的なタイムアウト
- `gateway closed` のような一時的な実行不調
- 一時的なログ読み込み失敗
- 一時的な補助コマンド失敗

やり直してよい失敗でも、3回とも失敗したらそのスキルだけ戻す。

---

## ゲート結果の保存

`scripts/run_iteration.py gate` は `auto_fix_gate.json` を作成し、
以下を最低限保存する。

- `allowed`
- `reasons`
- `change_kinds`
- `policy_mode`
- `pass_rate_before`
- `pass_rate_after`
- `regression_detected`
- `output_collapse_detected`

---

## 運用上の注意

- 許可されても、自動修正は1回だけにする
- 自動修正前に、対象スキルだけの戻しポイントを必ず作る
- 致命失敗は1回で止めて、対象スキルだけ戻す
- 一時失敗は最大3回までやり直し、それでも直らなければ対象スキルだけ戻す
- 修正後は必ず `skill-checker` を実行する
- 改善が曖昧な場合は、直すより止める方を優先する
