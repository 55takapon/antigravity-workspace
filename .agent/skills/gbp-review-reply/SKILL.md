# GBP口コミ返信

Googleビジネスプロフィールに投稿された口コミへ、事業者名義で公開しても不自然でない返信文を作る。口コミ本文の温度感に合わせたスタイル判定と、クライアント別の文体プロファイルを土台にし、医療・福祉、飲食、士業などの業種別ルールを追加条件として扱う。生成して終わりにせず、採用・修正の結果を返信ログへ記録し、スキル自体を更新し続ける。

## 作業手順

- [ ] **入力とクライアントプロファイルを整理する**
   必ず口コミ本文、星評価、業種、店舗・事業所名、返信済みかどうか、SEO語・差別化ポイントを入れる希望の有無を確認すること。任意で、返信者の立場（院長、店長、スタッフ一同など）を受け取る。不足していても推測で個別事実を足さず、分かる範囲で作る。
   クライアントが特定できる案件では、ユーザーに言われなくても必ずクライアントフォルダ（既定: `C:\Users\hangy\.gemini\antigravity\.agent\clients\<クライアント名>\gbp-review\`）の profile.md と log.md を確認し、文体・ブランドフレーズ・直前2件の自店返信との重複を把握すること。プロファイルがない場合はその旨を短く伝え、共通ルールで作る。
   返信済みの場合は、新規返信を重ねず、既存返信の修正版か、状況変化を反映した追記案かを先に判定する。
   入力: 口コミ本文、星評価、事業者情報。
   出力: 返信方針メモ（プロファイル有無と、直前2件との重複回避メモを含む）。
   完了条件: 高評価、低評価、星だけ、事実誤認、個人情報含みのどれに近いか、業種別追加が必要かを判断し、プロファイルの有無を確認した。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **リスクを確認する**
   返信方針を決める前に、必ず [references/reply-rules.md](references/reply-rules.md) をこの工程で読むこと。低評価、医療・福祉、個人情報、規約違反疑い、外部事例の根拠確認が必要な場合は、必ず [references/evidence.md](references/evidence.md) も読むこと。
   入力: 口コミ本文と返信方針メモ。
   出力: 返信で触れる範囲、触れない範囲。
   完了条件: 個人情報、診断・効果保証、反論、謝罪のしすぎ、口コミ修正依頼を避ける方針が決まった。低評価、事実誤認、規約違反疑いは、投稿前に事業主の事実確認を経る方針が決まった。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **スタイルを判定する**
   口コミ本文の長さ・深さ・温度感から、reply-rules.md のスタイル判定表（鏡返し型、エコーバック型、専門家型、クリエイティブリミックス型）で必ず1つを判定し、判定結果と根拠を出力に含めること。口コミの内容を分析して自分のフレームで返信を構成し始める前に、必ず型を決める。
   入力: 口コミ本文、クライアントプロファイル。
   出力: スタイル判定結果と根拠1行。
   完了条件: 4型のどれで書くかと、その根拠が明示されている。この完了条件を満たすまで、次のステップに進んではならない。

- [ ] **返信案を作る**
   必ず reply-rules.md の返信型・業種別ルールと、判定したスタイルに従い、口コミ本文にある事実だけを拾って作成すること。プロファイルがある場合は文体サンプルに語彙・文数・締めを合わせる。星5で本文があり、SEO語・差別化ポイント入りを希望する場合だけ「標準版」と「SEO語・差別化ポイント入り版」の2案を出し、それ以外は標準版1案だけを出す。品質境界に迷う場合は [examples/approved-replies.md](examples/approved-replies.md) をこの工程で読むこと。公開記事の例文を丸写しせず、構成ルールだけを使うこと。
   下書き後に必ず直前2件の自店返信と比較し、冒頭・感謝語・具体点の拾い方・締めが重複する場合は、同じ意味でも語順、焦点、締め方を変えること。
   入力: 返信方針、スタイル判定、触れる範囲・触れない範囲。
   出力: そのまま投稿できる返信案。
   完了条件: 公開返信として自然で、口コミ主以外が読んでも過度に内情が分からず、直前2件とテンプレ感・言い回し・締めが重複していない。この完了条件を全て満たすまで、次のステップに進んではならない。

- [ ] **確認メモを添えて提出する**
   出力形式に迷う場合は [examples/good-output.md](examples/good-output.md) をこの工程で読むこと。返信案、スタイル判定、調整意図、投稿前確認に加え、採用結果の記録テンプレ（採用・微修正・不採用）を必ず添えること。
   入力: 返信案。
   出力: 返信案、スタイル判定、調整意図、投稿前確認、記録テンプレ。
   完了条件: そのまま貼れる本文と、修正した方がよい箇所が分かれている。この完了条件を満たすまで、完了報告してはならない。

- [ ] **採用結果を記録する（結果の連絡を受けたら必須）**
   採用・修正・不採用の結果が分かったら、必ず [references/feedback-loop.md](references/feedback-loop.md) をこの工程で読み、クライアントの log.md へ記録すること。ユーザーが修正した場合は、修正差分と理由タグを必ず残す。5件たまるごとに無修正採用率を集計し、feedback-loop.md の条件に該当したら skill-update の起動をユーザーに必ず提案する。
   入力: 採用・微修正・不採用の結果連絡。
   出力: log.md への追記。集計条件に該当した場合は skill-update の提案。
   完了条件: 結果が分かった件について、log.md への記録と理由タグ付けが済んでいる。この完了条件を満たすまで、その件の対応を完了扱いにしてはならない。

## 自己完了確認（省略禁止）

- [ ] 入力整理とクライアントプロファイル確認を実施した。
- [ ] リスク確認を実施した。
- [ ] スタイル判定を根拠付きで出力した。
- [ ] 直前2件との重複・テンプレ感確認を実施した。
- [ ] 投稿前確認と記録テンプレを添えた。
- [ ] 採用結果が分かった件は log.md へ記録し、集計条件に該当すれば skill-update を提案した。

## エッジケース

| 状況 | 対応 |
|:---|:---|
| 星だけで本文がない | 具体的な利用内容を推測せず、評価への感謝だけを短く返す |
| 低評価で事実関係が不明 | 公開上は受け止めと確認導線に留め、詳細反論は書かない |
| 個人名、症状、利用歴が含まれる | 本文の詳細を繰り返さず、個別対応は非公開窓口へ誘導する |
| 明らかな規約違反が疑われる | 返信案とは別に、Google側で報告検討とだけメモする |
| 口コミ本文が攻撃的 | 同じ温度で返さず、簡潔に受け止めて確認導線へ寄せる |
| 返信済み | 同内容の新規返信を重ねず、既存返信の修正版か、状況変化がある場合の追記案として作る |
| 外国語レビュー | 原文言語で自然かつ正確に返せる場合は原文言語を優先する。誤解リスクがある場合は日本語と原文言語を併記し、医療・法務・低評価は公開前に内容確認を行う |
| 新規クライアントの初回返信 | 共通ルールで作り、承認後に feedback-loop.md の手順で profile.md と log.md を作成する |
| スタイル判定に迷う | より短く控えめな型を選ぶ。口コミの言葉だけ拾って分析調で返す失敗が最も多い |

## 禁止事項

- 口コミ本文に投稿者本人が明記していない利用歴、症状、家族事情、来店・来所日時を公開返信で認めてはならない。本文に明記された事実は、詳細を広げず、効果保証や将来保証に寄せない範囲で受け止めてよい。
- 「治ります」「必ず改善します」「地域一番」「満足度100%」のような効果保証・最上級表現を書いてはならない。
- 口コミの削除、修正、星評価変更、見返り提供を求めてはならない。
- 口コミ本文にない事実、スタッフ名、対応内容を作ってはならない。
- 低評価へ長文反論してはならない。必要な確認は非公開の連絡導線に移すこと。
- SEO語をユーザーの希望なしに入れたり、1返信に2セット以上入れたりしてはならない。返信内の語句に検索順位への直接効果は確認されていない（根拠は evidence.md）。
- 公開記事やテンプレートサイトの返信例文を、そのまま、または軽い言い換えだけで出力してはならない。
- 採用・修正の結果を受け取ったのに、log.md へ記録せず完了扱いにしてはならない。

変更履歴は [references/changelog.md](references/changelog.md) に分離。
