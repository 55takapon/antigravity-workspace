# GBP口コミ返信

口コミ主と第三者が読む公開返信を、必要十分な長さで作る。販促より事実性と安全性を優先し、共通、業種、クライアント固有のルールを分ける。

## 作業手順

- [ ] **1. 入力と参照範囲を確定する**
  - 入力: 星評価、口コミ本文、業種、返信済み状態、既存返信、特定できるクライアント。
  - 操作: クライアントが特定できる時は `clients\<client>\gbp-review\profile.md` と、`log.md` の `posted` / `final_approved` 直近5件を読む。knowledgeはprofileが許可した節だけに限定する。profileがなければ販促CTA・SEO・地域名入り締めをOFFにし、一般的な接客上の締めは評価帯、本文、業種リスクに合わせて判断する。
  - 出力 / 完了条件: 使用できる材料、返信済み状態、profile制約が内部で確定している。返信済みで修正・追記依頼がなければ、新規返信を作らない。
  - ゲート: 完了条件をすべて満たすまで次へ進まない。

- [ ] **2. 事実と公開リスクを整理する**
  - 入力: 工程1の材料。
  - 操作: 必ず [references/reply-rules.md](references/reply-rules.md) を読む。本文有無、評価帯、明記事実、項目別評価、強さ、禁止推測、公開リスク、返信状態、profile制約だけを内部整理する。高リスク時は [references/evidence.md](references/evidence.md) も読む。
  - 出力 / 完了条件: 触れる事実、触れない情報、評価強度の上限、個人情報・法規・規約上の制約が確定している。内部整理は通常表示しない。
  - ゲート: 完了条件をすべて満たすまで次へ進まない。

- [ ] **3. 情報量に合わせて生成する**
  - 入力: 工程2の安全な範囲。
  - 操作: `感謝または受け止め + 固有点への反応または今後の姿勢 + 必要な締め0〜1個` を基本にする。★5本文ありは自然な歓迎締めを原則入れ、明記された再来店意思には圧をかけず自然に応答する。肯定的な★4本文ありは、内容に応じて感謝に歓迎締めまたは節度ある改善姿勢を添える。★5本文なしは評価行為への十分な感謝と自然な歓迎、★4本文なしは十分な感謝と、より満足してもらえるよう努める姿勢で、いずれも2文にする。販促CTAは原則禁止し、接客上の締めと混同しない。
  - 出力 / 完了条件: 最低文字数や販促で水増しせず、店側の感情・受領報告だけで終わらない候補が1案ある。星だけへ体験を補わず、重要な意味差か明示依頼がある時だけ代替案を作る。
  - ゲート: 完了条件をすべて満たすまで次へ進まない。

- [ ] **4. 必ず全文検査して提出する**
  - 入力: 工程3の候補。
  - 操作: 必ず、事実追加、強度水増し、内心推測、曖昧表現の決めつけ、販促漏入、空虚文、歓迎締めの適否、個人情報拡張、反論、profile違反を全文検査する。同時バッチと直近の最終返信を横断し、同じ感情文の連続使用と同じ感謝→感情→締め構造の機械反復を避ける。標準の歓迎締め自体は自然なら時々重複可とし、珍しい類語へ置換しない。不合格箇所は削るか全文を再構成する。
  - 出力 / 完了条件: 通常は投稿可能な最終返信案だけを出す。複数件は番号対応させる。事実確認・規約報告が必要な場合だけ短い注意メモを分ける。
  - ゲート: 全検査と出力条件を満たすまで提出しない。

- [ ] **5. 修正と確定結果を処理する**
  - 入力: 修正指示、または採用・不採用・投稿済みの結果連絡。
  - 操作: 修正時は `元の口コミ + 現行profile + 確定済み指摘` から全文を再構成し、工程2〜4をやり直す。結果が分かった時だけ [references/feedback-loop.md](references/feedback-loop.md) を読み、clientの `log.md` へ記録する。
  - 出力 / 完了条件: 修正版は全検査済み。結果連絡があれば状態・最終文・理由を捏造せず記録し、未確定なら記録テンプレを表示しない。
  - ゲート: 該当する処理の完了条件を満たすまで、その案件を完了扱いにしない。

## エッジケース

| 状況 | 対応 |
|:---|:---|
| 星だけ | 体験や原因を補充しない。★5は十分な感謝と自然な歓迎の2文、★4は十分な感謝とより満足へ努める姿勢の2文。低評価は短い受け止め |
| 返信済み | 修正・状況変化による追記の明示依頼がなければ新規返信を作らない |
| 医療・法務等の高リスク | 投稿者が書いた情報も事業者側から反復・確認しない。再訪・再相談の誘導ではなく、一般的な感謝とサービス向上へ努める姿勢で返す |
| 肯定的な★4本文あり | 感謝だけで切らず、本文に応じて自然な歓迎締めまたは節度ある改善姿勢を選ぶ |
| 混合・低評価 | 不満・要望を先に受け止め、褒め言葉や販促で隠さず、未確認の原因・対応済み事実を書かない |
| 外国語 | profileを優先し、安全に書ける場合は原文言語のみ。内部説明や日本語訳を自動併記しない |

## 自己完了確認

- [ ] 明記事実と評価強度を越えていない。
- [ ] profile、業種リスク、返信済み状態を反映した。
- [ ] 販促CTA・SEO・knowledgeを混ぜず、接客上の歓迎締めと区別した。
- [ ] 店側感情・受領報告だけの文、機能重複、情報量に合わない文を残していない。
- [ ] 同時バッチと直近finalで、感情文・機能構造を機械反復していない。
- [ ] 必ず全文検査し、通常出力を最終返信案だけにした。
- [ ] 修正時は全文再構成して再検査した。

## 禁止事項

- 口コミにない事実、感情、満足、利用状況、原因、対応済み事実を作らない。
- 評価語を強めず、曖昧な感想を都合よく決めつけない。
- 口コミ削除、星変更、見返りを要求せず、低評価へ長文反論しない。
- 個人情報、診療・相談・契約関係、効果・成果を反復・拡張・保証しない。
- client knowledgeのSEO、固定フッター、競合分析、重点訴求を自動流用しない。
- 他商品、予約、割引、キャンペーン、同伴形態指定などの販促CTAを原則入れない。
- 単一クライアントの採否だけで共通ルールを変更しない。

変更履歴は [references/changelog.md](references/changelog.md) に分離する。
