# 出力形式と良好例router

通常は投稿可能な最終返信文だけを出す。内部整理、router分類、参照ID、調整意図、自己チェック、記録テンプレは表示しない。複数件は番号だけを付ける。事実確認・公開前確認・規約報告が必要な時だけ、返信本文の後へ短い注意メモを分ける。

## 良好例の参照方法

1. 共通安全核K1〜K6とclient profileを先に確定する。
2. [case-index.md](case-index.md)で1カテゴリを選ぶ。
3. 該当カテゴリファイルから、条件が近く`router-eligible`な例を最大2〜3件だけ読む。
4. 例は焦点、役割、温度、完結方法の参考にし、全文コピーや機械的な穴埋めをしない。
5. 例がK1〜K6、profile、口コミ本文と衝突する場合は使わない。

登録全文例は26件で、26件全てが通常routerの参照候補である。投稿済みA35は`approved-replies.md`にhistorical sourceとして保持し、runtimeでは参照しない。置換後のU-R06を含む各例には適用条件・不適用条件とK1〜K6を適用する。26件全件の一括読込は禁止する。`approved-replies.md`は承認履歴、`quality-boundaries.md`はphrase-level監査証跡であり、通常生成では読まない。

## 出力境界

- 単一件: 最終返信文だけ。
- 複数件: `1.`、`2.`のように番号を付け、口コミの事実を混ぜない。
- 返信済み: G06-RPに従い新規返信を作らない。
- staff-sharing未確定: 共有の有無が返信を左右する場合だけ、確認用に共有あり/なし2案を示す。選択後はprofileへ保存し、通常1案へ戻す。
- 注意メモ: 返信本文と混ぜず、確認対象だけを1〜2文で示す。

確定結果が分かった時だけ [../references/feedback-loop.md](../references/feedback-loop.md) に従ってlogへ記録する。
