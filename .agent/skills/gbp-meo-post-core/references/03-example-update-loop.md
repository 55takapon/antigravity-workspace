# 良好事例の更新手順

## 目的

ユーザーが選んだ良好事例だけを `examples/good-examples-index.md` に追加し、将来の投稿作成で再利用できる判断基準へ変換する。作成者が想像した完成文や、未承認の投稿を良好事例として追加しない。

## 追加してよい条件

次の条件を全て満たす場合だけ追加する。

- ユーザーが「この投稿を良好事例に追加して」と明示している。
- 実投稿本文または実ファイルの出典パスがある。
- クライアント、業種、主な読者、GBP投稿種別、投稿目的型、意思決定段階、切り口、投稿テーマ、採用理由が分かる。
- どの表現や構成を再利用してよいか説明できる。
- 使ってはいけない条件も説明できる。
- 個別クライアントの機密情報や固有事情を、汎用ルールとして混ぜていない。

## 追加してはいけない条件

- 作成者がその場で作った投稿案。
- ユーザーが良好事例として選定していない投稿。
- 出典パスがない投稿。
- クライアント固有のキャンペーン、価格、個人情報、機密情報が中心の投稿。
- 失敗例を、良好事例として扱うもの。

## 作業手順

1. 対象投稿の出典パスを確認する。
2. 投稿本文を読み、良い点を「再利用できるルール」と「その案件だけの事情」に分ける。
3. `examples/good-examples-index.md` に、事例カードを1件追加する。
4. 投稿本文を全文転載する必要がない場合は、要約と参照パスに留める。
5. 医療、士業、口コミ、個人情報を含む場合は、本文転記を避け、抽出した再利用ルールだけを書く。
6. 追加後、同ファイルの「追加前チェック」を全て満たしているか確認する。

## 事例カードの項目

```markdown
## 事例ID: YYYYMMDD-client-topic

- 出典パス:
- クライアント:
- 業種:
- 主な読者:
- GBP投稿種別: 最新情報・特典・イベント・商品のいずれか
- 投稿目的型: A：課題・疑問型／B：魅力・価値型／C：告知型のいずれか
- 意思決定段階:
- 切り口: FAQ型、商品紹介型、選び方型など
- 投稿テーマ:
- ユーザーが採用した理由:
- 抽出できる再利用ルール:
- 使ってはいけない条件:
- 注意が必要な固有情報:
```

## 抽出の観点

| 見る点 | 抽出する内容 |
|:---|:---|
| 冒頭 | 誰向けか、何の価値か、どう結論を出しているか |
| 構成 | 情報の順番、段落の切り方、読みやすさ |
| 事実確認 | どの材料を根拠にしているか |
| 表現 | 断定を避けながら魅力を出している言い回し |
| CTA | 投稿目的に合った次の一歩(相談、予約、来店、注文、査定、体験、詳細確認、セルフチェック、CTAなし等) |
| 除外条件 | 別業種や別状況で使うと危険な表現 |

## 不合格時の対応

- ユーザー選定がない場合は追加しない。
- 出典がない場合は追加せず、出典確認を依頼する。
- 再利用ルールが抽出できない場合は、事例ではなく案件固有メモとして扱う。
- 固有情報が強すぎる場合は、本文を転記せず、抽象化したルールだけ残す。
