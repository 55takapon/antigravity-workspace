# 投稿作成ワークフロー

## 目的

GBP投稿を、確認済み材料だけで読みやすく作る。既存の長文MEO投稿の強みである情報量、地域性、サービス理解は残しつつ、根拠のない盛り込みや同じ切り口の繰り返しを防ぐ。

## 使う材料

| 材料 | 扱い |
|:---|:---|
| ユーザー提供素材 | 確認済み材料として使う。曖昧なメモは質問候補にする |
| 公式サイト、LP、メニュー、サービスページ | 店舗情報、提供サービス、料金、対応地域、特徴の根拠にする |
| knowledge.md などのローカルナレッジ | 出典として使う。狙うキーワード、文字数、固定冒頭、固定フッターはナレッジの記載を正とする。古い可能性がある項目は確認候補にする |
| 過去投稿ファイル | 月次投稿の重複回避、トーン、構成、履歴把握に使う。記載事実を再利用する場合は現行ナレッジ、公式資料、またはユーザー提供情報で再確認し、過去投稿だけを現在事実の根拠にしない |
| 口コミ、感想、レビュー | 実ファイルまたはユーザー提供で確認できる場合だけ、要約材料にする |
| 未確認の推測 | 本文に使わず、質問候補または除外理由にする |

## 作業手順

1. 依頼内容から、クライアント、業種、地域、投稿目的、投稿月、テーマ、固定冒頭・固定フッターの有無を整理する。固定文がある場合は文言・位置・改行をそのまま控える。
2. 使える材料を出典付きで並べる。出典がない事実は、本文材料に入れない。
3. キーワードと文字数はナレッジ指定を優先する。キーワード方針がない場合は主軸キーワードを「未設定」とし、地域名+サービス名を自動生成しない。テーマと材料が十分なら作成を続け、キーワード指定が必須成果物の場合だけ質問する。文字数は指定がない場合だけ既存の標準値を使う。固定冒頭に含まれる語を、ルール充足だけを目的に可変本文へ反復しない。
4. 月次投稿では年間計画と対象クライアントの過去投稿を確認し、主な読者、生活場面、悩み・関心、核となる気づき、読後行動、企画の切り口の重複を把握する。キーワードの一致だけで重複と判定しない。
5. 投稿の狙いを1つに絞る。認知、来店予約、相談、サービス理解、季節企画、FAQ回答などを混ぜすぎない。
6. 投稿目的型として「A：課題・疑問型」「B：魅力・価値型」「C：告知型」から1つを選び、企画の切り口とは別に管理する。3型の詳細は [04-copywriting-rules.md](04-copywriting-rules.md) を正本とする。
7. 見出し・タイトル(必要な場合)、固定冒頭(定義時のみ)、可変本文、固定フッター(定義時のみ)の順で構成する。
8. 関連する承認済み良好事例がある場合は、対象読者・投稿目的型が近い1〜2件を本文作成前に参照する。
9. スマホで読みやすいように、短い段落、箇条書き、自然な改行を使う。
10. 作成後に投稿目的型、読者の意思決定段階、切り口、主軸キーワードを添えて `gbp-post-quality-check` を実行し、要修正があれば本文へ戻す。

## 構成基準

### 固定冒頭ブロック

- ナレッジに定義されている場合だけ置く共通ブランドブロックとする。
- 文言、位置、改行を変更しない。定義がない固定文を推測で作らない。
- 第1文、冒頭100文字、冒頭3秒、問いかけ、続きを読む理由の評価対象に含めない。

### 可変本文ブロック

- ナレッジに文字数指定がない場合のみ、900文字前後を目安にする。
- 投稿目的型に合う入り方で、冒頭に続きを読む理由を示す。問いかけは全投稿へ強制しない。
- 確認済みのサービス内容、対応範囲、利用前の判断材料、専門的な見方を中心に書く。
- 課題・疑問型と魅力・価値型の主要な訴求1〜2点には、事実に「読者が何をできるようになるか」を添える。告知型は確認済みのメリットがある場合だけ添え、休業・営業時間変更などの短い事務告知は、結論、日時・対象・内容、必要な補足・注意点、必要な行動が明確なら膨らませない。
- 読者の不安や悩みに触れる場合は、「こうした悩みを持つ方もいます」程度に留め、全員に当てはまるように書かない。
- MEOキーワードはナレッジ指定と文脈を優先する。固定冒頭を含め投稿全体に自然に入っている語を、完全一致の回数を満たすためだけに反復しない。

### 固定フッターブロック

- ナレッジに固定フッターの記載がある場合は、それを正として使い、文言を勝手に書き換えない。
- ナレッジにも依頼にも記載がない場合は、フッターを付けず、推測で作らない。
- 新規に作る指示があった場合は、固定冒頭と固定フッターの役割をナレッジに従って分ける。固定冒頭に地域名・事業者名がある場合は、同じ情報を固定フッターへ強制しない。
- 固定冒頭がない場合は、必要に応じて固定フッターで地域・サービス・導線を補完してよい。文字数や構成は一律に決めず、投稿全体の文字数と役割分担に合わせる。
- 地域名やサービス名をSEO目的だけで重複させない。
- 電話番号、URL、未確認の対応範囲、保証表現を入れない。

## GBP投稿種別ごとの使い分け

| GBP投稿種別 | 使う場面 | 書く内容 |
|:---|:---|:---|
| 最新情報 | 通常の月次投稿、FAQ、サービス紹介 | 専門的な気づき、よくある質問、利用前の判断材料 |
| 特典 | 確認済みキャンペーンがある場合 | 対象条件、期間、利用方法、注意点 |
| イベント | 日時や場所が確認済みの場合 | 開催目的、対象者、内容、参加方法 |
| 商品 | 商品やメニューを紹介する場合 | 商品特徴、利用シーン、注文や予約の自然な導線 |

## 月次投稿の重複回避と年間計画

- 重複回避は [05-annual-plan.md](05-annual-plan.md) の年間計画ファイルを正とする。計画がある場合は当月行のテーマ・主軸キーワード・投稿目的型・切り口を使い、過去投稿の全件読み返しは不要。
- 計画ファイルがない場合は、直近3ヶ月の過去投稿を確認し、読者、テーマ、核となる気づき、読後行動、企画の切り口の組み合わせを比べたうえで、年間計画の作成を提案する。
- 同じキーワードや投稿目的型の連続使用は可とする。キーワードはナレッジと投稿テーマの検索意図に最も合うものを選び、重複回避だけを目的に変更しない。
- 季節の一般事実は使ってよい。ただし「新生活で忙しいご家庭」「夏休みなら時間がある」など読者の予定・家庭状況・体調を季節から断定しない。同じ季節切り口の使用だけでは不合格にせず、読者、生活場面、核となる気づき、読後行動、企画の切り口の組み合わせで重複を判定する。

## 出力形式

投稿案の後に、確認結果を短く添える。

```markdown
## 投稿案

GBP投稿種別:

タイトル・見出し案(ユーザーが求めた場合、タイトル欄がある場合、または本文内見出しを使う場合のみ。該当時は3案):

固定冒頭:

可変本文:

固定フッター:

## 確認結果

- 主軸キーワード:
- 投稿目的型:
- 意思決定段階:
- 切り口:
- 使用した確認済み材料:
- 未確認のため入れなかった内容:
- 過去投稿との重複回避:
- gbp-post-quality-check:
```

## 不合格時の対応

- 出典のない事実がある場合は、削除するか質問候補にする。
- 口コミ風表現の出典がない場合は、体験談に見える表現を削除する。
- 季節や家庭状況の断定がある場合は、一般的な言い方へ弱めるか削除する。
- 品質チェックで要修正が出た場合は、修正後に再チェックする。
