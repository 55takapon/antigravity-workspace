# GBP MEO投稿作成コア

Googleビジネスプロフィール投稿を、確認済み材料に基づいて作成・改善する。長文MEO投稿の情報量は活かすが、未確認事実、根拠のない体験談、断定表現を標準で除外する。

## 必須工程

### 1. 材料を確認する

必要資料: [references/01-workflow.md](references/01-workflow.md) と [references/02-fact-guard-writing-rules.md](references/02-fact-guard-writing-rules.md) をこの工程で必ず読むこと。月次投稿では [references/05-annual-plan.md](references/05-annual-plan.md) も必ず読むこと。

- [ ] クライアント名、業種、対象地域、今回の投稿目的、投稿月、参照する実ファイルを確認した
- [ ] 公式サイト、knowledge、ユーザー提供素材などの現行の確認済み材料と、トーン・構成・重複確認に使う過去投稿を出典付きで分けた。過去投稿中の事実を再利用する場合は、現行ナレッジ、公式資料、またはユーザー提供情報で再確認した
- [ ] ナレッジに記載されたキーワードから検索クエリを1つ選んだ。記載がない場合は主軸キーワードを「未設定」とし、キーワード指定が必須成果物の場合だけ質問候補へ回した
- [ ] ナレッジに固定冒頭または固定フッターの記載がある場合は、それを正として確認した
- [ ] 未確認の設備、雰囲気、実績、来店状況、口コミ、季節行動、家庭状況を本文材料から除外した
- [ ] 月次投稿では、クライアントの `posts/annual-plan-YYYY.md` を確認し、当月のテーマ・主軸キーワード・投稿目的型・切り口を取得した(計画がない場合は当月分を作りつつ、年間計画の作成を提案する)

#### 完了条件
確認済み材料、参考資料、未確認材料、質問が必要な材料が分かれていること。主軸キーワードは指定値または「未設定」として記録されていること。テーマと材料が十分なら、キーワード未設定だけを理由に作業を止めない。

### 2. 構成を作る

必要資料: [references/04-copywriting-rules.md](references/04-copywriting-rules.md) をこの工程で必ず読むこと。GBP投稿種別や長文構成に迷う場合は [references/01-workflow.md](references/01-workflow.md) も読むこと。

- [ ] 投稿の狙いと読者の意思決定段階(認知・比較・行動)を1つに絞った
- [ ] 投稿を「見出し・タイトル(必要時)→固定冒頭(定義時のみ)→可変本文→固定フッター(定義時のみ)」に分け、固定文の文言・位置・改行を変更していない
- [ ] 可変本文は投稿目的型として「A：課題・疑問型」「B：魅力・価値型」「C：告知型」から1つを選び、企画の切り口と分けて管理した
- [ ] キーワードと文字数はクライアントナレッジを優先し、指定がない場合だけ既存の標準値を使った
- [ ] 課題・疑問型と魅力・価値型では、主要な訴求1〜2点を確認済み事実から読者の判断・行動可能性へベネフィット翻訳した。告知型では確認済みのメリットがある場合だけ添え、短い事務告知を膨らませていない
- [ ] 関連する承認済み良好事例がある場合は、対象読者・投稿目的型が近い1〜2件を構成やリズムの参考にした(固有表現・固有情報・事実根拠は模倣しない)
- [ ] ユーザーがタイトル案を求めた場合、投稿にタイトル欄がある場合、または本文内見出しを使う場合だけ、タイトルまたは見出し案を3つ提示し、1つを推奨した

#### 完了条件
投稿の構成が確認済み材料だけで説明できること。読者の季節行動・家庭・来店シーンを根拠なく前提にしている場合、または可変本文の冒頭に投稿目的に合う続きを読む理由がない場合は作り直すこと。課題・疑問型と魅力・価値型は確認済み事実を読者価値へ翻訳し、短い事務告知は必要情報を明確にする。

### 3. 投稿文を作成または改善する

必要資料: 表現判断に迷う場合は [references/02-fact-guard-writing-rules.md](references/02-fact-guard-writing-rules.md) をこの工程で必ず読み直すこと。良好事例が必要な場合は [examples/good-examples-index.md](examples/good-examples-index.md) を読むこと。

- [ ] 事実として確認できる内容だけを書く
- [ ] 口コミ風表現、体験の代弁、感情の断定を使わない
- [ ] 季節、家族構成、子ども連れ、初回来店、常連利用などの状況を出典なしに断定しない
- [ ] 医療・健康・士業・法務・税務などの結果や効果は断言せず、必要に応じて相談導線に戻す
- [ ] 電話番号、URLの本文直書き、過剰な絵文字、無意味なハッシュタグ羅列を入れない
- [ ] [references/04-copywriting-rules.md](references/04-copywriting-rules.md) の自己チェック(冒頭3秒・だから何・対象明確・テンプレ臭・ファクトガード再確認)を必ず実行した
- [ ] ベネフィット翻訳が感情の断定や効果保証に変わっていないことを確認した

#### 完了条件
各段落の主要事実について出典またはユーザー提供材料を説明できること。説明できない文は削除または質問候補へ戻すこと。自己チェックに不合格の項目が残ったまま次の工程へ進んではならない。

### 4. 品質チェックを実行する

投稿を作成・修正したら、報告前に必ず `gbp-post-quality-check` を実行すること。

- [ ] 投稿目的型、読者の意思決定段階、切り口、主軸キーワードを品質チェックへ渡した
- [ ] `gbp-post-quality-check` の全8軸(訴求力の軸8を含む)で検査した
- [ ] 要修正が出た場合は本文を修正し、再チェックした
- [ ] チェック完了報告を投稿案の後に付けた
- [ ] 合格後、投稿をクライアントフォルダの `posts/YYYY-MM.md` へ主軸キーワード・投稿目的型・切り口と一緒に保存し、年間計画の状態列を更新した
- [ ] 既存の `posts/YYYY-MM.md` をリライト・改訂する場合は、最新版(リライト版)をファイル冒頭に配置し、見出しに「【リライト版・最新】」等の版種を明記する。旧バージョンは削除せずファイル末尾に「【旧版・参考】」として残し、投稿には使わない旨を一言添える

#### 完了条件
`gbp-post-quality-check` が合格していること。合格前に最終版として報告してはならない。改訂時は最新版が常にファイル冒頭にあること。

### 5. 良好事例を更新する

必要資料: ユーザーが「この投稿を良好事例に追加して」と明示した場合だけ [references/03-example-update-loop.md](references/03-example-update-loop.md) を必ず読むこと。

- [ ] ユーザー選定済みの実投稿だけを候補にした
- [ ] 出典パス、クライアント、業種、採用理由、再利用ルール、使ってはいけない条件を記録した
- [ ] 作成者が想像した投稿本文を良好事例として追加していない

#### 完了条件
事例の出典と採用理由が明確であること。未選定の投稿は examples に追加してはならない。

### 6. ユーザー指摘のナレッジ反映を確認する（半自動）

- [ ] 今回のセッションでユーザーが表現方針・専門用語の扱い・禁止表現・業種特有の注意点などについて修正指示を出したかを確認した
- [ ] その指示が「今回限りの言い回し変更」か「今後の投稿にも継続して適用すべき恒久ルール」かを判断した
- [ ] 恒久ルールと判断した場合、報告の最後に「今回の指摘は、今後の◯◯（クライアント名）の投稿にも反映しておきますか？」とユーザーに確認した
- [ ] 承認された場合のみ、対象クライアントの `knowledge.md` に追記した。クライアントの枠を超えてスキル本体（本スキルや references）を変更する必要がある場合は、その場で無断編集せず `skill-update` スキルの手動改善フローに回す
- [ ] 一時的な指示や、その投稿だけの個別事情は `knowledge.md` に反映しない

#### 完了条件
恒久ルールかどうかの判断、ユーザーへの確認、反映または見送りの記録が完了していること。ユーザーに確認せず `knowledge.md` を書き換えてはならない。

## 標準禁止事項

- 未確認の設備、内装、スタッフ対応、人気、実績、営業時間、料金、キャンペーンを書くこと
- 実際の口コミやユーザー提供の声がないのに「という声をいただいています」などの口コミ風表現を書くこと
- 季節、天候、家族構成、子どもの有無、来店前後の感情、利用シーンを出典なしに断定すること
- 「必ず」「絶対」「一番」「最高」「解決します」「治ります」「順位が上がります」などの保証表現を書くこと
- 電話番号、URLを投稿本文または固定フッターへ直接書くこと
- 良好事例本文を作り物で追加すること

## エッジケース

| 状況 | 対応 |
|:---|:---|
| 材料が少ない | 確認済み事実だけで短めに作るか、不足情報を質問する |
| ナレッジにキーワード、固定冒頭、固定フッターの記載がない | 固定文は推測で補わない。主軸キーワードは「未設定」とし、地域名+サービス名を自動生成しない。テーマと材料が十分なら本文作成は続け、キーワード指定が必須成果物の場合だけ質問する |
| 季節感を使う | 出典なしで使えるのは、季節区分や「気温が高い日には」「空気が乾燥しやすい時期には」など条件形の一般表現までとする。現在の天候、発生傾向、人々の行動増加は確認済み材料がある場合だけ使い、読者の予定・家庭状況・体調・来店行動を断定しない |
| 口コミ風にしたいと言われた | 実際の口コミや感想の出典がある場合だけ要約して使い、なければ使わない |
| 月次投稿で前月と似ている | 問いかけ形式や投稿目的型の一致だけで不合格にせず、近似した冒頭文、生活場面、論理展開、核となる気づき、読後行動が重なる場合は企画から差し替える |
| 医療・士業など高リスク業種 | `gbp-post-quality-check` の業種別軸を必ず適用し、結果保証や法的助言の断定を避ける |

## 自己完了確認

- [ ] 必須工程で指定された references/examples を必要なタイミングで読んだ
- [ ] 確認済み材料と未確認材料を分けた
- [ ] キーワードと文字数はナレッジ指定を優先し、固定冒頭内の語を可変本文へ機械的に反復していない
- [ ] 未確認事実、口コミ風表現、季節・家庭・来店状況の断定を除外した
- [ ] 投稿目的型に合う冒頭設計を適用した。課題・疑問型と魅力・価値型ではベネフィット翻訳を行い、短い事務告知では必要情報を明確にした
- [ ] 長文投稿では情報量と読みやすさを両立し、短い事務告知は不要に膨らませていない
- [ ] `gbp-post-quality-check` を実行し、合格前に最終報告していない
- [ ] 投稿を `posts` フォルダへ保存し、年間計画の状態を更新した
- [ ] 良好事例を追加する場合、ユーザー選定済みの実投稿だけを追加した
- [ ] ユーザーから恒久ルールと判断できる修正指示があった場合、反映可否をユーザーに確認し、承認された場合のみ対象クライアントの `knowledge.md` に反映した
