# gbp-report-quality-check

> GBP月次レポート生成後、**スプレッドシートの元データとレポート内の数値が一致しているか**を自動突合チェックする。

## レポート作成プロセス（前提）

品質チェックスクリプトは以下のプロセスを前提に設計されている。
このプロセスを正しく踏めば「データ混在」「ベンチマーク空欄」「コメント空欄」は**起きない**。

| STEP | 作業内容 | 備考 |
|------|---------|------|
| 1 | **前月のHTMLを複製する** | コメント・ベンチマーク・構造すべて引き継がれる |
| 2 | **スプレッドシートからKPI数値を取得して更新** | 閲覧数・電話・ルート検索・Webクリック |
| 3 | **ベンチマーク（競合）の評価点数・口コミ数をWebから取得して更新** | スクレイピング失敗時は前月値がそのまま残る |
| 4 | **担当者コメントは前月のまま出力** | 必要に応じてユーザーが手動で書き換える |
| 5 | **数値突合チェックを実行する（本スクリプト）** | STEP 2で取得した数値がHTMLに正しく反映されたか確認 |

## 品質チェック手順

### STEP 1: 数値突合チェックスクリプトを実行

```powershell
node .agent/skills/gbp-report-quality-check/scripts/verify_report.js
```

スクリプトが検査する内容：
- **スプレッドシートの元データとレポートHTML内のKPI数値が一致するか**
  - 閲覧数
  - Webクリック
  - ルート検索
  - 電話発信

それ以外のチェックは行わない。

### STEP 2: 結果確認

- 全件 `✅ [OK]` → レポート完成
- `❌ [NG]` がある → 該当レポートの数値を修正して再チェック
- シート取得失敗 → 即中断（数値突合なしでOKを出すことは絶対にしない）

## NGパターン

- ❌ **シート取得失敗を無視して「OK」とする** → スクリプトが即中断するので発生しない
- ❌ **スクリプトを実行せずにレポートを納品する**
- ❌ **数値不一致を無視して納品する**

## ファイル構成

- `scripts/verify_report.js`: スプレッドシートとHTMLの数値突合チェックスクリプト
