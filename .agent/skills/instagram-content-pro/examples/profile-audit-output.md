# プロフィール監査の出力例

完成bioのサンプルは置かない（作成者が想像した完成文を見本にすることは品質基準で禁止されているため）。監査の評価過程と、改善案を「型」で出す粒度を示す。

## 入力

- 業種: 古民家カフェ（地方都市・固有名は案件ごとに入力）
- 目的: 新規来店、予約、保存
- 現状bio: 業態の自己紹介1文のみ（対象者・証拠・CTAなし）
- リンク: 複数リンク集
- ハイライト: 日常、ランチ、店内
- ピン留め: なし

## 出力

### 現状評価

| 項目 | 評価 | 理由 |
|---|---|---|
| 検索性 | 要改善 | 名前欄に地域名、業態、利用シーンが入っていない |
| 視認性 | 未確認 | アイコンとグリッドの情報がない |
| 価値宣言 | 要改善 | 誰が、なぜ行きたい店なのかが弱い |
| 証拠 | 要改善 | 口コミ、予約方法、価格、席情報が常設されていない |
| 出口 | 要改善 | 複数リンクで予約導線が薄まっている |

### 改善案の型

名前欄の型:
屋号｜地域名＋業態（05_profile_funnel.md の名前欄の型から「屋号+地域」を選択。本命＋代替1案を出す）

bioの型（4行・各行の役割を分ける）:
1行目: 対象（誰向けの店か。地域＋利用シーン）
2行目: 価値（何が得られるか。空間・メニューの特徴）
3行目: 証拠または利用条件（営業日・席情報の案内場所）
4行目: CTA（予約/アクセスへ1つだけ誘導）
※3行目と4行目で同じ行動を繰り返さない。

ピン留め3本:
1. はじめての方へ: 店内、席、利用シーン、アクセス。
2. 看板メニュー: 内容、価格、予約の必要性。
3. お客様の声/FAQ: よくある質問、駐車場、混雑時間。

ハイライト:
はじめに、メニュー、口コミ、FAQ、アクセス、予約。

リンク:
最上段は予約ページ。複数リンク集を使う場合は、予約、営業日、アクセスの3つまでにする。

### 投稿側への反映

- ReelsのCTA: 営業日・予約をプロフィールへ誘導する一文
- カルーセルのCTA: 保存＋来店前FAQ確認への誘導
- ストーリーズ: アンケート後に予約リンクを出す

### 計測

- プロフィールアクセス率
- リンクタップ率
- ストーリーズリンクタップ
- 予約時のInstagram経由申告
- DMでの席/営業時間質問数
