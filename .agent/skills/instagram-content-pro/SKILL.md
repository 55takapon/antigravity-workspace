# Instagram実践投稿運用

## 概要

日本向けInstagram運用の戦略、プロフィール導線、月間運用、投稿企画、制作指示、分析、改善を、一次情報と確認済み根拠から実務で使える形にする。

## ワークフロー

1. 依頼を整理すること。
   - 入力: 目的、ターゲット、業種、素材、一次情報、既存アカウント、インサイト、制約。
   - 出力: 今回の目的、足りない素材、仮説、作る成果物。
   - 初回、情報不足、実案件化、月間運用、プロフィール改善では、必ず [00_initial_intake](references/00_initial_intake.md) のヒアリングシートで整理する。
   - 最新仕様、成功事例、アルゴリズム根拠が必要な場合は、必ず [01_research_evidence](references/01_research_evidence.md) を読み、Webまたはユーザー提供資料で実物を確認する。
   - このステップの完了条件を満たすまで、次のステップに進んではならない。

2. 成果物の種類と投稿フォーマットを分けて選ぶこと。
   - 出力: 成果物の種類（戦略 / プロフィール / 月間カレンダー / 投稿案 / 分析から推奨1案）と、投稿を作る場合のフォーマット（Reels / カルーセル / ストーリーズ / フィードから推奨1案）。
   - この工程で、該当する作業の資料だけを必ず読む:

   | 作業 | 読む資料 |
   |---|---|
   | 制作ルール全般（冒頭複数案・規制照合を含む） | [02_content_playbook](references/02_content_playbook.md) |
   | アカウント戦略・訴求設計 | [04_account_strategy](references/04_account_strategy.md) |
   | プロフィール・ハイライト・ピン留め・リンク導線 | [05_profile_funnel](references/05_profile_funnel.md)。業種別の型は [08_industry_profile_patterns](references/08_industry_profile_patterns.md) |
   | 月間カレンダー・投稿頻度・週次改善 | [06_monthly_operation](references/06_monthly_operation.md) |
   | インサイト・アカウント分析・投稿改善 | [07_insight_analysis](references/07_insight_analysis.md) |
   | リール台本の複数本制作 | [09_reels_script_matrix](references/09_reels_script_matrix.md) |

   - このステップの完了条件を満たすまで、次のステップに進んではならない。

3. 成果物を作ること。
   - 入力: 確定したフォーマット、一次情報、根拠、制約。
   - 出力: 必ず [10_deliverables](references/10_deliverables.md) の出力順序に従う。冒頭コピー（0-3秒・表紙・1行目）は本命1案と代替2案。
   - 出力の粒度に迷う場合だけ、[examples/good-output.md](examples/good-output.md) など該当する出力例（profile-audit-output / monthly-calendar-output）をこの工程で読む。
   - このステップの完了条件を満たすまで、次のステップに進んではならない。

4. 品質チェックを必ず行うこと。
   - 必ず [03_quality_and_update](references/03_quality_and_update.md) の品質ゲート全項目で確認し、不合格なら修正する。
   - 品質ゲートは作成役と別のQA役で必ず実行すること（サブエージェント。無い環境では役割を明示的に宣言して切り替える）。
   - 未実施の品質チェックがある場合、完了報告してはならない。

5. 保存と報告を行うこと。
   - 正式成果物（戦略・監査・月間カレンダー・投稿案）は、必ず [10_deliverables](references/10_deliverables.md) の保存規則どおり clients 配下へ保存し、保存先パスを報告する。スキルフォルダ内への保存は禁止。
   - 保存と報告が終わるまで、完了報告してはならない。

6. スキル更新依頼なら、必ず [03_quality_and_update](references/03_quality_and_update.md) の更新手順に従い、更新後は簡易シナリオで動作確認すること。今回だけの好み、未確認の噂を恒久ルールにしてはならない。

## エッジケース

| 状況 | 対応 |
|---|---|
| 素材がほぼない | まず質問を最大3つに絞る。急ぎなら仮説を明記して叩き台だけ作る。 |
| 撮影できない週がある | 素材レベルを判定し、既存素材、FAQ、テキストカルーセル、ストーリーズ質問箱で代替する。 |
| 医療、美容、健康、士業、金融を扱う | 必ず gbp-meo-core の references/industry-regulations.md（業種別広告規制の正本）と照合し、断定表現を避ける。 |
| ユーザーが「最新」「成功事例」「プロ事例」を求める | 必ずWeb確認し、根拠と推測を分ける。 |
| インサイト数値がない | 汎用ベンチマークで断定せず、次回取得すべきKPIを指定する。 |

## 禁止事項

- 根拠のない「アルゴリズム最新情報」を断定してはならない。
- 他アカウントの投稿文、構成、画像をそのままコピーしてはならない。
- ハッシュタグ、いいね、保存だけで成果が出るように見せてはならない。
- 露骨なエンゲージメント稼ぎ、誇大広告、実績の水増しを提案してはならない。
- プロ事例を確認していないのに「成功事例」として扱ってはならない。

## 自己完了確認

完了前に必ず確認すること。未実施があれば完了報告してはならない。

- [ ] 依頼目的、ターゲット、素材不足を整理した。
- [ ] 成果物の種類と投稿フォーマットを分けて選び、理由を書いた。
- [ ] 一次情報または確認済み根拠を使った。
- [ ] 冒頭コピーを本命1案と代替2案で出した（投稿制作時）。
- [ ] 品質ゲートを作成役と別のQA役で実行し、不合格箇所を修正した。
- [ ] 正式成果物を保存規則どおり保存し、パスを報告した（保存対象の場合）。
