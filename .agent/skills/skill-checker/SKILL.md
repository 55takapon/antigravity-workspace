# Skill Checker

スキルの品質チェックを実行し、
品質基準の全項目に対して合否を判定する。
`skill-creator` と `skill-update` の最後の品質ゲートとして使う。

## ステップ1: 品質チェックリストを読み込む

- [ ] `references/skill-quality-checklist.md` を `view_file` で必ず読み込むこと
- [ ] 全カテゴリ・全項目数を数えて必ず記録すること

#### 完了条件
- 全カテゴリの項目数を正確に把握していること
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ2: 対象スキルを読み込む

- [ ] チェック対象の SKILL.md を `view_file` で読み込んだ
- [ ] references/ があれば内容を確認した
- [ ] examples/ があれば内容を確認した
- [ ] scripts/ があれば内容を確認した
- [ ] SKILL.md の文字数からトークン数を概算した（文字数÷4）

#### 完了条件
- スキルの全ファイルを読み込み済みであること
- トークン数を概算済みであること
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ3: 全項目チェック

`references/skill-quality-checklist.md` の全カテゴリと構造品質チェックに対して、必ず1項目ずつ判定すること。
チェック項目の本文は `references/skill-quality-checklist.md` を正本にし、SKILL.md側で同じ表を持たない。

判定結果はテーブル形式で出力する:

```
| カテゴリ | # | 項目 | 判定 | 根拠 |
|:---------|:--|:-----|:-----|:-----|
| 仕様準拠 | 1 | YAML frontmatter | pass | name/description 両方あり |
| 仕様準拠 | 2 | name形式 | fail | 大文字が含まれている |
| 続き | 全項目 | 省略禁止 | pass/fail/n/a | 1項目ずつ根拠を書く |
```

判定は3種類:
- **pass** — 基準を満たしている（根拠を1行で示す）
- **fail** — 基準を満たしていない（何が足りないかを具体的に示す）
- **n/a** — このスキルには該当しない（理由を示す）

#### チェック時の注意

- 一括判定の禁止: 「カテゴリ1は全てpass」のような省略は厳禁
- 必ず1項目ずつ判定すること。まとめ判定は絶対に禁止
- テーブルの行数 = ステップ1で数えた全項目数と必ず一致させること
- n/a判定は必ず慎重に行うこと。迷った場合はn/aではなくpassとし、確認した根拠を必ず明記すること
- スキップ防止パターン（カテゴリ7）は全スキルに適用されるため、絶対にn/aにしてはならない

#### 完了条件
- 全項目のテーブルが出力済みであること
- テーブルの行数がステップ1で記録した全項目数と必ず一致していること
- この完了条件を全て満たすまで、次のステップに進んではならない

---

## ステップ4: 修正（failがある場合）

fail判定の項目に対して:

- [ ] 修正内容を具体的に提示した
- [ ] 修正がスキルの他の部分を壊さないことを確認した
- [ ] 修正を適用した

#### 完了条件
- 全てのfail項目に対して修正が完了していること
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ5: 再チェック（最大3回ループ）

修正後のスキルに対してステップ3を再実行する。

- fail が 0 になるまでループ（最大3回）
- 3回で合格しない場合は必ずユーザーに報告すること

#### 完了条件
- 全項目が pass または n/a であること
- または、3回ループ後にユーザーに必ず報告済みであること
- この完了条件を満たすまで、結果報告（ステップ6）に進んではならない

---

## ステップ6: 結果報告

チェック結果を必ずユーザーに報告すること。以下を必ず含めること:

- チェック回数
- 検出・修正した問題の数
- 最終結果（全項目のpass/fail/n/a）

---

## 禁止事項

- 品質チェックリストを読まずにチェックしてはならない（ステップ1必須）
- 1項目でも判定をスキップしてはならない（全件テーブル出力が義務）
- 「カテゴリ1〜3は全てpass」のような一括判定は厳禁
- fail を無視して完了にしてはならない
- 修正で品質が下がった場合にそのまま進めてはならない

## エッジケース

| 状況 | 対応 |
|:-----|:-----|
| scripts/ のコードがある場合 | pro-quality-standards.md の基準も合わせてチェックする |
| 対象スキルが Skill Checker 自身の場合 | 通常通りチェックする（自己参照は問題ない） |
| 品質チェックリストが見つからない場合 | references/skill-quality-checklist.md を確認。なければユーザーに報告 |
| 修正3回で合格しない項目がある場合 | ユーザーに判断を仰ぐ |
| SKILL.md 80行以下でドメイン固有ルールなし | S2-S4はn/a。ただしS1, S5, S6は必ず判定 |
