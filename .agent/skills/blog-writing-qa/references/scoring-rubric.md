# QA採点ルーブリック（8軸・各100点・検算済み）

> このファイルは blog-writing-qa SKILL.md から参照する。
> 採点者（エージェント）はこのルーブリックに従って機械的に採点する。
> 主観的な合否判定は禁止。

---

## ⚠️ 採点前の確認事項

- コンテンツブリーフ（17項目）と記事を必ず照合する
- パーマリンク・アイキャッチ・altタグ は **採点対象外**（公開前チェックリストで人間が確認）
- 禁止表現・断言境界ルールは `blog-writing/references/common-rules.md` を参照

### 🔒 根拠引用ルール（採点のブレ防止・全軸共通）

- **加点項目は、本文から該当箇所を引用（抜粋）できた場合のみ加点する。**
- 該当箇所が見つからない項目、「おそらく満たしている」としか言えない項目は **0点** とする。
- 不合格・要修正項目には、問題箇所の引用を必ず添える（引用のない指摘は書かない）。
- 同じ記事を誰が（どのセッションで）採点しても同じスコアになることを目指す。

## 軸1: SEOキーワード配置チェック（100点）

| 項目 | 点数 | 確認方法 |
|------|------|----------|
| メインKWがH1（タイトル）に含まれる | 20点 | タイトルを目視確認 |
| メインKWが冒頭100文字以内にある | 15点 | 冒頭100文字を抽出して確認 |
| メインKWが1つ以上のH2見出しに含まれる | 15点 | 全H2を確認 |
| メインKWがメタディスクリプションに含まれる | 15点 | ブリーフ17番を参照 |
| サブKWに対応する見出しまたは段落が存在する | 15点 | 各サブKWのトピックが本文で扱われているか確認（機械的な回数ではなくトピックの網羅で判定） |
| 共起語・関連語が本文中に含まれる | 20点 | ブリーフ12番のリストと照合 |
| **満点合計** | **100点** | |

**減点項目**（下限0点）:
- KWスタッフィング（不自然な詰め込み）: -15点/件
- 同KW連続2回以上出現: -10点/件

> 検算: 20+15+15+15+15+20 = **100点** ✅

## 軸2: 構成フレームワーク適合チェック（100点）

### 共通構成（40点）

| 項目 | 点数 |
|------|------|
| H2/H3階層が論理的（見出しのみで流れが読める） | 10点 |
| FAQセクション（3問以上・PAA/サジェスト/現場質問から作成） | 10点 |
| まとめで要点を3点以内で再提示 | 10点 |
| CTAが末尾に自然な流れで設置（直前に本文とつながるブリッジ文がある） | 10点 |

### フレームワーク個別（60点） ※どれを選んでも満点60点

**PREP法の場合**（各15点 × 4項目 = 60点）:

| 項目 | 点数 |
|------|------|
| 冒頭/早期に結論（Point）が提示されている | 15点 |
| 理由（Reason）が説明されている | 15点 |
| 具体的な手順・例（Example）がある | 15点 |
| まとめで結論（Point）に戻っている | 15点 |

**PAS法の場合**（各20点 × 3項目 = 60点）:

| 項目 | 点数 |
|------|------|
| 問題（Problem）を具体的に言語化 | 20点 |
| 放置リスク（Agitation）の提示 | 20点 |
| 解決策（Solution）を具体的に提示 | 20点 |

**AIDA法の場合**（各15点 × 4項目 = 60点）:

| 項目 | 点数 |
|------|------|
| 成果/興味引き（Attention）で始まる | 15点 |
| 背景と課題（Interest）の説明 | 15点 |
| 施策と結果（Desire）が明確 | 15点 |
| 次の行動（Action）につながるCTA | 15点 |

> 検算: 40（共通）+ 60（個別）= **100点** ✅（PREP: 40+60, PAS: 40+60, AIDA: 40+60 どれも同じ）

## 軸3: ライティング品質チェック（100点）

| 加点項目 | 点数 |
|----------|------|
| 一文60文字以内（長文5行以上連続なし） | 15点 |
| 「あなた」に語りかける文体になっている | 15点 |
| 各セクションに「なぜそうするのか」の理由がある | 15点 |
| セクション間に「次への誘導」がある | 10点 |
| 具体的なアクション（「○○の画面を開いて〜」まで）が書かれている | 15点 |
| 専門用語を初出でかみ砕いて説明している | 15点 |
| 表記ゆれがない（ひらがな/カタカナ等） | 15点 |
| **満点合計** | **100点** |

**減点項目**（下限0点）:
- 禁止表現1件につき -20点（「〜という方は多いです」「いかがでしたか？」等）
- `blog-writing/references/common-rules.md` の禁止表現一覧を参照

> 検算: 15+15+15+10+15+15+15 = **100点** ✅

## 軸6: ジェットプロデュースらしさチェック（100点）

| 項目 | 点数 |
|------|------|
| 「伴走者・相談相手」の立場で書かれている（上から教えていない） | 20点 |
| 「あなたのお店では〜」と語りかける表現がある | 15点 |
| 匿名化した現場エピソード（who/where/when的な情報を伴う記述）が1つ以上ある | 20点 |
| ミッション「良いサービスが、正しく見つけられる世の中に」と記事方向性が一致 | 10点 |
| 読者が記事を読んで「自分でも動ける」状態になる（自立支援） | 15点 |
| CTAブロックが設計されている（①検索意図に合った選択 ②オファー価値の言語化＝何が手に入るかが具体的 ③不安解消の一文。frameworks.md「CTAブロックの書き方」参照） | 20点 |
| **満点合計** | **100点** |

**軸6のCTAブロック採点内訳**（20点の内訳）:

> 検算: 20+15+20+10+15+20 = **100点** ✅（CTA内訳: 7+7+6 = 20点 ✅）

## 軸7: 原稿QA技術チェック（100点）

> **採点対象はテキスト原稿で確認可能な項目のみ。** パーマリンク・altタグ・アイキャッチは除外。

| 項目 | 点数 |
|------|------|
| タイトルが28〜32文字で、重要語が前半15文字にある | 15点 |
| メタディスクリプションが80〜120文字で書かれている | 15点 |
| 冒頭付近（最初のH2前後）に「結論・直接回答」がある | 15点 |
| 各H2直下に「その問いへの2〜3文の自己完結回答」がある（パッセージ設計） | 15点 |
| FAQ構造がH2/H3形式で整理されている | 10点 |
| 内部リンク2〜3本・具体的なアンカーテキストで設置されている | 15点 |
| 一次情報・現場エピソード（匿名化）が1つ以上含まれている | 15点 |
| **満点合計** | **100点** |

> 検算: 15+15+15+15+10+15+15 = **100点** ✅

### ⚠️ 軸7「一次情報・現場エピソード」のペンディング運用

現場エピソードが存在しない場合（「ナシ」判定）:

```
【軸7 一次情報 判定】
現状: 現場エピソードが確認できません（0点）。
→ 執筆者への依頼: 「匿名化した現場エピソードを1つ追記してください」
   例: 「○○市の整体院オーナーから、〜という相談を受けたことがあります」
→ 記事ステータス: ペンディング（エピソード追記後に軸7を再採点）
```

PASSの最終判定はペンディング解消後（執筆者が追記→再採点）に行う。

## 軸8: 検索意図充足・事実性・独自性チェック（100点）

> 形式ではなく「中身」を検査する軸。記事がタイトルの問いに本当に答え、事実が正しく、
> 反論に答え、既存記事にない価値があるかを見る。

| 項目 | 点数 | 確認方法 |
|------|------|----------|
| タイトルの問い・検索意図に本文が直接答えている | 20点 | タイトルを質問文に変換し、本文にその答えがあるか確認 |
| ブリーフ14番「独自の要素・情報ギャップ」が本文で実現されている | 20点 | ブリーフ14番と本文を照合（書く予定だった独自要素が実際に書かれているか） |
| 事実・数値・仕様に根拠がある（出典・現場エピソード・Google公式のいずれか） | 20点 | 検証可能な記述を抽出して根拠を確認。Web検索で裏取り可能なものは裏取りする |
| 情報が現行仕様（古いUI・廃止機能・古い数値を書いていない） | 15点 | 手順・画面・仕様の記述を確認。疑わしい箇所はWeb検索で確認する |
| ブリーフ15番「想定反論」に本文が答えている（FAQ・比較表・向き不向き等） | 15点 | ブリーフ15番の反論3つと本文の回答箇所を照合 |
| 既存公開記事と内容が重複していない（同一主張・同一パッセージの繰り返しなし） | 10点 | 内部リンク先・同テーマ既存記事と見出し・主張を比較 |
| **満点合計** | **100点** | |

> 検算: 20+20+20+15+15+10 = **100点** ✅
> ⚠️ 明確な事実誤り（間違った手順・存在しない機能・誤った数値）を発見した場合は、
> 点数に関係なく修正指示を出し、修正まで報告不可とする。

## 総合判定基準

| 判定 | 条件 | 対応 |
|------|------|------|
| **PASS** ✅ | 全軸70点以上 かつ 軸5が100点 かつ 軸7ペンディングなし | 報告へ進む |
| **CONDITIONAL PASS** ⚠️ | 軸5が100点 かつ 他軸に60〜69点あり かつ ペンディングなし | 指摘箇所の軽微修正後に報告 |
| **PENDING** 🟡 | 軸7「現場エピソード」がナシ判定 | 執筆者が追記後に再採点。それまで報告禁止 |
| **FAIL** ❌ | 軸5に違反あり、または任意の軸が60点未満 | 修正後に再検査。報告禁止 |
