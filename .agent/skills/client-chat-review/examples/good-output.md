# 出力の型

実際のチャット事例が knowledge/ に登録されるまでの暫定の型。文章系スキルでは作成者が創作したクライアント文面を実例として置かない方針のため、各欄は〔 〕で「そこに書く内容の指定」だけを示す。実例（改善前後のペア）が登録されたら、この型を実例ベースに差し替える。

## 型0: 壁打ちモード（デフォルト。これが基本形）

```
〔判定1行。例の形: 「ここだけ直せば送れます」「このままは止めた方がいいです」「送ってOKです」〕

〔指摘は最大3つ、重要な順。各行: 「原文の該当箇所」→ 相手からどう見えるか〕

修正版:
〔そのまま送れる1案。数字はユーザー提供かプレースホルダーのみ〕
〔プレースホルダーがある場合のみ〕※送信前に記入: 〔箇所の一覧〕
```

- 見出し・採点・長い解説は付けない
- 相手の直前メッセージが未提供なら「※相手の質問に答えているかは仮判定です」を1行だけ添える
- 問題なしの場合は「送ってOKです。〔良い点を一言〕」で終わり

## 型1: フルモード（「採点して」「フルで」と言われた時だけ）

```
## 辛口総評
〔送信可否の結論を1〜3文で。遠回しにしない〕

## 総合スコア: 〔点数〕/100（判定: 送信可 / 修正推奨 / 送信不可）
〔特に低い軸を1〜2個、軸名と点数で示す〕

## 致命的な問題（最大3つ）
1. 〔ID+問題名〕: 「〔原文の短い引用〕」→〔営業・信頼形成の上でなぜまずいか〕

## 相手からどう見えるか
〔本人の意図と相手の見え方のギャップ。書き方の例: 「丁寧に確認しているつもりでも、相手からは費用回答を避けているように見えます」〕

## そのまま送れる修正版
〔推奨1案のみ。数字はユーザー提供情報かプレースホルダー〕
〔プレースホルダーがある場合のみ〕※送信前に記入: 〔一覧〕

## 修正のポイント
〔なぜこの順番・表現にしたかを簡潔に〕
```
