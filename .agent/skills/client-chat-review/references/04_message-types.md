# 文書タイプ・関係・チャネル別の修正基準

## 何をするか
ステップ5で修正版を組み立てる際の、状況別の基準。ステップ6の出力モード判定もこのファイルで行う。

## 修正文の基本構造（フル構成）
1. 感謝または相手の状況への反応
2. 質問への結論
3. 基本条件（費用・期間など。数字はユーザー提供かプレースホルダーのみ）
4. 条件によって変わる部分
5. 必要な確認事項（質問の理由は相手のメリットで書く）
6. 相手の負担を減らす提案
7. 次の行動

短い返信で足りる場合は必要な項目だけに絞る。全部入りを強制しない。

## チャネル別基準

| チャネル | 基準 |
|:--------|:-----|
| チャット（Chatwork/Slack/LINE等） | 1メッセージ=1〜2論点。目安300字以内。挨拶定型は最小限。箇条書きを活用する |
| メール | 件名と冒頭2行で用件が分かる。目安600字以内。宛名・署名の体裁を保つ |
| 不明 | 原文の体裁から推定し、推定した旨を出力に明記する |

## 関係別の温度感

| 関係 | 注意点 |
|:-----|:-------|
| 見込み客 | 回答の早さと判断材料の提供を最優先。売り込み臭・確約は抑える |
| 既存クライアント | 進行の安心感（現状・次の予定・期限）を必ず入れる |
| 代理店 | 代理店の確認・伝達・報告の負担軽減を重視。エンドクライアント直接連携・会議参加・報告フォーマット統一を必要に応じて提案する |
| 社内 | 敬語の丁寧さより結論と期限の明確さを優先する |

## 文書タイプ別の必須要素

| タイプ | 必須要素（この順で） | 特に検出する問題 |
|:------|:--------------------|:----------------|
| 見積もり・費用回答 | 基本料金/概算 → 変動条件 → 追加料金の条件 | 金額を聞かれて質問だけ返す（C1）。数字の創作（C5） |
| 納期・期間回答 | 目安 → 遅延条件 → 相手側の確認期限 | 確定していない納期の断定（M8） |
| 依頼を断る | 理由 → 対応可能な範囲 → 代替案 | 謝罪だけで終わる（M7） |
| 追加料金の案内 | 契約範囲の事実 → 追加作業の事実 → 費用 | 申し訳なさ過多で条件が曖昧になる（M7と軸7の同時劣化） |
| クレーム対応 | 感情の受け止め → 事実確認 → 責任範囲 → 対応策 → 期限 | 事実確認前の全面過失承認（C6） |
| 催促 | 相手が動きやすい形（選択肢・期限・理由）を渡す | 責め口調（C4）。目的が不明な催促（M4） |
| 短文返信 | 短さ自体は問題にしない | 不安にさせる・冷たい（M6）、次の行動不明（M4）のみ修正 |

## 出力モードの判定

| モード | 条件 | 出力内容 |
|:------|:-----|:---------|
| フルモード | 致命または重大が1件以上 / 79点以下 / ユーザーが採点を明示的に要求 | examples/good-output.md の型1（総評→採点→致命問題→見え方→問題箇所→修正版→ポイント→再発防止） |
| ライトモード | 致命0件・重大0件で80点以上（軽微のみ） | examples/good-output.md の型2（総評→点数1行→微調整または「修正不要」→ポイント1〜2行） |

## 確認方法
修正版が該当タイプの必須要素を順序どおり含んでいるか照合する。材料不足で含められない場合は、プレースホルダー+記入項目一覧にしたかを確認する。

## 不合格時の対応
文書タイプが判別できない場合は、フル構成の1・2・7（反応→結論→次の行動）だけは必ず満たす形にする。
