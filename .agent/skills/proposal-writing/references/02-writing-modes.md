# 文章作成モード

## 目的

依頼を5つのモードに分け、入力、出力、停止条件、文字数計測の扱いを固定する。

## モード判定

| モード | 入力 | 出力 |
|:---|:---|:---|
| 構成設計 | 本文を書く前の整理依頼 | 中心メッセージ、固定情報順序、各部分の役割、順序の理由、離脱・誤解リスク、最初に検証する1変数。完成本文は作らない |
| 新規作成 | 新しい提案文の作成依頼 | 指定がなければ約1,000字版と約2,000字版。片方指定ならその版だけ |
| 辛口レビュー | 既存文の評価依頼 | 送信可否、最重要問題、良い点が本当にある場合だけその点、改善優先順位、誤解・顧客流出・成果保証等のリスク。全文修正版は出さない |
| ブラッシュアップ | 既存文の改善依頼 | 辛口診断、重要な変更理由、固定構造と固定CTAへ再構成した全文修正版 |
| A/B案 | 1変数の比較案依頼 | 指定された1変数だけを変更したA案とB案、変更変数、同一に保った範囲 |

## 辛口レビューとブラッシュアップの違い

辛口レビューは判断材料を返すモードであり、全文を書き換えない。送信可否とリスクを先に示す。

ブラッシュアップは修正実行モードであり、既存文を診断したうえで全文修正版を出す。固定構造に不要な材料は削除し、削除項目のチェック表は出さない。

## コピーしやすい出力形式

本文を書く場合は、解説と本文を混ぜない。推奨形式は次の順にする。

1. 件名が必要な場合だけ短い件名案
2. 本文
3. 実測文字数
4. 必要最小限の補足

通常は「品質確認: 合格」などの自己評価を表示しない。問題がある場合だけ、未確認事実や未達条件を明示する。

## 文字数の計測範囲

本文冒頭から固定CTA末尾までを計測する。件名、設計意図、解説、署名、文字数表示は除外する。

改行コードは除外する。空白、句読点、記号は1文字として数える。目算せず、利用可能な手段で実測する。

## 客観的完了確認

実行時に残す確認は次の3つだけにする。

1. ユーザーが確認していない実績、数字、成果を追加していない
2. 約1,000字版・約2,000字版の本文文字数を実測している
3. A/Bモード時だけ、指定した1変数以外を変更していない

この3項目のための長い採点表や品質ゲートを作らない。

## 不合格時の対応

- 未確認事実が本文に入った場合は削除し、確認済み事実だけで再構成する
- 指定文字数帯から外れた場合は、固定情報順序と固定CTAを維持して調整する
- レビューのみの依頼で全文を書いた場合は、全文を削除してレビュー出力に戻す
- Web制作会社ではない条件外ターゲット向けの本文を作りそうな場合は、本文作成を止める
- 店舗型事業者の制作実績が未確認のWeb制作会社向けであることだけを理由に本文作成を止めない
