# proposal-writing

Web制作会社へ問い合わせフォームから送る、Googleビジネスプロフィール運用の協業提案文を作る。第1弾はWeb制作会社向けだけを扱い、実績掲載や店舗型事業者の制作実績を個別確認済みであることは必須条件にしない。

## ステップ1: 対象とモードを確定する

必要資料: [references/01-target-web-production-company.md](references/01-target-web-production-company.md) と [references/02-writing-modes.md](references/02-writing-modes.md) をこの工程で必ず読むこと。

- [ ] Web制作会社向けGBP協業提案か確認する
- [ ] 構成設計、新規作成、辛口レビュー、ブラッシュアップ、A/B案のどれかを確定する
- [ ] 約1,000字版、約2,000字版、または両方か確定する
- [ ] ユーザーが確認済みとして明示した事実と、未確認の材料を分ける
- [ ] Web制作会社ではない未対応ターゲットの場合は本文を作らず、現在の対応範囲と必要な次工程だけを伝える

#### 完了条件

対象、モード、文字数版、使用できる確認済み事実が分かれていること。このステップの完了条件を全て満たすまで、次に進んではならない。

## ステップ2: 固定構造で作成または診断する

必要資料: A/B案の場合だけ [references/03-ab-testing.md](references/03-ab-testing.md) をこの工程で必ず読むこと。出力例の型に迷う場合だけ [examples/good-output.md](examples/good-output.md) を読む。

- [ ] Web制作会社向けの固定情報順序を必ず使う
- [ ] 中心価値をGBPの機能説明や運用代行単体の売り込みへ弱めない
- [ ] 固定CTAを必ず使う
- [ ] 会社名、代表者名、個別事例、差し込みプレースホルダーを作らない
- [ ] レビューのみの依頼では全文修正版を出さず、ブラッシュアップでは診断後に全文修正版を出す

#### 完了条件

モードごとの出力責務を守り、固定構造と固定CTAから外れていないこと。このステップの完了条件を全て満たすまで、次に進んではならない。

## ステップ3: 客観的完了確認を行う

- [ ] ユーザーが確認していない実績、数字、成果を追加していないことを必ず確認する
- [ ] 指定文字数版の本文は、本文冒頭から固定CTA末尾まで改行を除外して実測する。空白、句読点、記号は1文字として数える
- [ ] A/B案では、指定した1変数以外が同一であることを必ず確認する

#### 完了条件

未確認事実の混入、実測文字数、A/B差分の3点を確認済みであること。これ以外の形式的な自己評価を追加してはならない。このステップの完了条件を全て満たすまで、次に進んではならない。

## ステップ4: コピーしやすく出力する

- [ ] 本文と解説を混ぜず、本文はそのままコピーできる形で出す
- [ ] 本文直後に実測文字数を示す
- [ ] 解説は必要最小限にする
- [ ] 通常は「品質確認: 合格」などの形式的な自己評価を表示しない
- [ ] 問題がある場合だけ、未確認事実や未達条件を明示する

#### 完了条件

ユーザーが本文を取り出しやすく、必要な計測結果だけが添えられていること。このステップの完了条件を全て満たすまで、完了報告してはならない。

## エッジケース

| 状況 | 対応 |
|:---|:---|
| Webマーケティング会社や広告代理店向けを求められた | 本文を作らず、第1弾の対象外であることと次に設計が必要なことを伝える |
| 店舗型事業者の制作実績を確認していないWeb制作会社群へ送りたい | 本文作成を止めず、個別閲覧や制作実績確認を装う冒頭を避けて、Web制作会社向けの広い共通冒頭で作る |
| 実績掲載が少ないWeb制作会社群へ送りたい | 実績掲載の有無で止めず、GBP運用やサービス拡充に興味がある会社だけが読み進める前提で作る |
| 既存文にAI時代の危機感、課題断定、成果保証がある | 固定戦略に不要な材料として削除し、根拠のある協業価値へ再構成する |
| CTA変更や資料送付CTAのA/Bを求められた | 第1弾ではCTAを変数にしないことを伝え、扱える1変数へ戻す |

## 禁止事項

- 企業検索、会社別調査、個社カスタマイズ、フォーム入力、フォーム送信、返信管理をしてはならない
- Webマーケティング会社、広告代理店、その他の提案先向け本文を作ってはならない
- 旧 sales-copywriting 系スキルとの互換性を前提にしてはならない
- 実績、数字、成果、URL、事例を創作してはならない
- 抽象的な称賛、疑似パーソナライズ、相手の課題断定、成果保証、押し付け表現を入れてはならない
- `{{company}}` や `[会社名]` などの差し込みプレースホルダーを入れてはならない
- ランタイム用の長い品質チェックリストや採点表を出力してはならない

## 自己完了確認

- [ ] ステップ1で対象、モード、文字数版、確認済み事実を確定した
- [ ] ステップ2で必要な参照資料を読み、固定構造で作成または診断した
- [ ] ステップ3で未確認事実、実測文字数、A/B差分だけを確認した
- [ ] ステップ4でコピーしやすい形に整えた
- [ ] 未実施のステップがある場合は、完了報告してはならない
