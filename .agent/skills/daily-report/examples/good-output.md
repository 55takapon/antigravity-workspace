# 入力→出力の例

出典: 実レポート `daily-reports/260516daily-report.md`（2026-05-16作成の実物）からの抜粋。collector出力例はv3.0の実実行結果（2026-07-17）。

## 例1: 正常系（collector出力 → レポートヘッダーとCHECK-1）

### 入力（collector実行結果・2026-07-17の実物）

```
===== Daily Report Collector v3.0（Claude Code対応） =====
対象日: 2026-07-17（JST 00:00〜24:00）
検出セッション数: 3

📁 [C--Users-hangy] be4a005e-5386-...
   ユーザーリクエスト数: 5 / 🚨 指摘/トラブル: 1件
   📋 リクエスト一覧（DONEに漏れがないか照合すること）:
     [10:54] いただき、連続がくどい！！
   ⚡ INCIDENT候補 [10:57] KW: ダメ
       → 次、返信済み、確定で登録  ★1 太郎 ■口コミ …全てダメです。…

----- レポートヘッダー用（この行をそのまま貼り付ける） -----
> 検出セッション数: 3件（daily-report-collector v3.0 / 対象日 2026-07-17 JST）
```

### 出力（レポート該当部の型）

```markdown
> 検出セッション数: 3件（daily-report-collector v3.0 / 対象日 2026-07-17 JST）

### CHECK-1：トラブル → スキル反映確認

| # | トラブル内容 | 対象スキル | 反映済み？ |
|---|---|---|---|
| 1 | 口コミ返信案で「いただき」が連続し「連続がくどい！！」と指摘（be4a005e 10:54） | gbp-review-reply | ✅ 表現重複チェックをSKILL.mdに追記済み |
```

※ この日の「KW: ダメ」は口コミ原文（★1レビュー引用）への誤ヒットのため、文脈確認のうえ理由付きで除外する。
逆に本物の指摘「くどい！！」はキーワード未登録で検出されていない — リクエスト一覧の目視照合が必須である実例。
必要なら `config/incident-keywords.json` に検出語を追加する。

## 例2: 異常系（ユーザー指摘をINCIDENTとして経緯付きで記録・実物抜粋）

### 入力（セッション内で発生した事象）

GBPオーナー登録サポート中、登録フローを推測で記載し「またテキトーなこと言ってる？また？また？また？」と指摘された（実セッション 6fd2aacf step 57）。

### 出力（実レポート260516の実記載）

```markdown
| 2 | **GBPオーナー登録フローを推測で書いた（2回目）**（6fd2aacf step 57）—
「Googleマップの住所地点から登録」という入口からのフローを把握せず、
「次はカテゴリ選択」と推測で記載。住所入力が「この入口では省略」の可能性を
考慮しなかった。「またテキトーなこと言ってる？また？また？また？」と指摘。
| gbp-meo-core / 全般 | ⚠️ チャット内で謝罪・不確実性を表明。SKILL.mdへの追記は未着手 |
```

※ この実例の「⚠️ 未着手」は旧運用の悪い状態。現行フローではステップ4で反映を完了させてからステップ5に進むため、「未着手」のままレポートを確定してはならない。

## 例3: 停止系（検出0件）

### 入力

```
検出セッション数: 0
🔴 検出0件です。作業した日なら異常です。
（終了コード: 2）
```

### 出力（レポートは作らない）

```
デイリーレポート作成を中止しました。collectorが検出0件（終了コード2）です。
本日は作業されているはずなので、データソース異常の可能性があります。
確認事項: (1) --date の指定日 (2) C:\Users\hangy\.claude\projects の存在と更新
原因判明までレポートは作成しません。
```
