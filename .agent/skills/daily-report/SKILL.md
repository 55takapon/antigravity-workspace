# daily-report

1日の全セッションを走査してレポート化し、トラブルをスキルに書き込むまでを1セットとする振り返りスキル。レポートを「書いて終わり」にしない。

## 成果物

- ファイル名: `YYMMDDdaily-report.md`（例: `260717daily-report.md`）
- 保存先: `C:\Users\hangy\.gemini\antigravity\daily-reports\`
- 形式: [references/report-template.md](references/report-template.md) に必ず従う

---

## ステップ1: 全セッションの機械走査

- [ ] 収集スクリプトを必ず実行した（会話の記憶やサマリーを情報源にしてはならない）:
  `node C:\Users\hangy\.gemini\antigravity\.agent\skills\daily-report\scripts\daily-report-collector.js`
  （前日以前の分を作る場合は `--date YYYY-MM-DD` を付ける）
- [ ] 出力末尾の「レポートヘッダー用」行をそのままレポート冒頭に貼り付けた
- [ ] 終了コード2（検出0件）の場合は作成を中止し、原因をユーザーに必ず報告した

#### 完了条件
- スクリプトが1件以上のセッションを検出し、ヘッダー行を転記済みであること
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ2: 前回レポートの確認（CHECK-3）

- [ ] 前回の `YYMMDDdaily-report.md` を開き、NEXT ACTIONと再発防止ピックアップを全件確認した
- [ ] 各件を 完了 / 継続（理由と次アクション付き）/ 未着手 のいずれかに必ず判定した

#### 完了条件
- 前回ピックアップ全件の判定が済んでいること（初回は「初回レポートにつきスキップ」と明記）
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ3: レポート作成

- [ ] CHECK-1〜3の記入基準と禁止パターンを [references/checks.md](references/checks.md) で必ず確認した
- [ ] スクリプト出力のリクエスト一覧をDONEセクションと1件ずつ照合した（漏れ確認）
- [ ] INCIDENT候補を精査し、経緯（何が起きて→どう指摘され→どう直したか）付きで記録した
- [ ] DONEを重要度順に並べた（判定基準はchecks.md）

#### 完了条件
- 全セッションの主要作業がDONEに含まれ、テンプレートの全セクションが埋まっていること
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ4: スキルへの反映（CHECK-1）

- [ ] 本日のトラブル・調べ直しを、対象スキルのSKILL.mdまたはreferences/に必ず追記した
- [ ] 再発防止ルール化すべきものは NG_RULES.md（knowledge/chat_ng_registry/artifacts/）に登録した
- [ ] レポートの「反映済み？」欄を実際の反映結果で更新した

#### 完了条件
- 「未反映」のまま残っている項目がないこと（レポートに書くだけで終わりにしてはならない）
- この完了条件を満たすまで、次のステップに進んではならない

---

## ステップ5: 品質検査

- [ ] `daily-report-quality-check` スキルを必ず実行した（省略禁止）
- [ ] 指摘があれば修正し、再検査で全項目通過を確認した
- [ ] レポートをファイル保存し、パスをユーザーに報告した

#### 完了条件
- 品質検査が通過済みで、保存パスを報告済みであること
- この完了条件を満たすまで、作業を完了してはならない

---

## エッジケース

| 状況 | 対応 |
|:-----|:-----|
| スクリプトが検出0件（終了コード2） | 作成中止。日付指定ミスかデータソース変更を疑い、ユーザーに報告する |
| 前日分を翌朝に作成したい | `--date` で前日を指定する（タイムスタンプはJSTで判定される） |
| 調べ直し・トラブルが本当にゼロの日 | 「本日は発生なし」と明記する（省略すると確認したか不明になる） |
| 日をまたいだセッション | 対象日のJST 00:00〜24:00の発話だけが集計される。翌日分は翌日のレポートに載る |
| INCIDENT候補が引用文への誤検出 | キーワード検出は候補にすぎない。文脈を確認し、誤検出は理由付きで除外してよい |
| 反映先スキルが存在しないトラブル | 新規スキル作成の要否を判断し、必要なら skill-creator を起動する |

---

## 禁止事項

- スクリプトを実行せずにレポートを作成してはならない（記憶・サマリーは情報源として禁止）
- 検出0件のままレポートを作成してはならない
- クライアント名・業種・数値を推測で書いてはならない（一次データで裏取りできないものは「未確認」と明記）
- トラブルをレポートに書くだけでスキルに反映せず完了してはならない
- 「発生なし」の明記を省略してはならない
- daily-report-quality-check を省略して完了報告してはならない
- 独自フォーマット・独自命名・独自保存場所で作成してはならない
