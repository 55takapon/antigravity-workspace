# daily-report

> 振り返りはレポートを「書いて終わり」にしない。**必ずスキルに書き込んでから完了とする。**

## ファイル命名規則

```
YYMMDDdaily-report.md

例:
  260429daily-report.md   ← 2026-04-29 のレポート
  260430daily-report.md   ← 2026-04-30 のレポート
```

保存場所: `C:\Users\hangy\.gemini\antigravity\daily-reports\`

## レポート作成フロー（順序厳守）

```
STEP 0: 【絶対スキップ禁止】本日の全セッションをスクリプトで走査する

         ★ 会話サマリー（上位15件）は絶対に使わない。セッションが多い日は15件を超える。
           ファイルシステムを直接走査するスクリプトだけが信頼できる情報源。

         【0-A】スクリプトを必ず実行する（省略絶対禁止）:
           node .agent/skills/daily-report/scripts/daily-report-collector.js

         【0-B】出力の「検出セッション数」をレポートのヘッダーに必ず記載する:
           > 検出セッション数: N件（0-A実行結果）
           この行がなければレポートは未完成。

         【0-C】出力の「📁 セッションID...」を1件ずつDONEと照合する:
           各セッションのリクエスト一覧がDONEに含まれているか目視確認。
           疑問があるセッションはoverview.txtを直接開いて確認する。

         ★ 「スクリプトを実行した」≠「全セッション確認済み」
            0-B（検出数記載）と0-C（照合）の両方が完了して初めて「確認済み」。
         ↓
STEP 1: 前回レポート（YYMMDDdaily-report.md）を開く
         → CHECK-3（前回ピックアップ・NEXT ACTION）を全件確認
         ↓
STEP 2: STEP 0で収集した情報をもとに、本日のトラブル・つまずきをリストアップ（CHECK-1）
         → ユーザーの厳しい指摘（「デタラメ」「出来損ない」等）は特に重点的に記録
         ↓
STEP 3: 対象スキルのSKILL.mdを全て更新してから次のSTEPへ進む
         ↓
STEP 4: 「調べ直し・探し直し」パターンを記録（CHECK-2）
         ↓
STEP 5: DONE / IMPROVEMENT / 数字 / NEXT ACTION を記入
         → DONEは重要度順に並べる（小ネタを先頭にしない）
         ↓
STEP 6: 翌日確認用「再発防止ピックアップ」を整理してファイル保存
         ↓
STEP 7: 【品質チェック】完成したレポートを以下の観点でセルフチェック
         □ STEP 0で特定した全セッションの主要作業がDONEに含まれているか？
         □ ユーザーが厳しく指摘した事項がINCIDENTに記録されているか？
         □ クライアント名・業種名が正確か？（推測で書いていないか？）
         □ 重要度の順序が適切か？（小ネタがメインになっていないか？）
```

## 3大 MUST CHECK

### CHECK-1：トラブル → スキル反映確認

本日発生したトラブル・つまずきを全件リストアップし、各項目を確認する：

```
□ 対象スキルの注意事項またはバージョン履歴に追記済みか？
□ 未反映 → 今すぐ SKILL.md を更新する（レポート完成前に行う）
□ 対象スキルが存在しない → 新規スキル作成の要否を判断する
□ NG_RULES.md に該当ルールとして登録済みか？（When/What/How to verify の3条件で）
□ 本日、NG_RULES.md の既存ルールに抵触した事象はなかったか？（すり抜け検知）
```

**絶対ルール: レポートに書くだけで終わりにしない。スキルに書き込むまで完了しない。**
**絶対ルール: NG_RULES.md への登録なしに「再発防止済み」とは言わない。**

---

### CHECK-2：調べ直し・探し直し 再発防止ピックアップ

以下のパターンが1回でも発生した場合、必ずスキルへ記録する：

| NGパターン | 具体例 |
|---|---|
| 同じ情報を複数回検索した | APIエンドポイントを2回以上調べた |
| 「どこに書いたっけ？」が発生した | ファイルパスが分からなくなった |
| 同じエラーで再度詰まった | 先週と同じエラーで止まった |
| 手順が分からず最初から調べた | セットアップ手順を毎回調べる |
| ツールの使い方を再確認した | コマンドオプションを毎回調べる |

**ルール: 同じ内容の調べ直しは2回以上許容しない。1回目で必ず記録・スキル化する。**

発生なし → レポートに「本日は発生なし」と明記する（省略不可）

---

### CHECK-3：前回ピックアップ進捗確認

```
□ 完了 → [x] にマーク
□ 未着手・継続中 → 理由と次アクションを記載
□ 漏れ発見 → 優先度を上げて本日対応
```

前回レポートなし（初回）→「初回レポートにつきスキップ」と明記する

## NGパターン

- ❌ トラブルをレポートに書くだけでスキルに書かない
- ❌ 前回の NEXT ACTION を確認しないままレポートを書く
- ❌ 「調べ直し」が起きても記録しない
- ❌ 「発生なし」の記載を省略する（確認したかどうか不明になる）
- ❌ NEXT IDEAS だけ書いて NEXT ACTION を書かない
- ❌ **全セッションのチャット履歴を探索せずにレポートを書く（STEP 0スキップ）**
- ❌ **小ネタ（ココナラ出品等）をメインに書き、重大トラブル（データ品質問題等）を省略する**
- ❌ **クライアント名・業種を推測で書く（必ず一次データ（セッションログ）で確認する）**
- ❌ **トラブルの経緯を省略してサラッと書く（何が起きて→何回やり直して→どう直したかを残す）**
- ❌ **「スクリプトを実行した」=「全セッション確認済み」と宣言する（スクリプト出力のリクエスト一覧をDONEと照合するまで確認完了ではない）**
- ❌ **中止・変更の判断をレポートに書く際に根拠数値を省略する（重複率・成功率・件数等を必ず記載）**
