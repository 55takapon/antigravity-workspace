# 入力→出力の型

投稿の完成文サンプルは置かない（作成者が想像した完成文を見本にすることは品質基準で禁止されているため）。
ここでは「入力の実例」と「出力の型（構造）」を示す。完成文の質は references/ のルールとQAで担保する。

---

## 正常系: 人柄系素材からの実行例

### 入力（実データ。出典: `clients\knowledge-taka-jet\self-output-knowledge-ledger.md` カードSELF-0002）

```markdown
# 入力カード
- 素材テキスト: 長女のニュージーランドホームステイの見送りで関空へ。トイレで掃除のおばちゃんに「綺麗にしてくれてありがとう」って言ってみた。「はい! いってらっしゃい!」って、めっちゃ元気に返してくれた。期待していなかった反応が返ってきた。愛を届けたら返ってくるんだと実感した小さな出来事。
- 投稿の目的: リプライ誘発
- ジャンル: 人柄系（倫理法人会・日常・思考）
- ターゲット読者: 仕事や家庭で人間関係に少し疲れている30〜50代
- 一次情報: SELF-0002の逐語「『綺麗にしてくれてありがとう』って言ってみた（略）『はい! いってらっしゃい!』って、めっちゃ元気に返してくれた」
- アカウント: jetproduce
- 対象プラットフォーム: X →（承認後）Threads・Instagram
- ユーザーからの個別指示: なし
```

### 出力の型（writerが提出すべき形）

```markdown
## 使用した型と選定理由
体験談型（STAR+学び）。固有の場面（関空のトイレ）と逐語があるため。

## 本命案
（1行目: フック。「体験」型 — 日常の一場面から入る。約140字以内）

（空白行）

（本文: 場面描写 → 行動 → 予想外の反応（逐語をそのまま使う） → 学び。
2〜3行ごとに空白行。外部リンクなし。ハッシュタグ0〜3個）

（最終行: 答えやすい問いかけCTA 1つ）

## 代替フック案
1.（「告白」型のフック 140字以内）
2.（「問い」型のフック 140字以内）

## 想定文字数
（実測値を書く）
```

## 正常系: 管理者がユーザーへ出す承認依頼の形

```markdown
## X投稿案のご確認
### 本命案
（本文全文）
### 代替フック案
1. …
2. …
### QA採点結果
（qa-criteria.md のレポート表。総合点と全軸の減点理由入り）
### 確認のお願い
修正指示があればお知らせください。「OK」でThreads・Instagram版の作成に進みます。
```

## 異常系: 一次情報のない依頼

### 入力

> 「AIってすごいよねっていう投稿作って」

### 正しい対応（writerに渡さず管理者が止める）

```markdown
このままだと一般論だけの投稿になり、バズの生命線である一次情報がありません。
以下のどれかを教えてください（1つで十分です）:
1. AIで実際に何をして、何が起きましたか?（作業時間・数字・失敗談など）
2. お客様や周囲の反応で印象に残った場面はありますか?
3. 台帳（knowledge-taka-jet）の素材から関連カードを探しますか?
```

## 異常系: QA3回不合格

### 正しい報告の形

```markdown
X案がQAを3回通過できませんでした。
- 不合格の根本原因: （例: 素材の一次情報が1文しかなく、③一次情報・独自性が6点止まり）
- 試した改稿: （各回の変更点1行ずつ）
- ご相談: 素材の追加提供 / 目的の変更（リプ誘発→保存誘発） / このまま公開 のいずれかをご指示ください。
```
