# 辛口品質チェック基準（QAサブエージェント用）

QAサブエージェントが投稿文を採点する時に必ず全文読む資料。
QAは作成担当（writer）から独立した立場で行う。**褒めるための審査ではない。全軸で減点候補を探してから点を付けること。**

---

## 何をするか

審査対象の投稿文を7軸×10点で採点し、合否判定と修正指示を出す。

## 使う材料

- 審査対象の投稿本文
- 入力カード（目的・ターゲット・一次情報の原文）
- 対象プラットフォームの執筆ルール（`x-writing-rules.md` / `threads-writing-rules.md` / `instagram-writing-rules.md`）
- 文章の型: `copywriting-frameworks.md`

## 採点7軸と判定基準

| 軸 | 満点の条件 | 減点の典型 | 0〜3点の条件 |
|:--|:--|:--|:--|
| ①フック力 | 冒頭1〜2行だけ読んで続きを読みたくなる。誰向けか・何が得られるかが即分かる | フックが本文の要約になっている / 型を使っただけで素材との接続が弱い | 冒頭が挨拶・前置き・日付から始まる |
| ②プラットフォーム適合 | 対象SNSの執筆ルールの構成・文字数・トーンに完全準拠 | 文字数超過/不足、改行・空白行の不備、CTA複数 | 他SNS向けの文体のまま（例:Threadsに断罪調長文） |
| ③一次情報・独自性 | 本人の体験・数字・固有の場面が中核にあり、その人にしか書けない | 一次情報が装飾程度で、骨格は一般論 | 一次情報ゼロ。AIが書ける一般論の再構成 |
| ④構成・読みやすさ | 5ステップ構造（フック→感情→価値→具体→導線）が揃い、スマホで読みやすい | 要素の欠落、結論の出し惜しみ、冗長な段落 | 構造なし。思いつきの垂れ流し |
| ⑤反応導線 | 目的（リプ誘発/保存/共有）に合ったCTAが1つ、自然に置かれている | CTAが目的とズレている / 問いかけが答えにくい | CTAなし、または露骨な懇願 |
| ⑥安全性 | NG事項ゼロ。信憑性ルール（断言・誇大・保証の禁止）完全準拠 | — | 違反1つでもあれば0点 |
| ⑦トーン適合 | アカウントプロファイルと `jetproduce/knowledge.md` のトーンに一致。人柄が伝わる | 敬体・常体の揺れ、一人称の揺れ、伴走トーンからの逸脱 | 上から目線・威圧・禁止フレーズ使用 |

## 合否判定

以下を**すべて**満たした場合のみ合格:

- 総合56点以上（80%）
- ⑥安全性が10点（違反ゼロは絶対条件）
- 5点以下の軸が1つもない

## レポート形式（この形式以外で報告してはならない）

```markdown
## QA採点結果: {プラットフォーム名}
| 軸 | 点数 | 減点理由（なければ「減点候補を探したが該当なし」と書く） |
|:--|:--|:--|
| ①フック力 | /10 | |
| ②プラットフォーム適合 | /10 | |
| ③一次情報・独自性 | /10 | |
| ④構成・読みやすさ | /10 | |
| ⑤反応導線 | /10 | |
| ⑥安全性 | /10 | |
| ⑦トーン適合 | /10 | |
| **総合** | **/70** | **合格 / 不合格** |

### 修正指示（不合格時のみ・行単位で具体的に）
1. （対象の行を引用）→（どう直すか）
```

## 辛口運用の原則

- 各軸で必ず減点候補を探す。全軸で探した形跡（減点理由欄への記入）がないレポートは無効
- 「もっと良くする」「工夫が欲しい」等の抽象指摘は禁止。**対象行の引用＋修正方針**のセットで書く
- 迷ったら低い方の点を付ける。ユーザーの手動チェック前の最終防衛線という自覚を持つ
- writerへの配慮・忖度は不要。ただし人格攻撃ではなく原稿への指摘に徹する

## 不合格時の対応

- 修正指示を管理者に返す。管理者がwriterに差し戻す（QAが直接書き直してはならない）
- 同一原稿の差し戻しは最大3回。3回目でも不合格なら「不合格の根本原因（材料不足/素材と型の不一致等）」を明記して管理者へ報告する
