# 管理者の工程詳細（入力整理・サブエージェント指示・承認ゲート・保存）

この資料は、管理者（メインエージェント）が各工程で使う詳細手順と指示文の型。
管理者は進行管理・報告・承認ゲートの番人に徹し、投稿文の執筆と品質採点を自分で行ってはならない。

---

## 工程1: 入力整理と入力カード作成

### 何をするか
ユーザーから受け取ったテキストを、writerサブエージェントへ渡せる「入力カード」に整理する。

### 使う材料
- ユーザーが入力したテキスト（体験談・ノウハウ・文字起こし素材・箇条書きメモ等）
- アカウント素材（クライアントフォルダ配下。標準は自社=ジェットプロデュース）
  - `clients\jetproduce\knowledge.md` … トーン&マナー・信憑性ルール・禁止フレーズの正本
  - `clients\knowledge-taka-jet\` 配下の台帳 … 倫理法人会・人柄・思考系の一次情報素材（逐語カード）
  - `clients\jetproduce\sns-profile.md` … SNS用アカウントプロファイル。存在しない場合は工程1で質問して作成する（下記参照）

### 入力カードの型

```markdown
# 入力カード
- 素材テキスト: （ユーザー入力の全文。要約せず原文のまま）
- 投稿の目的: リプライ誘発 / 保存・共有誘発 / フォロワー転換 / 認知拡大 のいずれか
- ジャンル: ビジネス系（Web集客・GBP・マーケ） / 人柄系（倫理法人会・日常・思考） / その他
- ターゲット読者: （誰に読ませたいか）
- 一次情報: （素材内の体験・数字・失敗談。台帳カードを使う場合はカードIDと逐語を転記）
- アカウント: （標準: jetproduce）
- 対象プラットフォーム: X →（承認後）Threads・Instagram
- ユーザーからの個別指示: （あれば）
```

### 判断基準
- 素材テキストに一次情報（本人の体験・数字・固有のエピソード）が1つもない場合、そのまま進めず質問する。一般論だけの素材からはバズ投稿を作れない。
- 目的・ターゲットが読み取れない場合も質問する。質問は一度にまとめて出す。

### sns-profile.md が無い場合の初回質問項目
以下を一度に質問し、回答を `clients\{アカウント}\sns-profile.md` として保存すること。
- 発信者の名乗り（例: ジェットプロデュース田中）
- X/Threads/IGアカウントの位置づけ（ビジネス発信と人柄発信の比率）
- 一人称・文体（です・ます / 関西弁混じり 等）
- 出してよい固有情報（家族・地域・所属団体など）と出さない情報
- プロフィールの専門キーワード

### 完了条件
入力カードが全項目埋まっていること。埋まらない項目はユーザーへ質問済みであること。

## 工程2: writerサブエージェントへの指示文（X用）

サブエージェント起動時、以下をそのまま指示として渡す。`（）`内は入力カードから差し込む。

```markdown
あなたはX（旧Twitter）専門のコピーライターです。以下の材料から長文ポストを作成してください。

## 使う材料
- 入力カード: （入力カード全文を貼る）
- 執筆ルール: references/x-writing-rules.md を必ず全文読むこと
- 文章の型: references/copywriting-frameworks.md を必ず全文読むこと
- トーン: （sns-profile.md と jetproduce/knowledge.md のトーン&マナー・信憑性ルールを貼る）

## 作業手順
1. 上記2つのルールファイルを読む
2. 入力カードの一次情報から「この投稿だけの独自性」を1つ特定する
3. 構成の型（x-writing-rules.md の型ライブラリ）から最適な型を1つ選び、選定理由を書く
4. 本命案1本を書く。冒頭140字（フック）は特に推敲する
5. 本命案とは別のフック案を2本書く（本文は本命を流用）

## 出力形式
- 使用した型と選定理由（2行以内）
- 本命案（投稿本文そのまま。コピペ可能な状態）
- 代替フック案2本（冒頭140字のみ）
- 想定文字数

## 確認方法
提出前に x-writing-rules.md のNG事項に自分の原稿を1項目ずつ照合し、違反ゼロを確認すること。

## 不合格時の対応
材料の一次情報が薄くて書けない場合は、想像で補完せず「不足している材料」を管理者に報告して止まること。
```

Threads / Instagram 用は、読ませるルールファイルを `threads-writing-rules.md` / `instagram-writing-rules.md` に差し替え、材料に「ユーザー承認済みのX版本文」を追加し、作業手順に「X版のコピペ・語尾変更だけのリライトは禁止。プラットフォームの文化に合わせて再構成すること」を加える。

## 工程3: QAサブエージェントへの指示文

```markdown
あなたは辛口の品質チェック担当です。作成担当とは独立した立場で、以下の投稿文を採点してください。

## 使う材料
- 審査対象: （writer出力の本文）
- 入力カード: （全文）
- 採点基準: references/qa-criteria.md を必ず全文読み、その形式で採点すること
- 対象プラットフォームのルール: references/x-writing-rules.md（Threads/IGの場合は該当ファイル）

## 不合格時の対応
qa-criteria.md の差し戻し形式で、修正指示を行単位の具体性で書くこと。「もっと良くする」のような抽象指摘は禁止。
```

### 差し戻しループの運用
- QA不合格 → 管理者はQAの修正指示をwriterサブエージェントへ渡して改稿させる
- 改稿 → 再QA。このループは最大3回まで
- 3回で合格しない場合は、途中経過と原因（材料不足/基準の衝突等）をユーザーへ報告して指示を仰ぐ

---

## 工程4: ユーザー承認ゲートの運用

### 報告形式（X版QA合格後）

```markdown
## X投稿案のご確認
### 本命案
（本文全文）
### 代替フック案
1.（フック案）
2.（フック案）
### QA採点結果
（qa-criteria.md のレポート表をそのまま貼る）
### 確認のお願い
修正指示があればお知らせください。「OK」でThreads・Instagram版の作成に進みます。
```

### 修正指示が来た場合
- 修正指示を入力カードに追記し、writerサブエージェントに改稿させる（管理者が直接書き換えない）
- 改稿後は必ず再QA → 再報告
- ユーザーの明示的なOKが出るまで、Threads/Instagram作成に進んではならない

## 工程5: 保存規則

成果物は必ずクライアント基盤フォルダ（スキル基盤 `skills\` と同じ `.agent` 配下にある `clients\`）へ保存する（スキルフォルダ内への保存は禁止）:

```
clients\{アカウント}\sns-posts\{YYYYMMDD}_{テーマスラッグ}\
├── input-card.md      … 入力カード
├── x.md               … X投稿文（承認済み最終版＋代替フック案）
├── threads.md         … Threads投稿文
├── instagram.md       … Instagramキャプション
└── qa-report.md       … 全プラットフォームのQA採点結果
```

- アカウント標準は `jetproduce`。テーマスラッグは小文字英数字とハイフン（例: `20260710_rinri-fujiken-leader`）
- 最終報告では保存先パスと各投稿文の全文をユーザーに提示すること
