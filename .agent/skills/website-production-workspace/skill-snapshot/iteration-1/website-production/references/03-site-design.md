# サイト設計と制作プロンプト

## 目的

材料カードと業種別方針から、トップページの構成と制作者がそのまま使える制作プロンプトを作る。

## 使う材料

- 材料カード
- 業種別方針
- サイト挿入画像一覧
- 参考URLや既存サイト
- 目的とCTA
- 出力先プロジェクトフォルダ

## 見る観点

- ファーストビューで何が記憶に残るか
- 画像、見出し、CTAが同じ役割を重複していないか
- 国内サイトとして自然な文字量、余白、導線か
- 汎用3カラムカードの量産感が出ていないか
- スマホで単なる縦積みになっていないか
- 高品質な主役画像があるのに、小さな右カラム画像として弱く扱っていないか
- ファーストビューの文字量、ラベル、タグが多すぎて、第一印象を鈍らせていないか
- 全セクションが白背景、中央見出し、薄いカード、同じ余白で処理されていないか
- ヒーロー画像だけが強く、下の通常セクションが既製テーマの並びに戻っていないか

## 作業手順

1. 初見3秒で何を記憶させるかを1文で決める。例: 誰の、どんな不安や欲求を、どう変えるサイトか。
2. ロゴと社名を隠しても残る、業種・地域・商品・人柄に紐づいた固有の視覚モチーフを1つ決める。
3. サイトの中心メッセージを1文で決める。
4. ファーストビューに、主役画像、メインコピー、サブコピー、CTAを置く。補足情報は必要最小限にする。
5. 主役画像の品質が高く、空気感や信頼感を担える場合は、左右2カラムではなく、画面幅いっぱいの背景画像または大判ビジュアルを優先する。
6. ファーストビューの文字は、メインコピー、1から2行のサブコピー、CTA最大2つを基本にする。タグ、バッジ、長い説明文は原則置かない。
7. セクションを、目的に近い順へ並べる。店舗なら商品・空間・アクセス、企業なら強み・サービス・実績を優先する。
8. セクションごとに、認知、共感、証明、比較、行動などの役割を割り当て、見た目の型を変える。
9. 3カラムを使う場合は、写真主役、ラベル比較、ステップ、編集罫線など意味のある形にする。
10. 制作プロンプトの冒頭に、必須スキル使用ゲートを入れる。
11. 制作プロンプトの冒頭または実装条件に、出力先プロジェクトフォルダを明記する。例: `出力先は <作業ディレクトリ>\demo-xxx とし、直下には作成しないでください。`
12. 制作プロンプトはMarkdown見出しで、実行前提、役割、材料、デザイン方針、画像、構成、実装条件、確認方法を書く。
13. 下層展開が想定される場合は、トップページ後に展開しやすいナビゲーション名を入れる。
14. 店舗・事務所などローカルビジネスでは、NAP（名称・住所・電話）の表記統一と、Googleマップ埋め込みまたはGBP（Googleビジネスプロフィール）への導線をアクセスセクションに含める（公開時の詳細は [08-static-publish.md](08-static-publish.md)）。

## 文字量ルール

- ファーストビューは、メインコピー、1から2行のサブコピー、CTA最大2つを基本にする。
- ファーストビューの補足バッジ、タグ、キーワードチップは原則置かない。置く場合も1つまでにし、読み飛ばしても意味が通る内容にする。
- メインコピーはPCで2行以内、スマホで3行以内を目安にする。
- サブコピーは70字前後までを目安にし、詳しい説明は次セクションへ送る。
- サービス、強み、流れの本文は短く切る。長文説明をカード内に詰め込まず、見出し、短文、詳細導線、FAQへ分ける。

## クリエイティブ品質基準

- 整っているだけのサイトではなく、初見3秒で「誰の何をどう助けるサイトか」が記憶に残るトップページにする。
- ロゴと社名を隠しても、その業種、地域、提供価値が残る固有の視覚モチーフを最低1つ入れる。
- ファーストビューは説明の場ではなく、印象を決める場として設計する。業務列挙、タグ、バッジを詰め込まず、約束、対象者、次の行動だけを残す。
- 3カラムを使う場合は、同じ大きさの角丸カードを横に並べるだけで終えない。番号、写真比率、罫線、ラベル、主従差、余白差のうち最低2つを設計する。
- 全セクションを「英字ラベル、中央見出し、短文、カード」の同じ型で処理しない。各セクションに、認知、共感、証明、比較、行動などの役割差を持たせる。
- サービス一覧は、写真主役のバナー、罫線だけの編集リスト、主役1つ+補助2つ、比較表、ステップ型などから業種に合う型を選ぶ。
- CTAは全箇所で同じ見た目と文言にしない。初回相談、業務確認、問い合わせなど、場所ごとの心理段階に合わせる。
- 色、書体、余白、角丸、線、影はデザイントークンとして指定し、雰囲気だけで使わない。
- ヒーロー以外の通常セクションにも、業種固有のモチーフ、写真、罫線、番号、余白設計を入れる。
- 余白は単なる空きではなく、主役を立てるための編集要素として使う。重要情報には大きい余白、補助情報には小さい余白を与える。

## デザイントークン初期値（案件ごとに上書きする前提のデフォルト）

毎回ゼロから発明せず、この初期値から出発して案件のトーンに合わせて上書きする。制作プロンプトにはトークン表として明記する。

| トークン | 初期値 | 備考 |
|:---|:---|:---|
| spacing scale | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px | セクション間は64〜96px、カード内は16〜24pxを基準 |
| type scale（本文基準16px） | 12 / 14 / 16 / 18 / 22 / 28 / 36 / 48px | 大見出しは `clamp(28px, 4vw, 48px)` のように可変にする |
| 角丸 | 0 / 4 / 8 / 16px | 業種トーンで1系統に統一（上質系は0〜4px、親しみ系は8〜16px） |
| 罫線 | 1px、テキスト色の20〜30%透過 | 編集的な区切りに使う。多用しない |
| 影 | 2段階のみ（浅: hover用 / 中: 浮遊要素用） | ぼかし過多の濃い影は禁止 |
| 色 | ベース（背景）/ テキスト / プライマリ / アクセント（CTA専用） | アクセントはCTA以外に使わない |

## 日本語タイポグラフィ基準

- 本文: 16px基準、`line-height: 1.8` 前後、`letter-spacing: 0.02〜0.05em`。
- 見出し: `line-height: 1.3〜1.5`、大見出しはやや広めの letter-spacing。
- 英字ラベル（セクション見出しの添え字）: 小さめ（11〜13px）+ 広め letter-spacing（0.1em前後）。多用せず、全セクション同型の原因にしない。
- フォントペアの初期候補（Google Fonts、業種トーンで選ぶ）:

| トーン | 見出し | 本文 |
|:---|:---|:---|
| 信頼・コーポレート | Noto Sans JP（Bold） | Noto Sans JP |
| 上質・和・こだわり | Shippori Mincho / Zen Old Mincho | Zen Kaku Gothic New |
| モダン・親しみ | Zen Kaku Gothic New / M PLUS 1p | 同左 |
| 英字アクセント併用 | Montserrat / Cormorant（英字のみ） | 日本語は上記から |

- メインコピーは固有名詞や意味の切れ目の途中で改行させない（`<br>` または `span` で改行位置を制御する）。
- 数字・価格は等幅または英字フォントで揃えると引き締まる。

## 確認方法

- 制作プロンプトがそのまま実行できる。
- 冒頭に `website-production`（本体スキル）の必須使用ゲートがあり、スキルを読めない場合に構築を始めない指示がある。
- 出力先プロジェクトフォルダが明記され、直下作成と確認なしの上書きを禁止している。
- 未完成の穴埋め、省略記号、未定稿表記がない。
- スライド用語がWeb制作指示へ混ざっていない。
- ファーストビューがテンプレ的な左テキスト、右画像の型に固定されていない。
- ファーストビューの文字量制限と、3カラム/カードの造形ルールが明記されている。
- 通常セクションが既製テーマの白背景+中央見出し+カードだけで処理されていない。
- 初見3秒で記憶させる内容と、ロゴを隠しても残る固有の視覚モチーフが明記されている。
- セクションごとの役割とシルエット差が明記されている。

## 不合格時の対応

- 材料不足なら完成文を作らず、質問または前提条件へ戻す。
- 汎用テンプレ感が強い場合は、主役素材、業種固有モチーフ、初見3秒で記憶させる内容から再設計する。
- 文字量が多い場合は、ファーストビュー、カード、CTA、FAQへ役割を分けて削る。
