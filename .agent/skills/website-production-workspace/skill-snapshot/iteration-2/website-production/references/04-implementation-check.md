# 実装と検証

## 目的

プロのコーダーが作ったかのような、保守しやすく崩れにくいトップページを作る。実装後は表示崩れを確認し、修正してから報告する。

## 使う材料

- 制作プロンプト
- サイト挿入画像
- 実装条件
- 既存プロジェクトの構成
- 出力先プロジェクトフォルダ

## 見る観点

- 作成予定パスが案件ごとの新規プロジェクトフォルダ内になっているか
- `index.html`, `style.css`, `script.js`, `images/` などを直下やスキル直下へ作ろうとしていないか
- 既存ファイルを確認なしに上書きしないか
- セマンティックなHTMLになっているか
- CSSの色、余白、文字サイズが管理されているか
- 画像比率とトリミングが安定しているか
- PC、タブレット、スマホで横スクロールやはみ出しがないか
- CTAが見つけやすく、タップしやすいか
- ファーストビューの文字量が多すぎず、画像、コピー、CTAの主従が明確か
- 既製テーマ感、均等カード量産、全セクション同型の単調さが残っていないか
- 通常セクションの見出し、余白、背景、カード、罫線に役割差があるか
- 初見3秒で、業種、対象者、提供価値、次の行動が分かるか
- ロゴと社名を隠しても、その案件らしさが残るか
- 各セクションをぼかして見ても、同じ白背景、中央見出し、カードの繰り返しに見えないか

## 作業手順

1. 実装前に出力先プロジェクトフォルダを確定する。新規制作やデモサイト制作では、案件ごとの新規フォルダを作成し、フォルダ名は英数字・ハイフン中心にする。
2. 作成予定パスを確認し、`index.html`, `style.css`, `script.js`, `images/` などが出力先プロジェクトフォルダ内に入ることを確認する。
3. カレントディレクトリ直下、スキル直下、既存プロジェクト直下へ確認なしに作成・上書きしない。同名フォルダがある場合は、明示された既存フォルダなら中身を確認し、明示がなければ別名フォルダを作るか確認する。
4. 既存プロジェクトがある場合は構成、パッケージ、起動方法を確認する。
5. 新規静的サイトの場合は、HTML、CSS、必要最小限のJavaScriptで作る。
6. CSSはカスタムプロパティで色、余白、文字サイズ、角丸、線を管理する。
7. 固定幅だけに頼らず、`max-width`、`grid`、`flex`、`clamp()`、`aspect-ratio`、`object-fit` を使う。
8. ファーストビューは、PCとスマホで主役画像、メインコピー、CTAが最初に目に入るか確認する。
9. 初見3秒テスト、ロゴ隠しテスト、セクションシルエットテスト、コピー削減テストを行う。
10. サービス、強み、流れ、問い合わせの各セクションが同じカード型の繰り返しになっていないか確認する。
11. 実装後に「確認幅とブレイクポイント標準」の各幅で確認する。
12. サブエージェントまたは別視点レビュー担当が使える場合は、構築後の品質レビューを依頼する。
13. サブエージェントを使えない場合は、未実行理由を記録し、同じ観点で代替セルフレビューを行う。
14. はみ出し、重なり、横スクロール、画像主役の切れ、ボタン文字崩れ、文字詰め込み、レビュー指摘を修正する。

## 確認幅とブレイクポイント標準

メディアクエリは**SWELL準拠**に統一する（静的サイトでも同じ。将来のWordPress化やSWELL案件との一貫性のため）。

- 主ブレイクポイント: **960px**（959px以下でナビをハンバーガー化。`@media (max-width: 959px)` / `@media (min-width: 960px)`）
- 補助ブレイクポイント: **600px**（599px以下をスマホ扱い。`@media (max-width: 599px)`）

確認は次の幅で行う（ブラウザDevToolsまたはブラウザ操作ツールで各幅を表示して確認する）:

| 幅 | 想定 | 特に見る点 |
|:---|:---|:---|
| 375px | スマホ標準 | FVの主役・コピー・CTA、横スクロール |
| 599px / 600px | 補助境界の両側 | 境界での切り替わり崩れ |
| 768px | タブレット | 2カラムの詰まり、画像トリミング |
| 959px / 960px | **主境界の両側（SWELLで最も崩れやすい点）** | ナビ切り替え、ヘッダー、余白の飛び |
| 1440px | PC標準 | 最大幅制御、余白バランス |

## アクセシビリティ最低基準

- [ ] 文字コントラスト比 4.5:1 以上（24px以上または18px太字の大きい文字は 3:1 以上）
- [ ] タップ領域はボタン・リンクとも 44×44px 以上
- [ ] すべての意味のある `img` に内容が伝わる `alt`（装飾画像は `alt=""`）
- [ ] 見出し階層を飛ばさない（h1は1つ、h1→h2→h3の順）
- [ ] キーボードフォーカスが見える（`outline` を消しっぱなしにしない）
- [ ] リンク・ボタンの文言だけで行き先が分かる（「こちら」のみは不可）

## 出力形式

```markdown
## 実装結果
- 出力先フォルダ:
- 作成ファイル:
- 使用画像:
- 上書きしていないこと:
- 確認した表示幅:
- 修正した崩れ:
- クリエイティブ品質の確認:
- サブエージェント品質レビュー:
- 残課題:
```

## 確認方法

- 画像が表示され、レイアウトが崩れていない。
- `index.html` の保存先が新規プロジェクトフォルダ内である。
- 既存ファイルを確認なしに上書きしていない。
- カレントディレクトリ直下やスキル直下に作成していない。
- スマホで横スクロールが発生していない。
- 標準確認幅（375/600境界/768/960境界/1440）で確認し、特に960px前後で崩れていない。
- アクセシビリティ最低基準（コントラスト、タップ領域、alt、見出し階層）を満たしている。
- ボタン、メニュー、住所、価格などが読める。
- 不要な重複CSSや意味のないdivが増えすぎていない。
- ファーストビューが長文説明、タグ、バッジ、ボタンの詰め込みになっていない。
- 全セクションが同じカード、同じ中央見出し、同じ薄グレー背景の繰り返しになっていない。
- 初見3秒テスト、ロゴ隠しテスト、セクションシルエットテストの結果が報告できる。
- サブエージェント品質レビュー、または使えなかった理由と代替レビュー結果が報告できる。

## 不合格時の対応

- 表示確認ができない場合は、実行できなかった理由と未確認リスクを報告する。
- 崩れが見つかった場合は、報告前に修正する。
- 案件らしさが残らない場合は、カード数を減らし、罫線リスト、大判写真、比較表、ステップ、CTA帯などへ組み替える。
- 文字量が多い場合は、ファーストビューとカードから削り、下部セクションやFAQへ移す。
- サブエージェントレビューで重大指摘が出た場合は、修正して再確認するまで完了報告しない。
