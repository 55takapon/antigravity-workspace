# 静的サイトの公開・計測・問い合わせ導線

## 目的

WordPressを使わない静的サイト（HTML/CSS/JS）を、デモで終わらせず、公開・SEO・計測・問い合わせ導線まで実用状態にする。受託の静的案件（納品形態A）では、このファイルの工程を完了せずに納品してはならない。

## 使う材料

- 実装済みの静的サイト一式（`index.html`, `style.css`, `script.js`, `images/`）
- 店舗・会社の確定情報（名称、住所、電話、営業時間 — NAP）
- LINE公式アカウント、Instagram、Googleビジネスプロフィール（GBP）のURL
- ドメイン、サーバーまたはホスティング先の情報
- GA4プロパティ、Google Search Consoleへのアクセス

## 問い合わせ導線の標準ルール

- **コンタクトフォームが必要な案件は、静的サイトにしない。** モード判定へ戻り、WordPress（SWELLまたはオリジナル軽量テーマ）を選ぶ。
- 静的サイトの問い合わせ主導線は、**LINE公式アカウント、電話（`tel:`リンク）、Instagram DM、GBP経由**のいずれかにする。業種と客層で選ぶ（店舗・サロン→LINE/電話、若年層→Instagram、シニア層→電話）。
- 例外的に「静的のままフォームが必須」の場合のみ、外部フォームサービス（SSGform、Googleフォーム埋め込みなど）を使い、**送信テストと通知先の受信確認**を必ず行う。
- LINE導線を主にする場合、友だち追加ボタンはファーストビュー直下または固定表示に置き、「LINEで気軽に相談」など行動ハードルを下げる文言にする。

## 公開前チェックリスト

### メタ情報・基本ファイル

- [ ] 各ページ固有の `<title>`（ページ名｜店名・社名）と `<meta name="description">`
- [ ] OGP（`og:title`, `og:description`, `og:image` 1200×630px, `og:url`, `twitter:card`）
- [ ] favicon（`favicon.ico` + `apple-touch-icon` 180×180px）
- [ ] `<html lang="ja">`、canonical、viewport
- [ ] `sitemap.xml` と `robots.txt` を作成しルートへ配置
- [ ] 404ページ（`404.html`。ホスティング側の割り当て設定も確認）

### 構造化データ（JSON-LD直書き）

- [ ] LocalBusiness（店舗・事務所: 名称、住所、電話、営業時間、地図座標）
- [ ] FAQPage（FAQセクションがある場合）
- [ ] BreadcrumbList（下層ページがある場合）
- [ ] リッチリザルトテストで検証する

### 計測

- [ ] GA4（gtag.js）を全ページに設置
- [ ] GSC所有権確認 + `sitemap.xml` 送信
- [ ] イベント計測: `tel:` クリック、LINEボタンクリック、外部予約リンククリック（GA4イベントまたはGTM）
- [ ] 計測が本番ドメインで発火することを公開後に確認

### GBP・ローカル導線（店舗・事務所案件では必須）

- [ ] NAP一致: サイト・GBP・SNSで名称、住所、電話の表記を完全に統一する
- [ ] GBP側の「ウェブサイト」欄に本番URLを設定する
- [ ] サイトのアクセスセクションにGoogleマップ埋め込みまたはGBPへの導線を置く
- [ ] MEO運用が案件に含まれる場合は `gbp-meo-core` スキル（`.agent/skills/gbp-meo-core/`）を参照し、制作とMEOをセットで設計する

## デプロイ先の選定

| デプロイ先 | 向くケース | 注意点 |
|:---|:---|:---|
| 既存レンタルサーバー（FTP/ファイルマネージャ） | 顧客が既にサーバー契約あり、独自ドメイン運用済み | SSL設定と公開ディレクトリを確認。既存ファイルを上書きしない |
| Cloudflare Pages | 新規・低予算・高速表示重視 | 無料枠で十分。独自ドメインのDNS移管または設定が必要 |
| Netlify | 新規・フォーム例外対応も視野 | 無料枠の帯域制限に注意 |

- 公開前にステージング（プレビューURLまたはBasic認証付きディレクトリ）で顧客確認を取る。
- 公開手順・更新手順（どのファイルをどこへ上げるか）を1枚のメモにして納品物へ含める。

## 確認方法

- 本番URLで全ページが表示され、SSL（https）エラーがない。
- OGPがLINE・X・Facebookのシェアプレビューで正しく出る。
- GA4のリアルタイムで自分のアクセスとtel/LINEクリックイベントが確認できる。
- GSCでsitemapが「成功」になっている。
- NAPがサイト・GBP・SNSで一致している。
- 問い合わせ主導線（LINE/電話）がスマホ実機で1タップで動く。

## 不合格時の対応

- フォームが必要と後から判明した場合は、外部フォームで暫定対応せず、WordPress化（納品形態B/C）の再見積を提示する。
- NAP不一致が見つかった場合は、正の表記を顧客に確定してもらい、全媒体を修正してから公開する。
- 計測が発火しない場合は、公開完了と報告せず、原因（タグ位置、ドメイン設定）を解消してから報告する。
