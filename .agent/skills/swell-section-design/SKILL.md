# SWELLセクションデザイン

SWELLサイトの「セクション1つ分」の設計とコード出力を行うスキル。
装飾カタログから選ぶのではなく、情報の役割からレイアウト型を判定し、案件のトークンで毎回生成する。

- サイト全体の新規制作、受託工程、画像生成は `website-production`（`../website-production/SKILL.md`）を使う。本スキルはそのセクション単位の部品工場として単独でも併用でも使える。
- 必要なツールを使って即座に自動実行すること。ユーザーへの確認は不要（レイアウト型の提案が複数拮抗する場合の選定だけ確認してよい）。

## ステップ1: セクション材料カードを作る

- [ ] セクションの目的（認知・共感・証明・比較・行動のどれか）を1つ決める
- [ ] 載せる項目と項目数、各項目の関係（対等か、主役1+補助か、順序ありか）を整理する
- [ ] ブランド色・書体・既存サイト・写真素材の有無を確認し、確認済みと未確認を分ける
- [ ] website-production 案件なら、材料カード・design-system.md・業種別方針を必ず流用する
- [ ] トークン未確定なら `../website-production/references/03-site-design.md` のデザイントークン初期値で仮置きし、仮置きであることを記録する
- 入力: 依頼文、業種、載せたい内容、ブランド情報、素材
- 出力: セクション材料カード（目的・項目・主従関係・トークン・素材）

完了条件: 目的が1つに決まり、項目の主従関係と確認済み/未確認の材料が分かれていること。この完了条件を満たすまで次に進んではならない。

## ステップ2: レイアウト型を判定する

必要資料: [references/01-layout-selection.md](references/01-layout-selection.md) をこの工程で必ず読むこと。

- [ ] 「3項目だから3カラム」と即断せず、判定表で情報の役割から型を1つ選ぶ
- [ ] 採用する型と、採用しなかった型・理由を必ず記録する
- [ ] 3カラムを採用する場合は、造形ルール（番号・写真比率・罫線・ラベル・主従差・余白差）から最低2つを必ず適用する
- 入力: セクション材料カード
- 出力: レイアウト判定結果（採用型・理由・不採用型・造形ルール）

完了条件: 型が1つ選ばれ、選定理由と不採用理由が言語化されていること。この完了条件を満たすまで次に進んではならない。

## ステップ3: 配色とタイポグラフィを確定し検証する

必要資料: [references/02-color-typography-check.md](references/02-color-typography-check.md) をこの工程で必ず読むこと。

- [ ] テキスト色・罫線色・背景階調をすべてトークンから導出する（直書き禁止）
- [ ] 本文4.5:1以上、大見出し3:1以上のコントラスト比を全組み合わせで必ず計算する
- [ ] 不合格の組み合わせはトークン側を調整し、調整で意図が崩れる場合はユーザーに報告する
- 入力: レイアウト判定結果、トークン
- 出力: 確定トークン表、コントラスト検証結果

完了条件: 全テキスト/背景ペアの比率が数値で記録され、不合格が残っていないこと。この完了条件を満たすまで次に進んではならない。

## ステップ4: SWELL貼付用コードとプレビューを生成する

必要資料: [references/03-swell-implementation.md](references/03-swell-implementation.md) をこの工程で必ず読むこと。出力の形に迷う場合だけ [examples/good-output.md](examples/good-output.md) を読む。

- [ ] 案件ごとの名前空間クラスで完全スコープしたHTML/CSSを生成する
- [ ] ブレークポイント959px/599pxのレスポンシブCSSを必ず含める
- [ ] SWELL貼付手順（どのブロックへ何を貼るか）を難易度目安つきで添える
- [ ] プレビューHTMLは案件プロジェクトフォルダまたは scratch に作成する。スキルフォルダ直下・カレント直下に確認なしで作成してはならない
- 入力: レイアウト判定結果、確定トークン表
- 出力: SWELL貼付用コード、貼付手順、プレビューHTML

完了条件: コードがスコープ済み・レスポンシブ込み・貼付手順つきで、プレビューの保存先が明記されていること。この完了条件を満たすまで次に進んではならない。

## ステップ5: 品質確認と報告

- [ ] シルエットテスト: ぼかして見ても汎用カード並びに見えないか（造形ルールが効いているか）を必ず確認する
- [ ] コントラスト・レスポンシブ（959px/599px）・スコープ漏れを必ず再確認する
- [ ] ブラウザでプレビューを開ける環境なら実表示を確認する。できない場合は理由を報告に明記する
- [ ] 報告に、採用型と理由、不採用型、トークン表、検証結果、保存先を必ず含める

完了条件: 上記確認が済み、報告に全項目が含まれていること。この完了条件を満たすまで完了報告してはならない。

## エッジケース

| 状況 | 対応 |
|:---|:---|
| ブランド色・書体が未提供 | トークン初期値で仮設計し、「仮置き・上書き前提」と成果物に明記する |
| ユーザーが「必ず3カラムで」と型を指定 | 3カラムで作るが、造形ルール最低2つの適用は省略しない |
| コントラスト不合格がトークン調整で解決しない | 代替配色を2案提示し、ユーザーに選定を仰ぐ |
| SWELL以外（静的サイト等）で使いたい | コードはそのまま流用し、SWELL貼付手順の代わりに読み込み方法を書く |
| 旧3col-design-toolの再現を頼まれた | 旧ツールは廃止済み。references/03 の移植パターンを案件条件で再生成する |
| 項目数が4以上ある | 3カラムに押し込まず、罫線リスト・2列グリッド・比較表を判定表で再検討する |

## 禁止事項

- 情報の役割を判定せずに3カラムカードを既定で出力してはならない
- テキスト色・背景色をトークン外で直書きしてはならない（コントラスト未検証の色出力禁止）
- 案件と無関係な装飾バリエーションの一覧（カタログ）を成果物にしてはならない
- 名前空間スコープのないCSS、`!important` に依存したCSSを出力してはならない
- 同一案件内で全セクションを同じシルエットで量産してはならない
- スキルフォルダ直下・カレント直下へ確認なしにプレビューHTMLを作成・上書きしてはならない
