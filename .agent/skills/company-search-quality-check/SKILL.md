# 企業リスト品質チェックスキル

> [!CAUTION]
> **このスキルは company-search スキルで収集・書き込みを行った「後」に必ず実行する。**
> チェック完了・全軸の結果報告なしに「完了しました」と報告することを禁止する。
> ユーザーに気づかせて指摘させることは失格。システムが全て検知・是正してから報告する。

---

## 🧭 設計思想（v2.0 根本改定）

### なぜ「ネガティブフィルター」では永遠に終わらないか

過去のアプローチ：
```
広く拾う → 業種NGキーワードを追加 → また漏れる → また追加 → 永遠に繰り返す
```

このモデルの欠陥：
- 「東京計器株式会社」のような計測機器メーカーを、**「計器」というキーワードを知らないと弾けない**
- 世の中の業種は無限にあり、NGリストは永遠に完成しない
- 問題が発覚するのは「ユーザーが見てから」であり、プロとして失格

### 正しい設計：ポジティブフィルター（v2.0〜）

```
収集 → 「Webマーケ会社である証拠がHPにあるか？」を確認 → ない → 問答無用で除外
```

**キーワードHIT（L列）が `×` = Webマーケ非該当 → 自動で `✕`**

SEO・MEO・Google広告・SNS運用・Webマーケティングといった言葉が企業のHP上に存在しない会社は、業種名を知らなくても対象外と判定できる。これにより：
- 計測機器メーカー、食品メーカー、鉄道会社など**あらゆる非対象業種を業種名なしで除外可能**
- NGリストの追加は原則不要
- ユーザーが指摘する前にシステムが処理済みにできる

> [!IMPORTANT]
> **NGキーワードリスト（`NG_INDUSTRY_KEYWORDS`）は補助的な存在。** メインのゲートは「キーワードHIT確認」。キーワードHITが設定されていないシートでのみNGリストが主役になる。

## 🎯 チェック対象の問題（MECE定義）

| # | 軸 | 問題カテゴリ | 発生事例 |
|---|---|---|---|
| A | 企業名・代表者名 | 人名・見出し語・文章片の混入 | 「長 伊藤淳一」「福田執筆の」「中山陽平中小企業」「企業情報」「経歴」 |

### AXIS-A：企業名・代表者名ノイズ一掃（`sweep_all.js` + `fix_representative_names.js`）

```bash
node sweep_all.js
node fix_representative_names.js
```

**企業名（C列）の排除パターン：**

| カテゴリ | 例 | ロジック |
|---|---|---|
| ラベル・見出し語 | 「企業情報」「会社名」「経歴」 | `INVALID_PATTERNS` 完全一致 |
| 人名（スペース区切り） | 「長 伊藤淳一」「杉岡 秀一」 | `isJapanesePersonName` + 空白区切り |
| 人名（スペースなし） | 「石原新也」 | `isJapanesePersonName` + 法人格なし |
| 役職切れ端＋人名 | 「長　伊藤」 | 漢字1文字+スペース+人名 |
| 執筆者情報 | 「福田執筆の」 | `執筆\|監修\|著\|編集` キーワード |
| NG業種 | 大学・病院・ホールディングス | `isNGIndustry` |
| 上場企業 | 東証プライム等キーワード | `isListedCorporation` |

**代表者名（D列）の排除パターン：**

| カテゴリ | 例 | ロジック |
|---|---|---|
| 名前＋一般名詞の連結 | 「中山陽平中小企業」→「中山陽平」 | `NOUN_NOISE` 末尾除去 |
| 役職切れ端 | 「長 林順之亮」 | `^長[\s　]+` 除去 |
| ラベル語 | 「経歴」「代表取締役」 | `LABEL_WORDS` 完全一致 |
| 文章片 | 「伝える力を」 | 助詞含む+長さ判定 |
| 人名判定不合格 | 上記以外の非人名 | `isJapanesePersonName` → false |

> [!NOTE]
> **代表者名抽出の根本問題：** `REPRESENTATIVE_PATTERNS` のスペースなしパターンが `{3,8}` （8文字まで貪欲マッチ）だったため「中山陽平中小企業」のような連結が発生していた。v2.0で `{3,5}` ＋ negative lookahead `(?![漢字・ひらがな・カタカナ])` に修正済み。今後の新規収集では抽出段階で防止。

### AXIS-B：フォームNG判定精度チェック（`check_ng_forms.js`）

```bash
node check_ng_forms.js --sheet [シート名]
```

**誤検知してはいけないパターン（除外済み）：**

| 分類 | 例 | 理由 |
|---|---|---|
| 安心訴求 | 「営業電話することはありません」 | 自社がしない宣言 → 営業可能 |
| 職種名・部署名 | 「印刷媒体・WEB媒体／営業・制作」 | 役職・事業部の説明 |
| 自社サービス説明 | 「弊社営業より提供のご案内」 | 自社からの行動説明 |
| コンテンツ文章 | 「営業と兼任でマーケティングを担当〜」 | ブログ・コラム記事 |
| 法的表明 | 「金融商品取引法に基づく勧誘」 | プライバシーポリシー |

### AXIS-E：業種・規模ポジティブフィルター（`apply_auto_reject.js`）★新設

```bash
node apply_auto_reject.js
```

**判定ロジック（優先順）：**

1. **キーワードHIT = `×`** → `【自動判定】キーワード未検出（Webマーケ非該当の可能性）`
   - WebマーケキーワードがHPに存在しない = 対象外業種の可能性が高い
   - 計測機器・食品・不動産・建設 など、**業種名不問で処理可能**
2. **従業員20名以上** → `【自動判定】従業員20名以上`
3. **資本金1000万円以上** → `【自動判定】資本金1000万円以上`

> [!IMPORTANT]
> **AXIS-Eは毎回実行すること。** `apply_auto_reject.js` は新規収集後だけでなく、`fill_employees.js` / `fill_capital.js` でデータ補完した後も実行する。データが埋まるたびに判定対象が増える。
