# chat-ng-learner

> **目的**: ユーザーからの品質NG指摘を「その場」でAI全体の絶対ルール（KI）として刻み込み、数日後の再発やすり抜けを完全に防ぐ。

## 📍 中央レジストリ（Knowledge Item）

チャットでのNG情報は、**会話開始時に強制ロードされる Knowledge Item** として以下の場所に保存されている。

```
C:\Users\hangy\.gemini\antigravity\knowledge\chat_ng_registry\artifacts\NG_RULES.md
```

> **なぜ Knowledge Item か？**: KI は新しい会話を開始するたびにシステムがサマリーをAIの脳内に強制注入する仕組み。これにより「数日経ったらAIがルールを忘れていた」というすり抜けを構造的に防止する。

---

## ⚙️ 強制学習プロセス（Stop → Think → Log → Resume）

### トリガーワード

以下のワードをユーザーが使用した場合、**NG指摘として検知し、強制学習プロセスを発動する**：

| トリガー | 発動条件 |
|---|---|
| `NG:` / `NG！` | 明示的なNG宣言（最優先） |
| `やり直し` / `やり直して` | 作業のやり直し要求 |
| `違う` / `それ違う` | 結果の否定 |
| `それダメ` / `ダメ` | 品質否定 |
| `何回言えば` / `また同じ` | 再発指摘（最重要） |

### プロセス詳細

AIはトリガーワードを検知した場合、**元の作業を中断して以下を完遂する**：

1. **Stop**: 現在進行中のコード生成、ファイル編集、コマンド実行を即座に中断する。
2. **Think**: 何がNGだったか分析し、以下の3条件を満たすルールを言語化する。
3. **Log**: 
   - `knowledge/chat_ng_registry/artifacts/NG_RULES.md` の該当カテゴリの表にルールを追記する。
   - 特定のスキルに関するNGであれば、対象の `.agent/skills/<skill>/SKILL.md` にも同時追記する。
4. **Resume**: NG_RULES.md の更新差分をユーザーに提示し、承認を得てから修正作業を再開する。

## 🔒 ルール登録品質ゲート（3条件必須）

**以下の3条件を全て満たさないルールは登録禁止。** 曖昧なルール（「気をつけます」レベル）はゴミであり、登録しても再発防止にならない。

| 条件 | 説明 | NG例 → OK例 |
|---|---|---|
| **When（いつ発動するか）** | 具体的なトリガー条件 | ❌「レポート作成時」→ ⭕「GBP月次レポートのグラフ描画時」 |
| **What（何をする/しないか）** | 具体的な行動制約 | ❌「気をつける」→ ⭕「数値カラムのカンマを除去してから数値変換する」 |
| **How to verify（どう検証するか）** | ルールが守られたことの確認方法 | ❌「目視確認」→ ⭕「HTMLをブラウザで開きグラフの値が元データと一致するか照合」 |

## ✈️ Pre-flight Check（作業開始前・必須）

**任意のタスクを開始する前に、AIは以下を実行する：**

1. `NG_RULES.md` を開いて全ルールに目を通す。
2. 今回の作業に該当するNGパターンがないか確認する。
3. 該当するルールがあれば、作業計画に組み込む。
4. チャットで「**Pre-flight Check 完了。該当ルール: [ID] or 該当なし**」と宣言する。

---

## 🛬 Post-flight Check（作業完了後・必須）

**任意のタスクが完了した時、AIは以下を実行する：**

1. `NG_RULES.md` を再度開く。
2. 今回の成果物が過去のNGパターンに抵触していないか自己監査する。
3. チャットで「**Post-flight Check 完了。抵触ルール: なし or [ID]（対処済み）**」と宣言する。

> **これがないと「すり抜け」が発生する。** ルールを読んだだけでは不十分。成果物を作った後に再度照合して初めて「すり抜け検知」が機能する。

## 📊 レジストリ運用ルール

### カテゴリ分類

ルールは以下のカテゴリに分類して登録する。タスクの種類に応じて該当カテゴリだけ読めば良い設計。

| カテゴリ | 対象 |
|---|---|
| A: データ破壊・上書き系 | Sheets書き込み、データ移行、復旧作業 |
| B: レポート・出力品質系 | GBPレポート、HTML生成、ドキュメント出力 |
| C: フォーム送信・自動化系 | contact-auto、Playwright操作 |
| D: リードデータ品質系 | スクレイピング、リード収集、重複チェック |
| E: Git/バックアップ系 | git操作、自動バックアップ |
| F: メタルール | Pre-flight/Post-flight、登録プロセス自体のルール |

### 棚卸しルール

- ルール総数が **20件を超えた時点で棚卸しを強制実施** する。
- 解決済み・統合可能なルールを圧縮し、ファイルサイズを小さく保つ。
- 棚卸し前後の件数を記録し、削除・統合の理由を変更履歴に残す。

## 🚫 NGパターン

- ❌ チャットで指摘されたのに「すみません、修正します」とだけ答えて `NG_RULES.md` に記録しない。（**最悪のNG**）
- ❌ 記録はしたが、関連する既存スキル（SKILL.md）のルールを更新し忘れる。
- ❌ 原因と防ぐためのルールが曖昧（「気をつけます」レベル）。3条件を満たさないルールは登録禁止。
- ❌ Pre-flight Check をスキップして作業を開始する。
- ❌ Post-flight Check をスキップして「完了です」と報告する。
- ❌ NG_RULES.md が20件を超えても棚卸しせず放置する。

## daily-report との連携

| daily-report のセクション | chat-ng-learner での役割 |
|---|---|
| CHECK-1（トラブル→スキル反映） | **NG_RULES.md にも反映されたか** を追加確認する |
| CHECK-2（調べ直し再発防止） | 同じ調査を繰り返していないか＝ NG_RULES のすり抜けの兆候 |
| CHECK-3（前回ピックアップ） | 前日のNG対策が実際に機能したか検証する |
