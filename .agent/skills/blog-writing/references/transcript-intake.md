# 音声文字起こしインテーク手順

> SKILL.md「STEP -1：音声素材インテーク」の詳細手順書。
> 音声文字起こし（主に運用者本人の語り）を素材化し、既存の執筆フロー（STEP 0以降）へ
> 流し込むための前工程。**この工程の出力は「素材リスト」であり、記事本文ではない**。
> 記事化はSTEP 1以降の既存ルール（断言境界・現場エピソード・QA）に従う。

---

## この工程のゴール

音声文字起こしを、そのまま執筆できる「整理済み素材」に変換する。

```
入力: 生の文字起こし（フィラー・重複・脱線・話し言葉まじり）
  ↓
出力: ① 素材リスト（下記7項目）
      ② ブリーフ項目へのマッピング草案
      ③ 一次情報候補（primary-info への追記候補）
```

---

## STEP -1-1: クレンジング（雑音の除去）

文字起こし特有のノイズを落とす。**意味のある中身は消さない**。

```
除去するもの:
□ フィラー（えー / あの / まあ / なんか / ええと）
□ 言い直し・重複（同じことを2回言っている箇所は1つに統合）
□ 脱線・雑談（本筋と無関係な話題）
□ 相づち・確認（はい / そうですね 等の単独発話）

残すもの（消去厳禁）:
■ 具体的な数値・固有名詞・体験談
■ 「なぜそう言えるのか」の理由・根拠
■ 読者の悩みに対する具体的な答え・手順
■ 運用者ならではの主観・判断（記事の独自性の核）
```

---

## STEP -1-2: 素材抽出（7項目）

クレンジング後のテキストから、以下を箇条書きで抜き出す。

```
【素材リスト】
A. 主張（この音声で一番言いたいこと・結論）: ___
B. ノウハウ手順（具体的なやり方・ステップ）: ___
C. 固有エピソード（実際の相談・現場の出来事）: ___
   ※ 話者=運用者本人。クライアント事例は必ず匿名化前提でメモ
D. 数値・事実（金額・件数・期間など）: ___
E. 想定読者の悩み（音声内で言及された「お客さんが困っていること」）: ___
F. 読者へのベネフィット（読むとどう変わるか）: ___
G. 補足・余談で使えるネタ（FAQ候補・小ネタ）: ___
```

> A〜Gが薄い場合は、無理に記事化せず「音声の追加・深掘りが必要」と報告する。
> 水増しは禁止（SKILL.md 文字数の考え方に従う）。

---

## STEP -1-3: ブリーフへのマッピング

抽出した素材を、既存ブリーフ（16項目）の該当箇所へ流し込む草案を作る。
**SERP分析（STEP 0）でKW・競合を裏取りする前提**なので、ここはあくまで草案。

| 素材 | 流し込み先（ブリーフ項目） |
|------|--------------------------|
| A 主張 | 1 記事タイトル案 / 8 読後のゴール |
| B ノウハウ手順 | 10 見出し構成（H2/H3）の骨子 |
| C 固有エピソード | `primary-info.md` へ追記候補（→本文の現場エピソードに使用） |
| D 数値・事実 | 14 独自要素（記事タイプ問わず具体数値OK。ただし使い回し禁止・断言境界を守る） |
| E 読者の悩み | 7 ペインポイント |
| F ベネフィット | 8 読後のゴール / 16 メタディスクリプション素材 |
| G 補足ネタ | FAQ候補（最低3問のうちの「現場の実質問」枠） |

> メインKW・サブKW（項目2,3）・検索意図（項目5）・共起語（項目12）は
> **音声から推測せず、必ずSTEP 0のSERP分析で確定する**。音声はテーマの種であって、KWの根拠ではない。

---

## STEP -1-4: 一人称・文体の変換ガイド

話者＝運用者本人のため、語り口がそのままだと記事の文体（SKILL.md の Role / Target Audience）と合わない。以下で整える。

```
【変換ルール】
1. 運用者の独白「〜なんですよ / 〜だと思ってて」
   → 伴走者の語りかけ「あなたのお店では〜ではないでしょうか」

2. 専門用語の口走り（GBP / MEO / CTR 等が音声に出ても）
   → common-rules.md の用語言い換え表に従って平易化

3. 断定的な成果トーク（「これやれば集客増えます」）
   → common-rules.md の断言境界に従う
     ・手順・事実は断言してよい
     ・集客成果・健康効果は断言しない（「〜しやすくなります」等）

4. 内輪ネタ・前提知識
   → 用語ゼロのオーナー読者にわかる説明を補う、または削る
```

---

## STEP -1-5: 引き継ぎ

素材リスト＋ブリーフ草案ができたら、**通常フローへ合流**する。

```
STEP -1 完了
  ↓
STEP 0: SERP分析（抽出テーマでKW・競合・共起語を裏取り）
  ↓
STEP 1: ブリーフ確定（草案＋SERP結果で16項目を埋める）
  ↓
STEP 2以降: 既存ルールどおり（構成→執筆→blog-writing-qa）
```

> ⚠️ 音声起点でも `blog-writing-qa` のPASS判定は必須。スキップ禁止。

---

## NGパターン（この工程固有）

- クレンジングで具体的な数値・体験談まで削ってしまう（一次情報の価値が消える）
- 音声の話し言葉をそのまま本文に貼り付ける（文体変換をしない）
- 音声内容だけでKW・検索意図を決める（SERP分析STEP 0を飛ばす）
- 素材が薄いのに水増しして記事化する（→「深掘り音声が必要」と報告すべき）
- クライアント事例を匿名化せず実名・特定可能な形で書く
