# 構成フレームワーク詳細設計

> このファイルは blog-writing SKILL.md から参照する。
> 各フレームワークの「なぜこの構成か」「どの記事タイプに合うか」を詳述する。

---

## フレームワーク選択の基準

| フレームワーク | 最適な記事タイプ | 読者の状態 |
|-------------|----------------|----------|
| PREP | ハウツー・解説記事 | 「やり方を知りたい」Know/Do意図 |
| PAS | 課題解決・提案記事 | 「困っている・不安」Know意図 |
| AIDA | 事例記事（カテゴリF） | 「成果が見たい・比較したい」Buy/Know意図 |

---

## PREP法（ハウツー・解説記事）

```
■ 導入（問いかけ→共感→ベネフィット→結論の予告）
  └── 冒頭400文字以内に収める
  └── 「この記事を読むと○○がわかります」とベネフィットを示す

■ H2-1: 結論・全体像（Point）
  └── 「ズバリ言うと〜です」から始めてよい
  └── この見出しが「引用可能なパッセージ」になる
  └── H2直下に2〜3文で問いに自己完結的に答えてから詳細へ ← AI検索対策

■ H2-2: なぜそうなのか（Reason）
  └── 「理由は3つあります」と構造化する
  └── 各理由にH3を使う

■ H2-3: 具体的なやり方（Example）
  └── 「実際の操作手順」や「現場エピソード（匿名化）」を入れる
  └── 必須: ○○市の△△院オーナーから実際にこう聞かれた、等の一次情報を1つ
  └── 図解・表・スクリーンショットの要否を判断（H2ごとに）

■ H2-4: 注意点・よくある間違い
  └── 読者が陥りやすいNG例を具体的に

■ H2-5: よくある質問（FAQ）
  └── 最低3問
  └── 出典: PAA / サジェスト / 現場の実質問（創作禁止）

■ H2-6: まとめ（Point）+ 最初の一歩
  └── 要点を3点以内で再提示
  └── 「まず○○から始めてみてください」と具体的な最初のアクションを示す

■ CTA（検索意図に合わせて選択）
```

### PREP法の「引用可能なパッセージ設計」チェック

各H2の直下に必ず以下を実施する（AI検索最適化）：
- その見出しの問いに「2〜3文で自己完結的に答える」
- 詳細・補足はその後に続ける
- 例: H2「Googleマップの情報を更新するには？」直下 → 「Googleビジネスプロフィール（マップ情報）の管理画面から、写真・営業時間・説明文をいつでも更新できます。スマートフォンのGoogleマップアプリからも操作可能です。以下で手順を説明します。」

## PAS法（課題解決・提案記事）

```
■ 導入（問いかけで悩みを言語化）
  └── 「〇〇でお困りではありませんか？」で始める
  └── 「偏見・嫌な記憶を代弁する」上級テクニックが特に有効

■ H2-1: 問題の深掘り（Problem）
  └── 読者が「そうそう、まさにそれ」と感じる解像度で書く
  └── H2直下に2〜3文で問題の核心を要約 ← AI検索対策

■ H2-2: このままではまずい理由（Agitation）
  └── 放置した場合のリスクを具体的に（「3ヶ月で〜になる可能性が」等）
  └── 脅しではなく「現実を教える」スタンスで

■ H2-3: 解決策の提示（Solution）
  └── 必須: 匿名化した現場エピソードを1つ以上
  └── 「ジェットプロデュースでは〜という方法を提案しています」と自社軸で語る

■ H2-4: よくある質問（FAQ）
  └── 最低3問（PAA/サジェスト/現場質問から）

■ H2-5: まとめ + 最初の一歩
  └── 要点3点以内

■ CTA（Know意図 → LINE登録・チェックリスト・関連記事を優先）
```

## AIDA法（事例記事専用）

```
■ 導入（Attention: 成果を先に見せる）
  └── 「〇〇をした結果、△△になりました」と成果から入る
  └── 数値がある場合は具体的に（「マップからの問い合わせが月3件→15件に」等）
  └── 数値は使い回し禁止。この記事固有のものを使う

■ H2-1: 状況と課題（Interest）
  └── 「この事例の主人公がどんな状況だったか」を丁寧に描写
  └── 読者が「自分も同じ状況だ」と感じられるかがポイント

■ H2-2: 何をしたか（Desire → 施策）
  └── 具体的な施策を順を追って説明
  └── 「なぜこの施策を選んだか」の理由も必ず入れる

■ H2-3: どう変わったか（Desire → 結果）
  └── 具体的な変化（数値・期間・読者の体験）

■ H2-4: ここから学べること
  └── 「この事例から読者が持ち帰れること」を3点以内で整理

■ H2-5: まとめ
  └── 要点3点以内

■ CTA（Action: Buy/Do意図 → 30分無料診断）
```

## CTA選択表（検索意図 × 記事カテゴリ）

| 検索意図 | 読者の状態 | 1次CTA（記事末尾） | 2次CTA（記事中間） |
|----------|-----------|------------------|------------------|
| Know | 情報収集中・認知段階 | LINE登録 / チェックリスト / 関連記事 | 関連記事誘導 |
| Do | 方法を探している・実行段階 | 30分無料診断 / LINE登録 | 関連記事誘導 |
| Buy | 比較検討中・決断段階 | 30分無料診断 | 事例記事誘導 |
| Go | 場所・連絡先を探している | 問い合わせ / LINE登録 | – |

### 記事中間部のCTA例（Know意図）

```
「ここまで読んでみて、自分のお店に当てはめるとどう考えればいいか
気になってきた方は、こちらの記事も参考になります。」
→ 関連記事への内部リンク
```

## CTAブロックの書き方（記事末尾・全フレームワーク共通）

CTAは「置く」だけでは行動されない。オファー名だけのCTA（「30分無料診断はこちら」）は禁止。
記事末尾のCTAブロックは、以下の3要素をこの順で書く。

1. **ブリッジ文**（1〜2文）
   記事の内容とオファーを橋渡しする。読み終えた直後の読者の頭の中
   ——「自分の店の場合はどうなんだろう」——を言語化する。
2. **オファー価値の言語化**
   オファー名で終わらせず、「受け取ると何が手に入るか」を具体的に書く。
   - NG: 「30分無料診断はこちら」
   - OK: 「30分の無料診断では、あなたのお店がいまマップで何位に表示されているか、どこを直せば見つけてもらいやすくなるかを、その場で一緒に確認します」
3. **不安解消の一文**
   「問い合わせたら売り込まれるのでは」という読者の警戒を先回りして解く。
   - 例: 「診断を受けたからといって、その場で契約をおすすめすることはありません」

### 記入例（Do意図 × 30分無料診断の場合）

```
ここまで読んで、「うちの店の場合は、どこから手をつければいいんだろう」と
感じた方もいると思います。

その「うちの場合」を一緒に確認するのが、30分の無料診断です。
あなたのお店がいまマップでどう表示されているか、
どこを直せば見つけてもらいやすくなるかを、その場でお伝えします。

診断を受けたからといって、契約をおすすめすることはありません。
まずは現状を知るところから始めてみてください。

[ボタン: 30分無料診断を予約する（LINEで簡単）]
```

### CTAブロックのチェック

```
□ 記事本文からCTAへのブリッジ文があるか（唐突にオファーへ飛んでいないか）
□ オファーで「何が手に入るか」が具体的に書かれているか
□ 不安解消の一文があるか
□ オファー名だけのCTAになっていないか
```

## 画像・図解の挿入指針

各H2を書いた後、以下の判断フローで画像・図解の要否を決める：

```
H2を執筆したら確認:
□ 手順・操作説明 → スクリーンショットまたは図解を推奨
□ 比較・選択肢 → 表（テーブル）を使う
□ 概念・構造説明 → 図解（フローチャート等）を検討
□ 事例・ストーリー → before/after画像・グラフを推奨
□ 上記に当てはまらない → テキストのみでOK
```

WordPress/SWELL 入稿時に画像を差し込む位置を `[画像: ○○の説明]` とプレースホルダーで明示しておく。
