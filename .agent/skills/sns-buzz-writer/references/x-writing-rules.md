## アルゴリズム前提（2026年5月更新で確認済みの事実）

1. **AIが投稿の中身（文脈）を読んで評価する**。旧来の「リプライは何点」「URLは減点」といった固定係数の攻略法は廃止された。ユーザーごとに「この投稿を見た人が次にどんな行動をしそうか」を予測して配信される。
2. **単独で完結する投稿が優遇される**。スレッド前提・続き物前提の断片投稿は不利。1ポストで価値が完結すること。
3. **テンプレ感・AI丸出しの無個性文は減点対象**。書き手固有の体験・視点が質評価の中心。
4. **投稿後30〜60分の初速**（特にリプライ・滞在時間・プロフィールクリック）が配信拡大の分岐点。
5. **複製露出低減**が導入され、同一投稿の再掲・セルフリポスト連打ではリーチが出ない。
6. **アカウントのテーマ一貫性**をAIが文脈で判定する。発信ジャンルが迷走するとフォロー外拡散に乗りにくい。
7. **ニッチな専門用語よりも、広いカテゴリ語**（例:「MEO」より「Googleマップ集客」）の方がトピック分類で有利。
8. 減点シグナル: ミュート・ブロック・「興味なし」。グレーゾーンの煽り投稿はリスク。

## 長文ポストの構成ルール

- **冒頭2行（約140字）が生死を分ける**。タイムラインには冒頭しか表示されない。「誰向けか」「何が得られるか」「読む価値」をここで明示する。
- 本文は**PREP法**（結論→理由→具体例→結論）を基本にする。結論を出し惜しみしない。
- **2〜3行ごとに空白行**を入れ、スマホでの圧迫感をなくす。複数の情報は箇条書きで縦に並べる。
- 太字は結論・重要な数字・キーワードだけに使う。
- **CTAは1つに絞る**（リプライでの問いかけ推奨。会話が最も強いシグナル）。
- 文字数の目安は800〜2,500字。素材が薄いのに長くしない。「ただ長いだけ」は滞在時間が伸びず逆効果。
- 一次情報（本人の体験・数字・失敗談）を必ず本文の中核に置く。一般論の再構成だけの投稿を書いてはならない。

## 構成の型ライブラリ（旧sns/スキルから継承。2026年7月に構成として再点検済み）

型は「構成の骨組み」であり、完成文の見本ではない。素材に合わせて1つ選ぶ。

| 型 | 骨組み | 向く素材 |
|:--|:--|:--|
| ノウハウ型 | フック「〜が知らない◯つのこと」→箇条書き5〜7個→問いかけ | 手順・チェックリスト系 |
| 意見・主張型 | フック「正直に言います。〜は間違いです」→理由3〜4点→意見募集 | 業界の常識への異論 |
| 体験談型 | 状況→つまずき→行動→結果→学び（Before/After明示）→共感の問いかけ | 本人エピソード・倫理法人会系 |
| データ/検証型 | 「〜を分析したら予想外のことが分かった」→データ→解説→意見募集 | 実測数字がある素材 |
| リスト型 | 「〜に悩む人が知らない◯選」→番号リスト→「1番刺さったのは?」 | 保存誘発を狙う素材 |
| 速報・解説型 | 「【速報】〜が変わります」→事実→プロ解説→今やること | 仕様変更・ニュース |
| 認知・マインド型 | 「成果を出す人と出せない人の違いは1つの〜」→概念を平易に解説→挑戦の宣言を促す | 思考・気づき系 |
| Googleマップ運用型 | 「上位表示される店が必ずやっている〜」→具体テクニック→自店への問いかけ | GBP/MEO系ビジネス素材 |
| Web集客型 | 「広告費をかけても集客できない会社の共通点」→使い分け解説→診断の問いかけ | マーケ系素材 |

## NG事項（1項目ずつ原稿と照合すること）

- 本文への外部リンク直貼り（リーチ低下。必要なら「リンクはリプ欄↓」でリプライに分離）
- ハッシュタグは0〜3個まで。乱用はスパム判定リスク
- エンゲージメントベイト（「いいねした人に〜」「同意ならRT」等の直接懇願）
- レイジベイト（怒り・不安を煽って反応を取る書き方）
- 誇大表現・効果の断言（「必ず儲かる」「100%上がる」→「〜の傾向があります」「〜といわれています」へ）
- 他プラットフォームのウォーターマーク付き素材への言及・転載前提の文章
- 同一内容の使い回し・再掲前提の構成
- 絵文字の乱用（1投稿3個まで。ビジネス系は0〜1個推奨）
