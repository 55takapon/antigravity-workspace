# 意思決定・構造変更の履歴記録（decision-record）

破壊的変更・設計判断・インシデントが起きたセッションの終了前に、検証済みの事実だけを1イベント1ファイルの不変な記録として `.agent/history/` に残す。全セッション一律の作業ログではなく、「後で必ず探すことになる出来事」だけを記録する。

必要なツール（ファイル作成・編集）を使って即座に自動実行すること。ユーザーへの確認は不要。ただし記録対象かどうかの判定（工程1）を必ず先に行うこと。

## 工程1: 発火判定

この工程では [references/01-trigger-judgment.md](references/01-trigger-judgment.md) を必ず読むこと。

- [ ] 今回のセッションの作業内容を振り返り、記録対象3類型（破壊的変更・設計判断・インシデント）のどれに該当するか判定した
- [ ] 除外条件（日常成果物のみ・軽微な単発修正）に該当しないか確認した
- [ ] 該当しない場合は、記録を作らず「記録対象外」と理由を1行でユーザーに報告して終了した

#### 完了条件
記録対象の類型が特定できているか、対象外として報告済みであること。判定せずに記録を作り始めてはならない。この完了条件を満たすまで次の工程に進んではならない。

## 工程2: 検証済み事実の収集

- [ ] 実際に変更したファイル・フォルダのパスを列挙した（実在を確認できるもののみ）
- [ ] 実行したコマンドと検証結果（テスト・動作確認の出力）を集めた
- [ ] 「やったこと」と「未検証・未対応のこと」を分けた
- [ ] 判断のトレードオフ（採用案・不採用案・理由）を特定した

#### 完了条件
記録する全事実について、実ファイル・実行結果のどちらかで裏付けを説明できること。裏付けのない内容は「未検証」に分類済みであること。この完了条件を満たすまで次の工程に進んではならない。

## 工程3: 記録ファイルの生成と索引更新

この工程では [references/02-record-template.md](references/02-record-template.md) を必ず読み、テンプレートに従うこと。出力の実例が必要なら [examples/good-output.md](examples/good-output.md) を読む。

- [ ] `.agent/history/YYYY-MM-DD_<内容を表す英語スラッグ>.md` を作成した（100行以内）
- [ ] `.agent/history/INDEX.md` に1行の索引を必ず追記した（なければ新規作成）
- [ ] 記録本文に、テンプレートの必須セクション（方針・実施事項・検証結果・未対応）を全て含めた

#### 完了条件
記録ファイルと索引行の両方が存在すること。索引を更新せずに完了してはならない。この完了条件を満たすまで次の工程に進んではならない。

## 工程4: 既存記録システムとの連携

- [ ] スキルを変更した場合は、そのスキルの `references/changelog.md` に1行追記し、詳細は今回の記録ファイルへ委ねた
- [ ] 同じ内容を daily-report や changelog に長文で重複記載していないことを確認した（重複はリンクに置き換える）

#### 完了条件
同一イベントの詳細記述が記録ファイル1箇所だけに存在すること。この完了条件を満たすまで次の工程に進んではならない。

## 工程5: 自己完了確認（省略禁止）

以下を1つずつ振り返り、未実施があれば完了報告してはならない。

- [ ] 工程1: 発火判定を行った（対象外なら理由報告のみで終了した）
- [ ] 工程2: 全事実の裏付けを確認し、未検証を分離した
- [ ] 工程3: 記録ファイルと索引行の両方を作成した
- [ ] 工程4: 既存記録との重複がないことを確認した
- [ ] ユーザーへ記録ファイルのパスと索引の内容を報告した

## 禁止事項

- 検証していない作業を「完了」として記録してはならない（未検証は「未対応・未検証」欄に書く）
- 記録対象外のセッション（日常の成果物作成のみ）で記録ファイルを作ってはならない
- 作成済みの記録ファイルを後から書き換えてはならない（訂正は新しい記録を作り相互リンクする）
- 索引（INDEX.md）の更新を省略してはならない
- 100行を超える記録を作ってはならない（詳細は影響ファイル側に委ね、記録は要点に絞る）
- daily-report・changelog と同じ内容を長文で重複させてはならない

## エッジケース

| 状況 | 対応 |
|:-----|:-----|
| 記録対象か判断に迷う | references/01-trigger-judgment.md の判断フローに従う。それでも迷えば「後で探すか？」で判定し、判定理由を報告する |
| 1セッションに記録対象イベントが複数ある | イベントごとに別ファイルを作る（1イベント1ファイル） |
| 過去の記録に誤りが見つかった | 元ファイルは変更せず、訂正の新規記録を作成し、両方の索引行に相互リンクを付ける |
| INDEX.md が存在しない | 新規作成してから索引行を追記する |
| 記録すべき事実の一部が未検証のまま | 「未対応・未検証」セクションに明記して記録する。検証済みとして書いてはならない |
