# 出力例

## 例1（正常系）: 破壊的変更セッション → 記録ファイル＋索引行

実データに基づく例。出典: `skills-archive/2026-07-07-gbp-meo-retirement/HISTORY.md`（2026-07-07のGBP/MEOスキル大整理セッションで実際に作成されたローカル実ファイル。本スキルはこの実例を型として設計された）。

### 入力（セッションの状況）

- ユーザー承認のもと、旧GBP/MEOスキル12本を廃止しアーカイブへ移動した
- クライアント成果物約90ファイルを `gbp-clients\_monthly-reports\` へ移動し、スクリプト10本のパスを書き換えた
- 保存先をクライアント別でなく共有フォルダにするトレードオフ判断をした

### 出力1: 発火判定（工程1の結論）

> 類型①（破壊的変更）および類型②（設計判断）に該当: スキル12本の廃止・移動と、月次レポート保存先の設計判断。記録を作成します。

### 出力2: 記録ファイル（テンプレート4セクションの記入例・抜粋）

```markdown
# 2026-07-07 GBP/MEOスキル大整理（12スキル廃止・core再構築）

種別: 破壊的変更・設計判断
関連: skills-archive/2026-07-07-gbp-meo-retirement/README.md

## 方針（なぜやったか）
業種別9スキルとpost系3スキルが最新スキル規則に不適合（本体2,000トークン超・references未分離・
未検証数値の混入）かつ運用フローから参照されていないため廃止。法規制部分のみ救出する方針を
ユーザーが承認。

## 実施事項（何をしたか）
- skills/gbp-meo-beauty ほか11本 → skills-archive/2026-07-07-gbp-meo-retirement/ へ移動
- 法規制テーブル → skills/gbp-meo-core/references/industry-regulations.md に集約
- gbp-meo-core/reports/（約90ファイル）→ gbp-clients/_monthly-reports/ へ移動

## 検証結果
- node実行で新パスの解決と90ファイルの認識を確認（batch_report.js等10本のパス書き換え後）
- 廃止スキル名への残存参照がないことをgrepで確認

## 未対応・未検証
- gbp-meo-core/references/ 内に未検証数値が残存（禁止事項でガード済み、刈り込みは未実施）
```

### 出力3: INDEX.md への追記行

```markdown
- [2026-07-07 GBP/MEOスキル大整理](../skills-archive/2026-07-07-gbp-meo-retirement/HISTORY.md) — 破壊的変更・設計判断 / 12スキル廃止・法規救出・レポート保存先変更
```

## 例2（異常系）: 記録対象外セッション → 記録を作らず理由を報告

### 入力（セッションの状況）

- ミート歯科の4月分GBP投稿を4本作成し、gbp-post-quality-check に合格して posts/2026-04.md に保存した
- ファイルの削除・移動・設計判断・インシデントは発生していない

### 出力（工程1で終了）

> 記録対象外: 成果物作成のみのセッションのため（除外条件1: 投稿は posts/2026-04.md 自体が履歴になっている）。履歴ファイルは作成しません。

記録ファイルもINDEX.mdへの追記も行わない。これが正しい動作であり、ここで記録を作るのは禁止事項違反。
