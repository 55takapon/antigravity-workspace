# GBP MEO診断レポート スキル

> **目的**: 見込み顧客のGBPを無料診断 → レポートで機会損失に気づかせる → 「専門家に任せたい」へ導く営業ツール
> **入力**: GoogleマップURL（1つ）
> **出力**: ① HTML診断レポート（PDF化用）② NotebookLM用テキスト ③ 診断データJSON
> **前提**: コアスキル（`gbp-meo-core/SKILL.md`）＋業種別スキルの知識

---

## 1. 実行フロー

```
【入力】
  GoogleマップURL（例: https://maps.google.com/maps?cid=XXXXX）

         ↓

【STEP 1: データ収集】
  ブラウザでGBPページを開き、以下を取得:
  - 基本情報（ビジネス名/カテゴリ/住所/電話/URL/営業時間/説明文）
  - 口コミ情報（件数/平均評価/直近20件のテキスト・評価・日付・返信有無）
  - 写真情報（枚数/種類）
  - 投稿情報（直近の投稿日・件数）
  - 属性情報（設定されている属性一覧）
  - 競合情報（同エリア×同カテゴリの上位3-5社の名前・評価・口コミ数）

         ↓

【STEP 2: スコアリング】
  5軸でS/A/B/C/D評価 → 総合スコア算出
  業種自動判定 → 業種別ベンチマーク適用

         ↓

【STEP 3: レポート生成】
  ① HTML（PDF化用の営業レポート）
  ② NotebookLM用テキスト（スライド作成指示付き）
  ③ PDF（Playwright自動生成）
```

> **🚨 絶対ルール: データ収集の正確性**
> - **口コミサンプリングは「新しい順」ソート後、最新から順に取得**
> - **写真カテゴリは4種類（外観/内観/メニュー/スタッフ）を個別に目視確認**
> - **投稿は「すべての最新情報を表示」で全件確認し、正確な件数をカウント**
> - **属性は「基本情報」タブの最下部まで必ずスクロールして全取得**
> - **口コミ返信は各口コミ直下の「オーナーからの返信」を1件ずつ確認**

## 2. データ収集仕様

### 2.1 ブラウザでの収集手順

エージェントはブラウザサブエージェント（browser_subagent）を使って以下を実行する:

```
1. GoogleマップURLを開く
2. ビジネス名・カテゴリ・住所・電話・URL・営業時間を取得
3. 説明文を取得（⚠️ 下記 2.3 の注意事項を参照）
4. 口コミセクションで件数・平均評価を取得
5. **口コミを「新しい順」にソートしてから**最大15件分スクロール取得（テキスト・評価・日付・オーナー返信有無）
   - **絶対ルール: サンプリングは最新の口コミから開始**
   - 返信の有無は各口コミの直下に「オーナーからの返信」があるかを1件ずつ確認
6. 写真タブで写真枚数を取得。**さらに以下の4カテゴリの有無を個別確認**:
   - 外観写真: 「オーナー提供」の写真に外観があるか
   - 内観/店内写真: 「オーナー提供」の写真に店内があるか
   - 商品/メニュー写真: 該当するカテゴリの写真があるか
   - スタッフ写真: 施術者/スタッフの写真があるか
7. 投稿の全件確認（⚠️ 下記 2.3 の注意事項を参照）
   - 概要タブで「最新情報」セクションを確認
   - 「すべての最新情報を表示」をクリックして投稿一覧を開く
   - 投稿の日付と件数を正確にカウントする（直近3ヶ月分）
   - 投稿の種類（最新情報/イベント/特典）を確認
8. 「基本情報」タブを**最下部まで必ずスクロール**し、全カテゴリの属性を1個ずつ取得
   - バリアフリー、サービスオプション、健康と安全、決済方法など全カテゴリを確認
   - **表示されている属性の総数が2個以下の場合、スクロール不足を疑って再確認**
9. 競合検索（⚠️ 下記 2.3 の注意事項を参照）
```

### 2.3 データ収集上の注意事項

> **⚠️ 説明文の表示場所による違い**
> - **Google検索結果（ブラウザ）** → 説明文は表示される
> - **Googleマップ（ブラウザ版）** → **投稿（最新情報）が存在する場合、説明文が非表示になる**ことがある
> - **Googleマップ（アプリ版）** → 説明文は表示される
> - 診断時の取得手順: ①まずGoogleマップで確認 → ②見つからない場合はGoogle検索（`ビジネス名 地域名`で検索）でナレッジパネルを確認
> - 説明文が設定されていてもGoogleマップブラウザ版では見えない場合がある。この場合はスコアリング上は「設定済み」として加点するが、レポートには「Googleマップのブラウザ版では投稿が優先表示されるため、説明文がPC検索ユーザーに直接見えない可能性があります」と補足する

> **⚠️ 投稿の正確なカウント**
> - 概要タブのトップに表示される投稿は**最新の1件のみ**の場合がある
> - 必ず「すべての最新情報を表示」ボタンをクリックして、全投稿一覧画面を確認する
> - 投稿一覧をスクロールして直近3ヶ月の投稿日を全て記録する
> - 「○週間前」等の相対表示ではなく、表示される**具体的な日付**を記録する

> **⚠️ 競合検索の正確性（最重要）**
> - **検索クエリ**: GBPに表示されている**メインカテゴリ名そのもの**（例: 「居酒屋」「歯科」「整体院」）＋エリア名で検索
>   - ❌ NG例: 「飲食店 加古川」（広すぎてカフェや中華も含まれる）
>   - ✅ OK例: 「居酒屋 加古川」（カテゴリ名と完全一致）
> - **カテゴリフィルタ**: 検索結果に表示される各店舗のカテゴリが対象店舗と**同一または類似**であることを確認。異なるカテゴリ（カフェ、レストラン等）は除外する
> - **個別ページ確認必須**: 検索結果一覧のサマリー数値は不正確な場合がある。**必ず各競合の個別ビジネスページをクリックして開き**、以下を目視確認する:
>   - 店舗名の正式表記
>   - カテゴリ名（居酒屋、カフェ等）
>   - 平均評価（小数点第1位まで）
>   - 口コミ件数（正確な数値）
> - **不正確な競合データは絶対に記載しない**。データの信頼性がレポート全体の信用を左右する

## 3. 5軸スコアリング基準

### 3.1 評価ランク定義

| ランク | 点数範囲 | 表示 | 意味 |
|--------|---------|------|------|
| **S** | 90-100 | 🟢 | 最高水準。維持推奨 |
| **A** | 70-89 | 🔵 | 平均以上。微調整で伸びる |
| **B** | 50-69 | 🟡 | 平均的。改善余地あり |
| **C** | 30-49 | 🟠 | 改善が必要。機会損失中 |
| **D** | 0-29 | 🔴 | 深刻。早急な対応が必要 |

### 3.2 軸①: 基本情報の完全度（配点100）

| チェック項目 | 配点 | 評価基準 |
|-------------|------|---------|
| ビジネス名 | 5 | 正式名称で登録されているか |
| メインカテゴリ | 15 | 業種に最適なカテゴリか |
| サブカテゴリ | 10 | 2個以上設定されているか |
| 住所 | 5 | 正確に登録されているか |
| 電話番号 | 5 | 設定されているか |
| ウェブサイトURL | 10 | 設定されているか（なしは-10） |
| 営業時間 | 10 | 全曜日設定されているか |
| 説明文 | 20 | 設定されているか / 文字数は十分か（500文字以上で満点） |
| 属性 | 10 | 5個以上設定されているか |
| サービス項目 | 10 | 設定されているか / 具体的か |

### 3.3 軸②: 写真・動画の充実度（配点100）

| チェック項目 | 配点 | 評価基準 |
|-------------|------|---------|
| 写真総枚数 | 40 | 5枚以下=0, 10枚=20, 20枚=30, 30枚以上=40 |
| 外観写真 | 15 | あり=15, なし=0 |
| 内観写真 | 15 | あり=15, なし=0 |
| 商品/メニュー写真 | 15 | あり=15, なし=0 |
| スタッフ写真 | 15 | あり=15, なし=0 |

### 3.4 軸③: 口コミの力（配点100）

| チェック項目 | 配点 | 評価基準 |
|-------------|------|---------|
| 口コミ件数 | 25 | 業種別ベンチマークとの比較 |
| 平均評価 | 25 | 4.5以上=25, 4.0-4.4=20, 3.5-3.9=10, 3.5未満=0 |
| オーナー返信率 | 25 | 100%=25, 80%以上=20, 50%以上=10, 50%未満=5, 0%=0 |
| 口コミの鮮度 | 15 | 直近30日以内に新規口コミあり=15, 90日以内=10, それ以外=0 |
| 口コミの質 | 10 | 50文字以上の詳細な口コミの割合で評価 |

### 3.5 軸④: 投稿の活用度（配点100）

| チェック項目 | 配点 | 評価基準 |
|-------------|------|---------|
| 投稿の有無 | 30 | 投稿実績あり=30, なし=0 |
| 最新投稿の鮮度 | 30 | 7日以内=30, 14日以内=20, 30日以内=10, それ以外=0 |
| 直近3ヶ月の投稿数 | 25 | 12件以上(週1)=25, 6件以上=15, 3件以上=10, 1件以上=5, 0件=0 |
| 投稿の種類多様性 | 15 | 最新情報+イベント+特典=15, 2種類=10, 1種類=5 |

### 3.6 軸⑤: 競争力スコア（配点100）

| チェック項目 | 配点 | 評価基準 |
|-------------|------|---------|
| 口コミ件数の競合比較 | 35 | 上位20%=35, 上位40%=25, 上位60%=15, 下位40%=5 |
| 平均評価の競合比較 | 35 | 競合平均以上=35, 同等=20, 下回る=5 |
| 写真枚数の競合比較 | 30 | 競合平均以上=30, 同等=15, 下回る=5 |

### 3.7 総合スコア算出

```
総合スコア = 
  基本情報(25%) + 写真(20%) + 口コミ(30%) + 投稿(15%) + 競争力(10%)

重み付けの理由:
  - 口コミが最も来店決定に影響するため30%
  - 基本情報は「検索で見つかる」ための必須基盤で25%
  - 写真は視覚的な第一印象で20%
  - 投稿は鮮度・活性度の指標で15%
  - 競争力は相対的な位置づけで10%
```

## 5. 「伸びしろ TOP3」の選定ロジック

### 選定基準

5軸のスコアから、以下の優先度で改善インパクトが大きい項目を3つ選定:

```
優先度1: スコアがD（0-29）の軸 → 「深刻な問題」として最優先
優先度2: スコアがC（30-49）の軸 → 「改善が必要」として次点
優先度3: 同ランクの場合は重み（口コミ30%>基本情報25%>写真20%>投稿15%>競争力10%）順
```

### 伸びしろの表現テンプレート

```
【投稿がDランクの場合】
  現状: 投稿が{最新投稿からの日数}日間更新されていません
  伸びしろ: 定期的な投稿でGBPの「活性度」が高まり、
    検索表示回数の改善が見込まれます
  推奨アクション: 週1回の投稿（最新情報・写真・イベント情報）
  想定工数: 投稿テーマの企画・写真撮影・文案作成で1投稿あたり約30〜60分

【口コミ返信率がCランクの場合】
  現状: {返信率}%の口コミに未返信です
  伸びしろ: 口コミへの丁寧な返信は、他の閲覧者の来店意欲を
    高める効果が期待できます
  推奨アクション: 全口コミへの個別対応（過去分＋今後の即時返信体制構築）
  想定工数: 過去の未返信{件数}件の対応に約{時間}時間＋今後は1件5〜10分

【写真がCランクの場合】
  現状: 写真{枚数}枚（業種平均{業種平均}枚に対して不足）
  伸びしろ: 写真の充実は第一印象を高め、来店検討者の
    興味を引く重要な要素です
  推奨アクション: 外観・内観・商品/メニュー・スタッフ等の
    カテゴリ別に計{推奨枚数}枚以上の掲載を推奨
  想定工数: プロカメラマン撮影 or 自社撮影＋編集で半日〜1日
```

> **⚠️ 表現ルール（必須）**
> - 数値の断定を避ける: 「〜倍になります」→「〜倍に改善が見込まれます」「〜の可能性があります」
> - 投稿頻度: 最大「週1回」を推奨上限とする
> - 根拠のない数値を使わない: 「問い合わせ○件増」→「問い合わせ増加が期待できます」
> - レポート最終段階で全文の断定表現チェックを実施する

## 6. 推定機会損失の算出ロジック

### 計算式

```
機会損失 = 診断により改善が見込まれる範囲を定性的に表現

【表現例（ランク別）】
  総合S: 「現時点で非常に高い水準です。さらなる最適化で持続的な成長が期待できます」
  総合A: 「改善ポイントを押さえることで、さらなる集客効果が期待できます」
  総合B: 「いくつかの改善により、現在取りこぼしている可能性のある顧客層にアプローチできます」
```

## 9. 最終検証チェック（データ照合）

> **⚠️ このチェックを全項目PASSしなければ、レポート生成・ユーザー報告に進んではならない**

データ収集完了後、レポート生成前に以下の全項目をブラウザで目視照合する。
browser_subagentで対象ページを開き直し、各項目をスクリーンショット付きで確認する。

### 9.1 チェックリスト

#### 【VERIFY-1】基本情報照合
```
□ ビジネス名が正確か（公式表記と一致）
□ カテゴリが正確か（メインカテゴリのテキスト一致）
□ 住所が正確か（番地・ビル名まで）
□ 電話番号が正確か
□ ウェブサイトURLが正確か（リンク先が存在するか）
□ 営業時間が全曜日取得できているか
```

#### 【VERIFY-2】説明文照合
```
□ 説明文の有無を以下の3箇所で確認したか:
  ├─ Googleマップ概要タブ → あり/なし
  ├─ Googleマップ基本情報タブ → あり/なし
  └─ Google検索ナレッジパネル → あり/なし
□ 説明文がある場合、文字数は正確にカウントしたか
□ マップでは非表示だが検索では表示される場合、その旨を記録したか
```

#### 【VERIFY-3】属性・サービス照合
```
□ 「基本情報」タブを最下部までスクロールしたか
□ 以下のカテゴリごとの項目数を記録したか:
  - サービスオプション（イートイン/テイクアウト等）
  - サービス（アルコール/ビール等）
  - 特徴（飲み放題等）
  - 食事（ランチ/ディナー等）
  - 設備（Wi-Fi/トイレ等）
  - 雰囲気（カジュアル等）
  - その他（車椅子対応等）
□ 属性+サービスの総数が収集データと一致するか
```

#### 【VERIFY-4】口コミ返信率照合
```
□ 口コミ総件数が収集データと一致するか
□ 平均評価が収集データと一致するか
□ 返信率の算出根拠を記録したか:
  ├─ 全件確認の場合 → 「X/Y件確認」
  └─ サンプルの場合 → 「X/Y件のサンプル（全Z件中）・参考値」
□ サンプルベースの場合、レポートに「参考値」注釈が含まれるか
```

#### 【VERIFY-5】投稿照合
```
□ 「すべての最新情報を表示」をクリックして全投稿一覧を確認したか
□ 直近3ヶ月の投稿日を全て記録したか（具体的な日付で）
□ 投稿件数が収集データと一致するか
□ 最新投稿日が収集データと一致するか
```

#### 【VERIFY-6】写真照合
```
□ 写真タブで総枚数を確認したか
□ 写真カテゴリ（外観/内観/料理/スタッフ等）の有無が正確か
```

#### 【VERIFY-7】競合照合（最重要）
```
□ 検索クエリが「GBPメインカテゴリ名 × エリア名」で正確か
  例: 「居酒屋 加古川」 ←カテゴリ名をそのまま使う
□ 各競合のカテゴリが対象店舗と同一または類似か
  → 異なるカテゴリ（カフェ、レストラン等）は除外したか
□ 各競合の個別ビジネスページをクリックして開き、以下を目視確認したか:
  - 店舗名の正式表記
  - カテゴリ名
  - 平均評価（小数点第1位まで正確か）
  - 口コミ件数（正確な数値か）
□ 検索結果一覧のサマリー数値ではなく、個別ページの数値を使用しているか
□ 不正確なデータが含まれていないか（信用に直結する）
```

#### 【VERIFY-8】レポート出力検証（必須）
```
□ HTML内のスコアが期待値と一致するか（grep/Select-Stringで確認）
  - 口コミ返信率が「0/XX件」のままになっていないか
  - 投稿スコアがD(5点)など極端に低くないか（投稿がある場合）
  - 写真スコアが実態と乖離していないか（写真ありの場合）
□ 「改善アクション」に事実と矛盾する記述がないか
  例: 返信率100%なのに「返信がありません」と表示されていないか
  例: 週1投稿しているのに「投稿機能が活用されていません」と表示されていないか
□ 競合テーブルの数値がVERIFY-7のスクリーンショットと一致するか
```

### 9.2 チェック実行方法

```
1. 対象GBPページをbrowser_subagentで開き直す
2. 各VERIFYセクションについて:
   a. 該当セクションに移動（タブ切替・スクロール）
   b. スクリーンショットを取得
   c. 収集データと照合
   d. 不一致があれば修正
3. 全項目PASSしたら「✅ 最終検証完了」を記録
4. 1つでもFAILがあれば:
   a. データ修正
   b. 再スコアリング
   c. 再度VERIFY実行
```

### 9.3 チェック結果報告フォーマット

レポート生成前に以下の形式で結果を記録する:

```markdown

| # | チェック項目 | 結果 | 備考 |
|---|-----------|------|------|
| V1 | 基本情報照合 | ✅/❌ | {不一致があれば詳細} |

| V3 | 属性・サービス照合 | ✅/❌ | {項目数: XX個} |
| V4 | 口コミ返信率照合 | ✅/❌ | {X/Y件, 参考値/全件} |
| V5 | 投稿照合 | ✅/❌ | {直近3ヶ月: X件} |
```
