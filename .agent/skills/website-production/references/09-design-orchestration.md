# デザインオーケストレーション（管理者＋サブエージェント分業）

## 目的

一発生成の当たり外れを排除し、プロの制作工程（案出し→比較選定→デザイン固定→段階展開）を再現してデザイン品質を担保する。ファーストビュー（FV）を2〜3案コンペし、合意後にデザインシステムを固定し、下層セクションを2セクションずつ実装・レビューして進める。

## 適用条件

- **受託案件、およびデザイン品質が論点になる案件では必須。**
- デモ・速度優先の案件は簡易モード（FV1案＋セルフレビュー）でよいが、簡易モードで進めたことを完了報告に明記する。
- 品質モードか簡易モードか迷う場合は、ユーザーに1問だけ確認する。

## 役割分担

| 役割 | 担当 | 責務 |
|:---|:---|:---|
| **管理者（アートディレクター）** | メインエージェント | ブリーフ作成、差分軸の指定、サブエージェントへの発注、比較表作成、選定の進行、デザインシステムの番人、最終統合。**自分ではデザインを描かない** |
| FVデザイナー | サブエージェント×2〜3（並列） | ブリーフに従いFV案を1案ずつ独立に制作 |
| セクションデザイナー | サブエージェント | 確定デザインシステムに従い2セクションずつ実装 |
| レビュアー | 別サブエージェント（[07-subagent-quality-review.md](07-subagent-quality-review.md)の役割文を使用） | 各段階の辛口レビュー |

サブエージェントが使えない環境では、管理者が各役割を**別ターンに分けて**順番に演じ、その旨を報告する（1ターンで全部やると分業の意味が消える）。

## フェーズ0: デザインブリーフ作成（管理者）

材料カード・業種別方針・[03-site-design.md](03-site-design.md)を基に、A4一枚相当のブリーフを作る。

- 初見3秒で記憶させる内容（1文）
- 固有の視覚モチーフ候補（2〜3個）
- 確定コピー（メイン・サブ）と使用画像（**全案で同一素材を使う**）
- デザイントークン初期値（03の表から出発）
- **差分軸の指定**: 3案が似た案にならないよう、案ごとに方向性を明示的に変えて発注する。例:
  - 案A: 大判写真フルブリード型（空気感・没入）
  - 案B: タイポグラフィ主役型（コピーの強さ・余白）
  - 案C: 分割/モチーフ構成型（固有モチーフを構造に使う）

## フェーズ1: FVコンペ（2〜3案）

- 各案は**ヘッダー＋FVのみ**の自己完結HTML/CSS 1ファイルとして、プロジェクトフォルダ内 `fv-variants/fv-a.html`, `fv-b.html`, `fv-c.html` に出力させる。
- コピー・画像・CTA文言は全案共通。**変えてよいのはデザインだけ**（条件を揃えないと比較にならない）。
- 視覚レビュー: 各案を375px / 960px / 1440pxでスクリーンショットし、[06-creative-direction-research.md](06-creative-direction-research.md)の品質ゲート（初見3秒・ロゴ隠し・文字量・モバイル初見）で採点する。コードを読んで判断せず、必ず描画結果を見る。
- 管理者が比較表（各案の狙い・強み・弱み・ゲート採点）を作り、**ユーザー（または顧客）に提示して合意を取る。勝手に1案へ絞って先へ進まない。**

### FVデザイナーへの発注テンプレ

```text
あなたは日本向けWebサイトに強いプロのデザイナーです。
以下のブリーフに従い、ファーストビュー（ヘッダー含む）のみを自己完結のHTML+CSS 1ファイルで制作してください。

# ブリーフ
（初見3秒 / モチーフ / 確定コピー / 使用画像パス / トークン初期値）

# この案の差分軸
（例: 大判写真フルブリード型。写真の空気感を主役にし、文字は最小限）

# 制約
- コピー、画像、CTA文言は変更禁止。デザインのみで差を作る
- 文字量ルール: メインコピー+1〜2行サブコピー+CTA最大2つ。タグ・バッジ禁止
- ブレイクポイントは960px/600px。375pxで主役が破綻しないこと
- 出力先: <プロジェクトフォルダ>/fv-variants/fv-X.html（他の場所に作成しない）
```

## フェーズ2: デザインロック

採用FVから、以後の全セクションが従う仕様を `design-system.md` としてプロジェクトフォルダに文書化する。

- 確定トークン: 色（ベース/テキスト/プライマリ/アクセント）、書体ペア、spacing、角丸、罫線、影
- 固有モチーフの使い方（どの要素として、どの頻度で現れるか）
- 写真のトーン指定（ライティング・カラーグレード）
- CTAの階層（主/副の見た目と文言方針）

**以後の変更は管理者の承認制。** セクションデザイナーが勝手にトークンを増やす・変えることを禁止する。

## フェーズ3: 下層展開（2セクションずつ）

- セクションを役割順（認知→共感→証明→比較→行動）に**2セクションずつ**発注→実装→レビュー→修正→次のバッチへ。**一括生成しない。**
- 各バッチのレビュー観点:
  - `design-system.md` からの逸脱がないか（色・書体・余白の勝手な追加）
  - 直前までのセクションとの**シルエット差**があるか（同じカード型の繰り返しになっていないか）
  - FVと並べて1つのサイトに見えるか（一貫性）
  - 文字量ルール
- レビューで不合格のバッチは修正してから次へ進む。

### セクションデザイナーへの発注テンプレ

```text
design-system.md と実装済みの index.html（FV＋ここまでのセクション）を読み、
続きとして次の2セクションを実装してください。

# 今回のセクションと役割
1. （例: Strength — 証明。写真主役1+補助2の構成）
2. （例: Flow — 行動ハードル低下。番号付きステップ）

# 制約
- design-system.md のトークン・モチーフ・写真トーンに完全準拠。新しい色・書体・角丸を追加しない
- 直前セクションと背景・見出し位置・構成の型を変える（シルエット差を作る）
- 既存部分のHTML/CSSを勝手に変更しない
```

## フェーズ4: 統合と最終レビュー

- 管理者が全体を結合し、重複CSS・未使用スタイルを整理する。
- [04-implementation-check.md](04-implementation-check.md)の確認幅・アクセシビリティ基準で全幅チェック。
- [07-subagent-quality-review.md](07-subagent-quality-review.md)のサブエージェント最終レビューを実施（バッチレビューをしていても省略不可。全体を通して見ると出る問題があるため）。

## 出力形式

```markdown
## デザインオーケストレーション記録
- モード: 品質モード（FV3案） / 簡易モード（理由: ）
- FV比較表: 案A/B/Cの狙い・採点・選定結果と理由
- 合意: ユーザー確認日時・選ばれた案
- design-system.md: パス
- バッチ記録: 第1バッチ（セクション名/レビュー結果/修正内容）…
- 最終レビュー: 07の結果
```

## 確認方法

- FV案が2〜3案あり、差分軸が明確に異なる。
- 選定がスクリーンショット（描画結果）に基づいている。
- ユーザーまたは顧客の合意を経てから下層展開している。
- design-system.md が存在し、全セクションが準拠している。
- バッチごとのレビュー記録がある。

## 不合格時の対応

- 3案が似てしまった場合は、差分軸を再指定して作り直す（微修正で済ませない）。
- バッチでトークン逸脱が出た場合は、design-system.md を正として実装側を直す（design-system.md を後追いで変えない）。
- FVで全案不合格の場合は、ブリーフ（モチーフ・コピー・画像）まで戻って作り直す。デザインだけの再抽選をしない。
