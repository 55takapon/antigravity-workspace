# 5ステップ リサーチフロー詳細

SKILL.md の各ステップから、その工程に入った時に読む詳細手順。
各Stepは「見る観点 → 作業手順 → 出力形式 → 確認方法 → 不合格時の対応」で構成する。

---

## Step1: ペルソナの悩みを抽出する

### 見る観点
読者本人が口に出す「困りごと」と、その裏にある本音（言語化されていない欲求）を分けて捉える。

### 作業手順
1. 対象ペルソナを業種・地域・属性まで具体化する。
2. 表面的な悩みを書く。
3. その悩みの裏にある本音（コスト・不安・理想）を書く。
4. 読者が検索しそうな言葉を、本人の語彙で3つ以上書く。
5. 解決した先の理想像を書く。

### 出力形式（悩み抽出シート）
```
- ペルソナ: （例）加古川市で整体院を経営する40代男性
- 具体的な悩み: （例）ホットペッパーに頼らず自力で集客したい
- 悩みの裏にある本音: （例）広告費を下げて利益率を上げたい
- 検索しそうな言葉: （例）「整体院 集客 ホットペッパー以外」
- 解決した先の理想: （例）指名検索で来る患者だけで予約が埋まる
```

### 情報源（優先度順）
1. クライアントとの日常会話・問い合わせ内容
2. GBPの口コミ・質問
3. Yahoo!知恵袋 / 教えて!gooの質問
4. SNSのコメント・DM
5. 競合サイトのFAQ・ブログコメント欄

### 確認方法
検索しそうな言葉が、Step2のKW調査の起点として使える具体性になっているか。

### 不合格時の対応
ペルソナや悩みが曖昧なら、想像で埋めずユーザーへの質問に戻る。

## Step2: キーワードを調査する

### 見る観点
検索意図（読者が何を求めて検索したか）と、勝てる検索ボリューム帯を見極める。

### 作業手順
1. Step1の言葉を起点に、サジェスト・関連語からKW候補を収集する。
2. 質問形の会話型クエリ（「〜するには？」「〜と〜どっちがいい？」等）をPAA・サジェストから収集する。AIモード・音声検索で増えている聞き方のため、H2見出し・FAQの素材にもなる。
3. 各候補を検索意図で分類する。
4. 月間検索ボリュームの目安を確認する。

### 検索意図の分類
- Know（知りたい）: 「MEO対策とは」
- Do（やりたい）: 「GBP 設定方法」
- Go（行きたい）: 「加古川 整体院」
- Buy（依頼したい）: 「MEO対策 代行 料金」

### ボリュームの目安
月間検索ボリューム100〜1,000がスイートスポット。大きすぎると大手と競合し、小さすぎると流入が見込めない。

### 使用ツール
Google検索サジェスト・ラッコキーワード・Googleキーワードプランナー・Search Console。

### ボリュームが実測できない場合（幻覚防止）
ツールにアクセスできず実測できない場合、**断定値をでっち上げない**。
「推定」と明記した上で、以下を代理指標にする。
- サジェスト・関連語の数（多い＝一定の検索需要がある）
- PAAの有無（表示される＝質問需要がある）
- SERPの広告出稿数（多い＝商業価値のあるKW）

### 出力形式
```
- メインKW候補: ___（検索意図: Know/Do/Go/Buy ／ ボリューム目安: ___）
- サブKW候補: ___
```

### 確認方法
メインKWと検索意図が1つに絞れているか。

### 不合格時の対応
ボリュームがほぼ0なら、関連KW・複合KWへ広げるか、指名検索狙いに切替える。

## Step3: 競合を分析する（上位10件）

### 見る観点
上位が全員書いていること（必ず入れる内容）と、誰も書いていない切り口（差別化チャンス）を分ける。

### 作業手順
1. 対象KWで検索し、上位10件のタイトルを記録する。
2. 共通する訴求ポイントを抽出する。
3. 不足している切り口を特定する。
4. 記事形式と平均文字数を記録する。

### 出力形式（競合分析シート）
```
- 検索KW: ___
- 上位10件のタイトル一覧: ___
- 共通する訴求ポイント: ___
- 不足している切り口: ___ ← 差別化チャンス
- 記事の形式: リスト型 / ガイド型 / Q&A型 / 事例型
- 文字数の平均: ___文字
```

### 確認方法
差別化チャンスが1つ以上、具体的に言語化できているか。

### 不合格時の対応
上位が広告・大手ばかりなら、地域名・ロングテール・複合KWへずらして再分析する。

## Step4: AI検索（AI Overviews・AIモード）を確認する

### 見る観点
AI検索に引用される余地があるか、従来型SEO（順位勝負）で攻めるかを判断する。
**AI OverviewsとAIモード（2025年9月に日本提供開始）は引用元がほとんど重ならない別物**のため、両方を確認する。
AIモードは会話型・複合的な質問に強く、1回の回答で多数のサイトを引用する。

### 作業手順
1. 対象KWでGoogle検索する。
2. AI Overviewsの表示有無を確認する。
3. AIモード（または同等のAI検索）で、読者が聞きそうな質問文（Step2の会話型クエリ）を投げる。
4. 表示・引用される場合: 引用サイトを特定し、回答パターンを分析し、含まれていない情報を差別化に活用する。
5. どちらにも表示されない場合: 従来型SEO（検索順位勝負）で攻める方針にする。
6. ツールの制約で確認できなかった項目は「未確認」と明記する（確認したことにしない）。

### 出力形式
```
- AI Overviews表示: あり / なし / 未確認
- AIモードでの引用: あり / なし / 未確認（投げた質問文: ___）
- 引用サイト: ___
- 含まれていない情報（差別化材料）: ___
- 方針: AI検索引用狙い / 従来型SEO
```

### 確認方法
差別化材料、または従来型SEOで攻める判断のどちらかが決まっているか。

### 不合格時の対応
AI Overviewsが網羅的で差別化余地が薄い場合は、一次情報・地域固有・事例型で角度を変えるか、別KWへ切替える。

## Step5: タイトル案を3パターン生成する

### 見る観点
同じKWでも「直球」「差別化」「常識破壊」で読者の反応が変わる。3つの角度を必ず出し分ける。

### 3パターンの定義
1. 王道パターン: 検索意図に直球で応えるタイトル。
2. 差別化パターン: Step3で見つけた競合にない切り口を入れたタイトル。
3. フィルター書き換えパターン: 読者の「当たり前」を壊し、知的好奇心を刺激するタイトル。

### 作業手順（発散→収束）
1. [references/title-templates.md](title-templates.md) のテンプレートとフィルター書き換えパターンから、検索意図に合う型を選ぶ。
2. 各パターン3案ずつ（計9案）を発散生成する。1案ずつテンプレを埋めて終わりにしない。
3. [references/seo-title-rules.md](seo-title-rules.md) の設計ルールに沿って文字数・KW位置を調整する。
4. [references/title-templates.md](title-templates.md) の品質チェックリストで検査し、各パターン最良の1案（計3案）に絞る。
5. フィルター書き換え型でKW左寄せと訴求が両立しない場合は、訴求を優先してよい（その場合、王道案でKW左寄せを担保する）。
6. 同サイト内のKWカニバリがないか確認する。

### 出力形式
```
【王道】___（文字数: __ / 狙うKW: __ / 根拠: __）
【差別化】___（文字数: __ / 狙うKW: __ / 根拠: __）
【フィルター書き換え】___（文字数: __ / 狙うKW: __ / 根拠: __）
推奨案と理由: ___
```

### 確認方法
3案全てが品質チェックリストを通過し、カニバリがないこと。

### 不合格時の対応
チェックリスト不通過の案は修正する。カニバリが起きる場合は新規タイトルを出さず、既存記事のリライト提案へ切替える。
