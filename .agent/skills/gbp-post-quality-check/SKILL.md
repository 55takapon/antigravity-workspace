# GBP投稿文 品質チェックスキル

GBP投稿文を納品・報告・出稿する前に、未確認事実、誇大表現、断定、業種別広告リスクを検査する。文章を良く見せるための推測を止め、確認済み材料だけで安全に投稿できる状態へ戻す。

## 起動条件

以下のいずれかに当てはまる場合は必ず使用すること。

- GBP投稿案を新規作成、修正、月次納品、出稿前確認する場合
- ユーザーから「投稿前チェック」「品質確認」「誇大表現」「断定」「未確認事実」「口コミ風」「医療広告」「士業広告」と言われた場合
- 医療、歯科、士業、健康、美容、教育、飲食など、効果・体験・家庭状況・季節行動を語りやすい投稿を扱う場合
- 過去投稿やナレッジにない口コミ、お客様の声、予定、来店・受診行動、家族構成、季節の悩みを本文へ入れている可能性がある場合

## 入力として確認するもの

- チェック対象の見出し・タイトル、固定冒頭、可変本文、固定フッター。固定文の有無と役割はクライアントナレッジを正とする
- クライアント名、業種、地域、対象サービス
- 確認済み材料の所在。ナレッジ、公式サイト、過去投稿、実際の口コミ、ユーザー提供メモを分ける
- 出稿先と投稿タイプ。GBP最新情報、特典、イベント、商品など

## チェック工程

### 1. 材料と未確認情報を分ける

必要資料: [references/01-check-axes.md](references/01-check-axes.md) の「材料確認ゲート」をこの工程で必ず読むこと。

- [ ] 投稿内の事実、口コミ、体験、予定、季節行動、家族状況を抜き出した
- [ ] 抜き出した各情報に、確認済み材料があるかを判定した
- [ ] 出典がない情報を「未確認」として分け、本文材料へ混ぜていない

#### 完了条件

確認済み材料、未確認材料、削除候補が分かれていること。この条件を満たすまで次に進んではならない。

### 2. 共通軸(軸1〜4・軸7・軸8)で本文を検査する

必要資料: [references/01-check-axes.md](references/01-check-axes.md) の各軸をこの工程で必ず読むこと。

- [ ] 軸1から軸4、軸7の全業種共通チェックを実施した
- [ ] 「未確認の口コミ・お客様の声」「季節・家庭状況・体験の断定」「予定・来店・受診行動の決めつけ」を要修正として拾った
- [ ] 軸8で固定冒頭を除く可変本文の冒頭・ベネフィット翻訳・CTAの段階整合を検査し、投稿目的型に合わない平坦投稿を要修正として拾った
- [ ] 軸8の修正案が、未確認事実・口コミ風表現・感情断定・効果保証を追加していないことを確認した
- [ ] 修正案は、確認済み事実へ戻す、断定を弱める、削除する、または確認済み事実をベネフィット翻訳する方針で書いた

#### 完了条件

各指摘に、該当軸、問題箇所、悪い理由、安全な修正方向があること。この条件を満たすまで次に進んではならない。

### 3. 業種別コンプライアンスを確認する

必要資料: 医療、歯科、士業、健康、美容、教育に該当する場合は [references/02-industry-compliance.md](references/02-industry-compliance.md) をこの工程で必ず読むこと。

- [ ] 医療・歯科は軸5を必ず追加した
- [ ] 士業は軸6を必ず追加した
- [ ] 軸5・軸6が対象外の場合も、対象外理由を明記した
- [ ] 飲食、健康、美容、教育でも、健康効果、成果保証、利用者像の決めつけを確認した
- [ ] 法令・制度の判断が必要な場合は、確認済み資料の範囲を明記し、必要なら専門家確認へ回した

#### 完了条件

業種別の適用軸と対象外軸が明確であること。この条件を満たすまで次に進んではならない。

### 4. 失敗例と照合する

必要資料: 似た表現がある場合は [examples/failure-cases-iami-kamada.md](examples/failure-cases-iami-kamada.md) をこの工程で必ず読むこと。

- [ ] iami型の口コミ風表現、季節の食行動、家族利用の決めつけと照合した
- [ ] kamada型の受診行動、家庭状況、医療効果、季節症状の決めつけと照合した
- [ ] 同じ型の失敗があれば、具体表現、悪い理由、安全な修正方向で記録した

#### 完了条件

過去の失敗型と今回の指摘が対応しているか確認済みであること。この条件を満たすまで次に進んではならない。

### 5. QAチェック結果を出す

必要資料: 出力形式は [examples/good-check-report.md](examples/good-check-report.md) をこの工程で必ず読むこと。

- [ ] 要修正箇所を表で出した
- [ ] 問題なしの軸も「確認済み」として明記した
- [ ] 判定を「合格」「要修正」「保留」のいずれかで出した
- [ ] 合格時のみチェック完了報告を出した

#### 完了条件

ユーザーが修正すべき箇所と出稿可否を判断できること。この条件を満たすまで完了報告してはならない。

### 6. 指摘をスキル更新へ戻す

必要資料: 新しいユーザー指摘、修正済み投稿、再発パターンがある場合は [references/03-update-loop.md](references/03-update-loop.md) をこの工程で必ず読むこと。

- [ ] 新しい失敗表現が既存examplesにない場合、追加候補として記録した
- [ ] 複数案件に共通する失敗なら、references/01-check-axes.md へ一般化する候補にした
- [ ] クライアント固有本文はSKILL.mdへ入れず、必要な場合だけexamplesへ最小限で分離する

#### 完了条件

今回の指摘を次回の品質向上に使うか、今回限りの案件情報として除外するかが分かれていること。

## 合否判定

| 判定 | 条件 | 次の対応 |
|:---|:---|:---|
| 合格 | 共通軸(軸1〜4・軸7・軸8)と業種別軸に要修正がなく、未確認事実が残っていない | チェック完了報告を出す |
| 要修正 | 誇大、断定、未確認口コミ、家庭状況・季節行動・受診行動の決めつけ、広告リスク、または訴求力不足(平坦な事実羅列・冒頭の弱さ・CTA不一致)がある | 修正後に再チェックする |
| 保留 | 出典確認、法令判断、専門家確認が必要 | 未確認のまま出稿しない |

## エッジケース

| 状況 | 対応 |
|:---|:---|
| 実際の口コミか、AIが作った口コミ風表現か判別できない | 未確認の声として要修正。出典が出るまで「お声をいただいています」と書かない |
| 季節テーマがあるが、読者の予定や家庭状況は確認できない | 季節事実だけ使い、「増える」「多いはず」「ご家族で」などの決めつけを避ける |
| 医療・士業で制度や症状に踏み込む | 軸5または軸6で保留を検討し、必要なら専門家確認へ回す |
| 修正すると訴求が弱くなる | 訴求より確認済み事実を優先する。未確認の魅力付けで補わず、確認済み事実のベネフィット翻訳で補う |
| ユーザーが事実のみの淡々とした告知を明示した、または休業・営業時間変更などの事務連絡 | 軸8の告知型として、確定した結論、必要条件、注意点、必要な行動が明確かを簡潔に検査する |

## 禁止事項

- 確認済み材料がない口コミ、お客様の声、利用者の感情、来店・受診行動を本文へ残してはならない
- 「多い」「よくいただく」「人気」「定番」「ご家族で」「夏休み中なら」などを、根拠なしに事実のように書いてはならない
- 医療・士業で効果、結果、手続き、治療、受診の必要性を断定してはならない
- 訴求力を上げる目的で、未確認事実、口コミ風表現、感情断定、効果保証を追加する修正案を出してはならない
- 要修正が残っている投稿にチェック完了報告を出してはならない
- クライアント固有本文や今回だけの作業指示をSKILL.md本体へ混ぜてはならない

## 自己完了確認

完了前に必ず確認すること。未確認がある場合は完了報告してはならない。

- [ ] 材料確認ゲートを通した
- [ ] 軸1から軸8をすべて確認した(対象外の軸は対象外理由を明記した)
- [ ] 医療・士業などの業種別軸を適用または対象外判定した
- [ ] 未確認の口コミ・お客様の声を残していない
- [ ] 季節・家庭状況・体験・予定・来店・受診行動の決めつけを残していない
- [ ] 軸8の指摘・修正案が未確認事実や断定を追加していない
- [ ] 合格時だけチェック完了報告を出した
- [ ] 新しい失敗型を更新ループへ回すか判断した
