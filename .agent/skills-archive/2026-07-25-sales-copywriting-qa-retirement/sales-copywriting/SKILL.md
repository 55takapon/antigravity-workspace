# sales-copywriting

> 提案文はセールスレターではない。**伴走者としての最初の握手**である。

## 根本哲学

- **成約はゴールではなくスタート**: 正しい相手と正しいタイミングでご縁を生む。返信率より質
- **煽らない、事実を共有する**: 気づきを渡し、相手が自分で判断する。今すぐじゃなくていい
- **読み手のエネルギーを奪わない**: すっと読めてすっと行動できる。判断力を消費させない
- **セールス臭ゼロ**: 無自覚のセールス拒否反応を起こさせない。ヨイショ・盛りは全カット

提案文が超えるべき唯一のハードルは「信用」。だから Block 1（安心装置）が文面の中で一番重い仕事をする。

## ステップ1: 依頼の確認と対象判定

必要資料: 実在するプロファイルと計画中テンプレは [knowledge/profile-registry.md](knowledge/profile-registry.md) をこの工程で必ず読むこと。

- [ ] 新規テンプレ作成か、既存プロファイルの改善かを判別した
- [ ] 送信対象がフォームを持つ中小B2B企業であることを確認した（直接BtoCは対象外。エッジケース参照）

#### 完了条件
- 対象業種と「新規/改善」の別が確定していること。満たすまで次のステップに進んではならない

## ステップ2: 設計

必要資料: フレームワーク選択（BAB/PAS/AIDA/SPIN応用）は [references/frameworks.md](references/frameworks.md) を、送り先の現実・運用前提・心理原則は [references/02_sending-context.md](references/02_sending-context.md) と [references/psychology-triggers.md](references/psychology-triggers.md) をこの工程で必ず読むこと。

- [ ] 業種×提案タイプに合うフレームワークを選択した
- [ ] 相手の構造的な痛みと「3行プレビューで捨てられる現実」を前提に切り口を決めた

#### 完了条件
- フレームワークと切り口が決まっていること。満たすまで次のステップに進んではならない

## ステップ3: 執筆（7ブロック構成）

読み手の心理フロー「安心 → 興味 → 読み進める → 行動 or 心に留める」に沿って組む。
Block 1〜2 がメールプレビューの3行に収まり、不審者フィルター・自分ごとフィルター・コスパフィルターを突破する。

| Block | 内容 | 行数 |
|:--|:-----|:-----|
| 1 | 信頼セットアップ: 宛名+名乗り+権威性を最短で（権威性=自慢ではなく安心装置。超えると自分語り） | 2〜3行 |
| 2 | パーソナライズ・フック: 相手の事業・業種への具体的言及 | 1〜2行 |
| 3 | 課題共感: 「同業種でよく聞く声」の箇条書き（煽りではなく事実共有） | 2〜3行 |
| 4 | ブリッジ: 「1つでも当てはまれば、お役に立てます」 | 1行 |
| 5 | ベネフィット: ①②③で相手の理想の未来を描写。主語は常に「貴社」 | 3〜5行 |
| 6 | CTA: 「15分の情報共有」+カジュアルでOKの一言+実績URL。CTAは1つだけ | 1〜2行 |
| 7 | 署名: 社名・氏名（電話はフッター） | 2行 |

- 文字数: **600〜800字が理想。1,000字未満は必須制約**
- フォーム制約: 太字・見出し不可。①②③記号と改行で視覚的区切りを作る
- 件名: 20文字以内。相手のメリットor課題を含める。自社名・「ご提案」「ご案内」は入れない

#### 完了条件
- 7ブロックが揃い、実績・数字はすべて事実であること。満たすまで次のステップに進んではならない

## ステップ4: セルフチェックと品質検査

必要資料: NG表現の詳細は [references/ng-patterns.md](references/ng-patterns.md) をこの工程で必ず読むこと。

- [ ] 本文と件名の文字数を実際に数えた（600〜800字目標・1,000字未満必須・件名20字以内）
- [ ] クイックチェック: Block1で何者か伝わるか / ベネフィットの主語が貴社か / セールス臭・煽り・ヨイショがないか / CTAが1つか
- [ ] `sales-copywriting-qa` スキルで8軸検査を必ず実施し、合格を確認した

#### 完了条件
- 文字数実測と sales-copywriting-qa 合格の両方を満たすこと。満たすまで次のステップに進んではならない

## ステップ5: プロファイル反映（PDCA）

- [ ] 反映先は contact-form-assist の実在置き場（knowledge/profile-registry.md 記載のパス）にした
- [ ] **既存プロファイルは上書きせず**、`[業種]-v[N].json` 形式でバージョン追加した（初版はそのまま残す。差分が見えないとPDCAが回せない）
- [ ] [references/pdca-log.md](references/pdca-log.md) に「前版の懸念点 / 変えた点 / 良くなる仮説 / 検証結果（送信後追記）」を必ず記録した

#### 自己完了確認（省略禁止）
- [ ] ステップ1〜4を全て実行したか
- [ ] 文字数を実測したか
- [ ] sales-copywriting-qa の合格を確認したか
- [ ] プロファイルを上書きしていないか・pdca-log に記録したか

1つでも未実施の場合、完了報告してはならない。

## 連携スキル

| スキル | 役割 |
|:------|:-----|
| `contact-form-assist` | 送信実行の正本（半自動送信・NGワードスキップ・結果記録）。旧 contact-auto / form-automation は廃止済みのため案内禁止 |
| `sales-copywriting-qa` | 送信前の8軸品質検査（必須） |
| `blog-writing` | 記事末尾CTA設計で本スキルの型を参照する側。説得心理の正本は本スキルの references/psychology-triggers.md |

## エッジケース

| 状況 | 対応 |
|:-----|:-----|
| 直接BtoC（飲食・美容・一般クリニック・士業）に送りたい | フォームなしのため対象外と判定し理由を説明。歯科クリニックのみ手紙営業型（文体・構成を別設計）で対応 |
| 本文が1,000字を超えた | 必須制約違反。Block 3の箇条書きとBlock 5の項目数から削って再検査する |
| profile-registry と実ファイルが食い違う | 実ファイル（config/profiles）を正とし、registry を更新する |
| 実績・数字の根拠が不明 | 創作せずユーザーに確認する。水増し・誇張は絶対禁止 |

## 禁止事項

- 煽り表現（「今すぐ」「限定」「損」）・希少性の演出を使ってはならない
- 実績・数字を水増し・誇張してはならない
- プロファイルを上書きしてはならない（バージョン追加のみ）
- 1,000字以上の本文・20字超の件名で納品してはならない
- sales-copywriting-qa を通さずに送信フローへ渡してはならない
- 廃止済みスキル（contact-auto / form-automation）や旧パスを連携先として案内してはならない
- 「御社にピッタリ」「ぜひ導入を」等のセールス臭表現・過剰な敬語・ヨイショを使ってはならない
