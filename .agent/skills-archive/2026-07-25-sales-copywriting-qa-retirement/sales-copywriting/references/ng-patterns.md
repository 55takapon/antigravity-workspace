# NGパターン集 — 失敗パターンと改善例

## カテゴリ A: 構造的NGパターン

### A-01: Block 1 で権威性ゼロ
**NG例:**
```
○○株式会社 ご担当者様

突然のご連絡失礼いたします。
ジェットプロデュース田中と申します。
```
**問題**: 何者か全く分からない。不審者フィルターを突破できない。
「突然のご連絡失礼いたします」は全員が使う定型文 → 即スパム判定。
**改善:**
```
○○株式会社 ご担当者様
GBP運用11社・継続率90%超のジェットプロデュース田中です。
```
→ 2行で「何者か」「信頼できそうか」が伝わる。

---

### A-02: Block 1 が5行以上の長い自己紹介
**NG例:**
```
突然のご連絡失礼いたします。
ジェットプロデュース田中克章と申します。
弊社は2021年創業で、GBP運用を専門としております。
これまで様々な業種のクライアント様を支援してまいりました。
元システムエンジニアで、IT分野での経験も豊富です。
Web制作会社での受託経験も年単位でございます。
```
**問題**: 安心装置を超えて「自分語り」化。相手は離脱する。
**改善**: 最も強い1つだけに絞って2〜3行。残りはURL誘導。

---

### A-03: 権威性なしで課題指摘から入る
**NG例:**
```
貴社では、即戦力が不足しているのではないでしょうか。
できる人材が辞めていくお悩みを抱えていませんか。
```
**問題**: 「お前に言われたくない」と反発を招く。
何者か分からない人から課題を指摘されても聞く気になれない。
**改善**: まず Block 1 で安心を確保 → その後に Block 3 で課題共感。

---

### A-04: パーソナライズゼロ
**NG例:**
```
ご担当者様
突然のご連絡失礼いたします。
弊社はGBP運用のサービスを提供しております。
ぜひご検討ください。
```
**問題**: テンプレート一斉送信と即判断される。
相手の業種・事業への言及が一切ない。
**改善**: Block 2 で業種名・業界固有の文脈を入れる。

---

## カテゴリ B: 文体・表現のNGパターン

### B-01: 煽り表現
**NG例:**
```
今すぐご検討ください。
残り3社様のみの募集となっております。
このままでは、競合他社に差をつけられてしまいます。
```
**問題**: 短期的に成約が取れても長期的な関係にならない。
読み手の不安を操作している。伴走者としての信頼を失う。
**改善**: 「こういう現実があります」と事実として共有する。

---

### B-02: セールス臭の強い表現
**NG一覧:**
- 「ぜひ一度お話を」（連呼すると必死感が出る）
- 「御社にピッタリです」（根拠なし）
- 「業界No.1の実績」（誇張・根拠なし）
- 「ご導入を強くおすすめします」（押し売り感）
- 「今がチャンスです」（煽り）
- 「お断りする理由がない」（上から目線）

**共通の問題**: 日本人は無自覚にセールスに拒否反応を起こす。
これらの表現は「営業されている」と即判断させる。

**代替の考え方**: 選択権は常に相手に。「お役に立てると思ってご連絡しました」程度に留める。

---

### B-03: 過剰な敬語・距離感
**NG例:**
```
お忙しい中、ご高覧いただきまして誠にありがとうございます。
ご多忙の折、誠に恐縮ではございますが、
ご一考いただけますれば幸甚に存じます。
```
**問題**: 不自然・距離感・読む気が失せる。
**改善**: 自然な丁寧語。伴走者として話しかける文体。

---

### B-04: ヨイショ・過剰な持ち上げ
**NG例:**
```
貴社の素晴らしい取り組みを拝見し、
業界をリードされているご活躍に感銘を受けました。
```
**問題**: 根拠のない持ち上げはすぐ見抜かれる。
セールスの常套句として認識されて逆効果。
**改善**: 具体的な言及（業種・事業内容）に留める。ヨイショはゼロ。

---

## カテゴリ C: 構成・設計のNGパターン

### C-01: 長文（1000文字超）
**問題**: 読まれない。エネルギー・判断力を消費させる。
1回だけ売る場合にしか通用しない設計。
**対策**: 600〜800文字が理想。1000文字未満は必須制約。

---

### C-02: CTA が複数ある
**NG例:**
```
詳細資料はこちら: [URL]
お電話でのお問い合わせ: 090-XXXX-XXXX
Webからのご相談: [別URL]
まずはLINEでお気軽に: [LINE URL]
```
**問題**: 相手が何をすればいいか迷う。認知負荷が上がる。
**改善**: CTAは1つだけ。最も低ハードルのアクションに絞る。

---

### C-03: 添付ファイル
**問題**: フォームでは添付不可の場合がほとんど。
開く手間がかかる → 認知負荷が上がる。
**改善**: LP or 資料ページの URL で代替。読みたい人だけ見られる。

---

### C-04: 「突然のご連絡失礼いたします」で開始
**問題**: 全員が使う定型文。セールスメールの証明になる。
**改善**: 宛名の直後に Block 1（信頼セットアップ）から入る。
謝罪の言葉から始めない。

---

## カテゴリ D: PDCA・管理のNGパターン

### D-01: プロファイルの上書き
**問題**: 旧バージョンが消えるとPDCAの差分が分からなくなる。
「何を改善したのか」「初期版はどうだったか」が追跡不能になる。
**対策**: `[業種]-v[N].json` で追加のみ。上書き禁止。

---

### D-02: 返信率だけで評価
**問題**: ボリュームモデルでは返信率は低くなるのが前提。
返信率だけを見ると「全部だめだ」という誤った判断につながる。
**対策**: 返信の質（前向き/断り）・商談化率・長期関係化率で評価する。
