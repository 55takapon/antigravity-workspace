# 送り先の現実と運用前提

## 何をするか
提案文の設計（ステップ2）の前提として、送信モデルと読み手の現実を把握する。

## 運用前提

- 月1000件以上を半自動送信する大量送信モデル（送信実行は `contact-form-assist` スキル。人間が送信ボタンを押す設計）
- 返信率の低下は想定内。ボリュームで補填する
- パーソナライズは**業種レベル**（企業個別は将来の改善項目）
- テンプレートの軸は「業種 × 提案タイプ」で管理する
- 送信対象: お問い合わせフォームが存在する中小規模のB2B会社のみ

## 送信候補のフィルタリング条件

- 資本金1000万円以上 → 除外
- 社員20名以上 → 除外
- 「営業お断り」表記あり → 除外（contact-form-assist のNGワード検出でも自動スキップされる）
- フォームなし → 除外（contact-form-assist がスキップ自動判定）

## 送り先の現実（書く前に必ず思い浮かべること）

相手の会社は日々の業務に追われている。一日10件以上のフォーム問い合わせを処理している。
メールのプレビューで最初の3行を見て「読む価値があるか」を瞬時に判断する。余裕がない。

**相手が常に抱えている構造的な痛み:**
- 即戦力がいない。提案レベル・クライアント対応レベルの人材は別物
- できる人ほど辞めていく。やっと育てた右腕・二番手が辞める
- この問題はこれから加速する一方。人材が来てくれない時代になっていく
- AI時代の不安: 今の事業がこのまま続くのか？経営者は漠然とした不安を抱えている

**提案文が超えるべき唯一のハードル = 「信用」**
メリットは明らか（外部委託でLTVが毎月積み上がる、採用コストゼロ）。
相手が納得すべきは「この人は信用できるか？本当にやっていけるか？」だけ。
信用さえ伝わればやらない理由は正直ない。だから Block 1（安心装置）が一番重い仕事をする。

## 文体の手本（3人の頭脳）

- **鴨頭嘉人**: 相手の関心に関心を持つ。商品ではなく未来を売る。言葉のプレゼント
- **西野亮廣**: 先に与える。信用で繋がる。嘘のない誠実な姿勢。盛らない
- **宋世羅**: 応援したくなる人になる。ヨイショ禁止。過剰な持ち上げ全カット

## 確認方法
設計した切り口が「3行プレビューで捨てられない」「信用の証拠が先頭にある」の2点を満たすか確認する。

## 不合格時の対応
切り口を相手の構造的な痛みのいずれかに結び直し、Block 1 の権威性を具体的な事実に差し替える。
