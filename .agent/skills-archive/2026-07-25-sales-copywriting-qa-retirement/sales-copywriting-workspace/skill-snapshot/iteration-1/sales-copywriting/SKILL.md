# sales-copywriting

> 提案文はセールスレターではない。**伴走者としての最初の握手**である。

## 根本哲学

| 原則 | 説明 |
|------|------|
| **成約はゴールではなくスタート** | 正しい相手と正しいタイミングでご縁を生む。返信率より質を重視 |
| **煽らない、事実を共有する** | 気づきを渡し、相手が自分で判断する。今すぐじゃなくていい |
| **読み手のエネルギーを奪わない** | すっと読めてすっと行動できる設計。判断力・意志力を消費させない |
| **セールス臭ゼロ** | 日本人は無自覚にセールスに拒否反応を起こす。お互いのためにならない |
| **デリバリーは負担ではなく可能性** | 届けるのは売り込みではなくチャンスと可能性 |

### 3人の頭脳

**鴨頭嘉人**: 相手の関心に関心を持つ。商品ではなく未来を売る。言葉のプレゼント。
**西野亮廣**: 先に与える。信用で繋がる。嘘のない誠実な姿勢。盛らない。
**宋世羅**: 応援したくなる人になる。ヨイショ禁止。過剰な持ち上げ全カット。

## 運用前提

- 月1000件以上を自動送信する大量送信モデル（`contact-auto` スキルと連携）
- 返信率の低下は想定内。ボリュームで補填する
- パーソナライズは**業種レベル**（企業個別は将来の改善項目）
- テンプレートの軸は「業種 × 提案タイプ」で管理する
- **プロファイルは上書き禁止・追加のみ**（→ バージョン管理ルール参照）

### 送信候補のフィルタリング条件（contact-auto 側で設定済み）

- 資本金1000万円以上 → 除外
- 社員20名以上 → 除外
- 「営業お断り」表記あり → 除外
- フォームなし → 除外（スキップ自動判定）

### 送り先の現実（書く前に必ず思い浮かべること）

相手の会社は日々の業務に追われている。一日10件以上のフォーム問い合わせを処理している。
メールのプレビューで最初の3行を見て「読む価値があるか」を瞬時に判断する。余裕がない。

**相手が常に抱えている構造的な痛み:**
- 即戦力がいない。提案レベル・クライアント対応レベルの人材は別物
- できる人ほど辞めていく。やっと育てた右腕・二番手が辞める
- この問題はこれから加速する一方。人材が来てくれない時代になっていく
- AI時代の不安: 今の事業がこのまま続くのか？経営者は漠然とした不安を抱えている

**提案文が超えるべき唯一のハードル = 「信用」**
メリットは明らか（外部委託でLTVが毎月積み上がる、採用コストゼロ）。
相手が納得すべきは「この人は信用できるか？本当にやっていけるか？」だけ。
→ 信用さえ伝わればやらない理由は正直ない。
→ だから Block 1（安心装置）が文面の中で一番重い仕事をしている。

## 提案文アーキテクチャ（7ブロック構成）

**読み手の心理フロー: 「安心 → 興味 → 読み進める → 行動 or 心に留める」**

**3行プレビュー勝負**: Block 1〜2 がメールプレビューに収まる。ここで3つのフィルターを突破する。
1. 不審者フィルター（怪しくないか？）→ Block 1 の安心装置で突破
2. 自分ごとフィルター（うちに関係あるか？）→ Block 2 のパーソナライズで突破
3. コスパフィルター（読む時間の価値あるか？）→ Block 2〜3 の切り口で突破

```
┌─ Block 1: 信頼セットアップ（2〜3行）──────┐
│ 宛名 + 名乗り + 権威性を最短で              │
│ ※「何者か」を明示し不審者フィルターを突破    │
│ ※ 権威性 = 安心装置（自慢ではなく信頼の証拠）│
│ ※ 2〜3行が限界。超えると自分語りになる      │
├─ Block 2: パーソナライズ・フック（1〜2行）──┤
│ 相手の具体的な事業・業種への言及             │
│ ※「この人、うちのことを分かってる」感        │
├─ Block 3: 課題共感（2〜3行）───────────────┤
│ 「同業種でよく聞く声」を箇条書き             │
│ ※ 煽りではなく「こんな声を聞きます」の事実共有│
├─ Block 4: ブリッジ（1行）──────────────────┤
│ 「1つでも当てはまれば、お役に立てます」       │
├─ Block 5: ベネフィット（3〜5行）──────────┤
│ ①②③ で相手の理想の未来を描写               │
│ ※「貴社が〜になります」主語は常に相手        │
│ ※ フォームは太字不可 → ①②③記号で区切る    │
├─ Block 6: CTA（1〜2行）───────────────────┤
│ 「15分の情報共有」+ カジュアルでOKの一言     │
│ + 実績詳細URL（読みたい人だけ見る導線）      │
├─ Block 7: 署名（2行）─────────────────────┘
│ 社名・氏名。電話番号はフッターに             │
└───────────────────────────────────────────┘
```

> **文字数**: 600〜800文字が理想。1000文字未満は必須制約。
> **フォーム制約**: 太字・見出し不可。①②③記号と改行で視覚的区切りを作る。

詳細は `references/frameworks.md` 参照。

| フレームワーク | 使い所 | 構造 |
|---------------|--------|------|
| **BAB** | 事例・実績が強いとき | Before（現状）→ After（理想）→ Bridge（橋渡し） |
| **PAS** | 痛みが明確なターゲット | Problem（問題）→ Agitate（深掘り）→ Solution（解決） |

| **SPIN応用** | 論理的な相手向け | 状況 → 問題 → 影響 → 解決 |

## プロファイルのバージョン管理ルール

> **鉄則: プロファイルは上書き禁止。追加のみ。**

差分が見えないとPDCAが回せない。最初の「しょぼいバージョン」を残すことが改善の証明になる。

**命名規則:**
```
[業種]-[バージョン].json
例:
  web-company.json        ← 初期バージョン（そのまま残す）
  web-company-v2.json     ← 改善版
  web-company-v3.json     ← さらに改善
```

**バージョンアップ時に必ず記録する（→ references/pdca-log.md）:**
1. 前バージョンの懸念点・問題点
2. 何を変えたか（差分）
3. なぜ良くなると思うか（仮説）
4. 検証結果（送信後に追記）

## 心理原則の活用ルール

詳細は `references/psychology-triggers.md` 参照。

| 原則 | 使い方 | 絶対NG |
|------|--------|--------|
| 損失回避 | 「こういう現実があります」と事実を共有 | 「今すぐ動かないと損」の脅し |
| 社会的証明 | 「同業種でこんな声を聞きます」の文脈で | 数字の水増し・誇張 |
| 返報性 | 読むだけで視点が変わる情報を含める | 見返りを期待する設計 |
| 認知的容易性 | 短い文・箇条書き・余白でエネルギー消費ゼロ | 判断力を奪う長文・複雑な構成 |
| 希少性 | **使わない** | 「限定○社」「今月だけ」 |

> **煽りと事実共有の境界線**:
> 煽り = 自分のメリットのために書く。即効性を求める。
> 事実共有 = 相手のメリットのために書く。今すぐじゃなくていい。
> 読んだ相手が、契約しなくても視点が変わって行動が変わればそれで価値がある。

## 件名（subject）設計ルール

- **20文字以内**が理想
- 相手のメリット or 課題を含める
- 自社名は入れない（本文署名で十分）
- 「ご提案」「ご案内」は使わない（セールス臭）

## NGパターン（絶対禁止）

詳細は `references/ng-patterns.md` 参照。

| NG | 理由 | 代替 |
|----|------|------|
| Block 1 で権威性ゼロ（名乗りだけ） | 何者か分からない → 即離脱 | 最短で信頼の証拠を1つ入れる |
| Block 1 が5行以上 | 安心装置を超えて自分語り化 | 2〜3行に凝縮。残りはURL |
| 権威性なしで課題指摘から入る | 「お前に言われたくない」と反発 | まず安心 → その後に課題共感 |
| 煽り表現（「今すぐ」「限定」「損」） | 長期関係にならない | 事実の共有として伝える |
| 読み手の判断力を奪う設計 | 1回だけ売る場合にしか通用しない | すっと読めてすっと行動できる |
| 長文（1000文字超） | 読まれない。エネルギー消費 | 600〜800文字が理想 |
| 過剰な敬語・ヨイショ | 不自然・距離感・セールス臭 | 自然な丁寧語。伴走者の文体 |
| 「御社にピッタリ」「ぜひ導入を」 | セールス臭MAX | 選択権は常に相手に |
| プロファイルの上書き | PDCA の差分が消える | バージョン番号を付けて追加 |
