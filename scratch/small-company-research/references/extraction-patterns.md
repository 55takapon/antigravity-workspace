# 抽出パターン集

company-search の crawler.js（1,218行）から蒸留した、スクレイピングファーストの抽出パターン。
DOM解析と正規表現のみでトークンゼロで抽出する。

---

## 全角数字→半角変換（前処理）

全パターン適用前に必ず実行する。

```javascript
function normalizeDigits(text) {
    return text.replace(/[０-９]/g, c => String.fromCharCode(c.charCodeAt(0) - 0xFEE0));
}
```

## 1. 企業名抽出（5段階フォールバック）

| 優先 | ソース | 信頼性 |
|------|--------|--------|
| 1 | 会社概要ページの `<title>` | 最高（「会社概要 \| 株式会社〇〇」形式） |
| 2 | 本文の会社名/商号ラベル | 高（th/td、dl/dt/ddから取得） |
| 3 | OGP `og:site_name` | 中（法人名を含むことが多い） |
| 4 | メインページ `<title>` | 中（ノイズが入りやすい） |
| 5 | 本文先頭5000文字からフォールバック | 低（最終手段） |

### 法人名切り出し正規表現

**前置型**（株式会社〇〇）:
```regex
(株式会社|合同会社|有限会社)([A-Za-zＡ-Ｚａ-ｚ0-9０-９一-龯ァ-ヶー・＆&\-.]{1,12})
  (?![代表所在設立事業資本従業創立本社会社取社長会長理専常監])
```

**後置型**（〇〇株式会社）:
```regex
([一-龯ァ-ヶA-Za-zＡ-Ｚａ-ｚ0-9０-９ー・＆&\-.]{1,15})(株式会社|合同会社|有限会社)
  (?=[\s|｜／\/（(\n]|$)
```

### 会社名ラベルからの取得

```regex
(?:会社名|商号|法人名)[：:／\s\u3000]*([^\n]{3,40})
```

### フリガナ除去

英数字直後のカタカナ4文字以上連続を除去:
```regex
([A-Za-zＡ-Ｚ0-9０-９])[ァ-ヶー]{4,}$  →  $1
```
例: `株式会社WEBGRAMウェブグラム` → `株式会社WEBGRAM`

### 企業名クリーニング

抽出後に必ず適用する後処理:

```text
1. 括弧内に法人格がある場合 → 括弧内を本体として抽出
   例: 「移動（株式会社〇〇）」→「株式会社〇〇」

2. パイプ・ダッシュ以降を除去
   例: 「株式会社〇〇 | Web制作」→「株式会社〇〇」

3. 末尾ノイズ除去
   - のホームページ / の公式サイト / 公式サイト / ホームページ
   - オフィシャルサイト / 様 / さん

4. 法人格前後の余分なテキスト除去
   抽出されたテキストが法人名部分+5文字以上超過 → 法人名部分のみ再抽出
```

## 2. 従業員数抽出（12パターン）

### テーブル型（改行区切り: `<th>従業員</th><td>20名</td>` → innerTextで `従業員\n20名`）

```regex
従業員[数]?\n[約]?([\d,]+)[名人]
社員[数]?\n[約]?([\d,]+)[名人]
スタッフ[数]?\n([\d,]+)[名人]
```

### 通常型（同一行: `従業員数：20名`）

```regex
従業員[数]?[：:\s]*[約]?([\d,]+)[名人]
社員[数]?[：:\s]*[約]?([\d,]+)[名人]
スタッフ[数]?[：:\s]*[約]?([\d,]+)[名人]
メンバー[：:\s]*[約]?([\d,]+)[名人]
人[員数]?[：:\s]*[約]?([\d,]+)
正社員[：:\s]*([\d,]+)[名人]
従業[員]?[：:\s]*約?([\d,]+)
```

### 補助パターン

```regex
([\d,]+)[名人]\s*[（(].*?[正社員|パート|アルバイト]
([\d,]+)\s*(?:名|人)\s*(?:在籍|所属)
社員[：:\s]*([\d,]+)[名人]?\s*[（(]
```

### 注意事項

- 全角数字→半角変換を事前適用すること
- カンマ区切り（`1,200名`）に対応すること
- `約` 前置を許容すること
- 取得できない場合は `null`（推測で断定しない）

## 3. 代表者名抽出（11パターン）

### スペース付きフルネーム優先（最も信頼性が高い）

```regex
代表取締役[社長]*[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{1,5}[\s\u3000][一-龯ぁ-んァ-ヶ]{1,6})
代表者[名]?[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{1,5}[\s\u3000][一-龯ぁ-んァ-ヶ]{1,6})
CEO[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{1,5}[\s\u3000][一-龯ぁ-んァ-ヶ]{1,6})
代表[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{1,5}[\s\u3000][一-龯ぁ-んァ-ヶ]{1,6})
社長[：:\s\u3000]+([一-龯]{1,5}[\s\u3000][一-龯]{1,6})
```

### コロンなし直結パターン

```regex
代表\s*取締\s*役[\s\u3000]*[社長]*[\s\u3000]*([一-龯]{1,5}[\s\u3000][一-龯]{1,6})
```

### スペースなし短縮パターン（negative lookahead付き）

```regex
代表取締役[社長]*[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{3,5})(?![\u4e00-\u9faf\u3041-\u3093\u30a1-\u30f6])
代表者[名]?[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{3,5})(?![\u4e00-\u9faf\u3041-\u3093\u30a1-\u30f6])
CEO[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{3,5})(?![\u4e00-\u9faf\u3041-\u3093\u30a1-\u30f6])
代表[：:\s\u3000]+([一-龯ぁ-んァ-ヶ]{3,5})(?![\u4e00-\u9faf\u3041-\u3093\u30a1-\u30f6])
社長[：:\s\u3000]+([一-龯]{3,5})(?![\u4e00-\u9faf\u3041-\u3093\u30a1-\u30f6])
```

> [!CAUTION]
> スペースなしパターンの文字数上限は `{3,5}` に制限すること。
> `{3,8}` にすると「中山陽平中小企業」のように後続テキストまで巻き込む過剰マッチが発生する（company-search v2.0で修正済みの実績バグ）。

### 抽出後の2段階処理

1. `cleanRepresentativeName(raw)` — ゴミ除去
2. `isJapanesePersonName(cleaned)` — 正判定

→ 処理詳細は `references/validation-rules.md` 参照

## 4. 資本金抽出（3パターン）

### テーブル型（改行区切り）

```regex
資本金\n([\d,]+\s*(?:万円|億円|円|万|億))
```

### 通常型（同一行）

```regex
資本金[：:\s]*([\d,.]+[万億]?円?[^<{\n]*)
```

### 括弧付き補助

```regex
([\d,.]+[万億]円)\s*（.*?資本準備金
```

### インラインバリデーション（抽出直後に適用）

```text
合格: 数字+単位  → ^[\d,]+\s*(万円|億円|円|万|億)$
合格: 純数字6桁以上 → ^[\d,]+$ かつ 6桁以上 → "{数字}円"として採用
合格: 非公開 → ^非(公開|開示)$
不合格: 文章片、JSON断片、メールアドレス → 空にリセット
```

## 6. テーブル型データ専用パーサー

HTMLの `<table>` 要素から th-td ペアを辞書形式で抽出する。
innerText では th と td の間に改行が入るため、DOM直接解析を使用する。

```text
入力: <tr><th>資本金</th><td>900万円</td></tr>
出力: { '資本金': '900万円', '従業員': '20名', ... }
```

**対応構造:**
- `<table>` の `<th>` / `<td>` ペア
- `<dl>` / `<dt>` / `<dd>` ペア
- 見出し + 値のフリーテキスト構造

テーブルパーサーで取得した辞書からキーワードマッチで各フィールドを取得する。

## 7. 企業サイト内のページ分類

企業の公式サイトをクロールする際、**どのページから情報を抽出しキーワード判定するか**を制御する。
ポータルサイト（Web幹事、アイミツ等）のページ構造とは無関係。

### 問題の本質

Webマーケティング会社のサイトには「顧客の成功事例」ページがある。
そこには顧客企業名（NTT、博報堂等）や顧客の業種キーワードが大量に含まれる。
これらのページからキーワード判定や企業名抽出を行うと、**顧客企業を提案候補として誤取り込みしてしまう**。

```text
company-a.co.jp（Webマーケ会社）のサイト構成例:

├── /              ← トップ（自社サービス紹介）     【✅ 情報抽出対象】
├── /service/      ← サービスページ                【✅ 情報抽出対象】
├── /company/      ← 会社概要                      【✅ 情報抽出対象】
├── /contact/      ← お問い合わせ                  【✅ フォーム取得対象】
├── /case/         ← 事例紹介（顧客：NTT、博報堂） 【❌ 除外：顧客企業名混入】
├── /works/        ← 実績一覧（顧客企業名が並ぶ）  【❌ 除外：顧客企業名混入】
├── /blog/         ← ブログ（顧客事例・業界記事）   【❌ 除外：顧客キーワード混入】
├── /column/       ← コラム（SEOノウハウ等）        【❌ 除外：他社キーワード混入】
├── /news/         ← お知らせ                      【❌ 除外：提携先・受賞等】
└── /recruit/      ← 採用情報                      【❌ 除外：職種名がノイズに】
```

### 情報抽出対象ページ（ホワイトリスト方式）

以下のページのみを情報抽出・キーワード判定の対象とする:

```text
トップページ:
  /

サービスページ:
  /service, /services, /solution, /solutions, /business
  リンクテキスト: サービス, 事業内容, 事業紹介, ソリューション

会社概要ページ:
  /company, /about, /corporate, /profile, /outline
  リンクテキスト: 会社概要, 企業情報, 会社案内, About

お問い合わせページ:
  /contact, /inquiry, /form
  リンクテキスト: お問い合わせ, ご相談, 見積もり
```

### 情報抽出除外ページ（ブラックリスト方式）

以下のURLパスに該当するページは、情報抽出・キーワード判定の対象外とする。
**理由: これらのページには顧客企業名・顧客業種のキーワードが含まれ、誤取り込みの原因になる。**

```text
事例・実績:
  /case/          ← 導入事例・成功事例
  /cases/
  /works/         ← 制作実績・支援実績
  /results/
  /portfolio/
  /achievements/
  /voice/         ← お客様の声

ブログ・コラム:
  /blog/
  /column/
  /article/
  /media/
  /magazine/

ニュース・お知らせ:
  /news/
  /topics/
  /info/
  /press/

採用:
  /recruit/
  /careers/
  /jobs/

その他:
  /archives/
  /entry/
  /guide/
  /\d{4}/\d{2}/   ← 日付パス（2024/03/等、ブログ記事の日付構造）
```

### 判定方法

URLパスで判定する。タイトルでは判定しない。

```text
理由:
  「比較」「一覧」「おすすめ」等のワードはサービスページのtitleにも含まれることがある。
  例: 「SEO対策の比較ポイント | 株式会社A」（自社サービス説明）
  タイトルで判定すると、自社サービスページを誤って除外してしまう。
  URLパスのみで判定する方が確実。
```

## 8. キーワードHIT判定の対象範囲

### 判定の目的

企業の公式サイトに、`vertical-profiles.md` のターゲットキーワードが含まれるかを判定する。
**キーワードが含まれない企業は提案対象外としてフィルタリングする**（ポジティブフィルター）。

### 判定対象ページ（優先順）

上記セクション7のホワイトリストに基づく:

```text
1. サービスページ（/service, /services 等）  ← 最も信頼性が高い
2. トップページ（/）                        ← サービス概要が含まれることが多い
3. 会社概要ページ（/company, /about 等）     ← 事業内容の記載がある
```

### 判定対象テキスト

```text
- 上記ページの <body> 内テキスト
- ただし <nav>, <header>, <footer>, <aside> を除外
- メインコンテンツ領域のみを対象とする
```

### 判定ロジック

```text
1. ホワイトリスト対象ページのメインコンテンツテキストを取得
2. vertical-profiles.md の包含キーワードと照合
3. 1つでもマッチ → keyword_status = matched
4. 0件マッチ → keyword_status = not_matched
5. ページ取得失敗 → keyword_status = unknown
```

> [!IMPORTANT]
> 事例・実績・ブログ・コラム・採用ページのテキストは判定対象に含めない。
> これらのページには顧客企業の業種キーワードが含まれることがあり、
> 「自社サービスとしてSEOを提供している」のか「顧客がSEO施策をした事例を紹介している」のか
> テキストだけでは区別できない。判定対象を自社サービス関連ページに限定することで精度を担保する。
