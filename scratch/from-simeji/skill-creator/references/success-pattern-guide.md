# 成功法則の使い方

成功例、改善前後、A/B結果、レビュー結果、実行ログを材料にする時は、実物をそのまま真似ず、次のスキルでも使える作業ルールへ変換する。

## 使える材料

- ユーザー提供例
- 実ファイル
- 実行ログ
- A/B比較結果
- レビュー結果
- 公開されている実例
- 公式資料や論文

確認できない材料は使わない。出典や実本文がないものを、成功例やプロ事例として扱ってはならない。

## 抽出する内容

成功法則として採用する前に、必ず以下を分けること。

| 項目 | 書く内容 |
|:---|:---|
| 根拠となる実物 | 見たファイル、URL、ログ、A/B結果、レビュー結果 |
| 良かった点 | 何が出力品質を上げていたか |
| 採用する作業ルール | 次のスキルでも使える形にした手順や判断基準 |
| 使える条件 | どの種類の依頼、素材、工程で使ってよいか |
| 使ってはいけない条件 | どの場面では誤作動や品質低下につながるか |

## 成功例と失敗例の扱い

成功法則を作る時は、成功例、改善前後、レビュー結果を中心に見る。

失敗例は、やってはいけないこと、不合格条件、再確認する条件にだけ使う。失敗例だけを集めて、禁止事項を増やすだけのスキルにしてはならない。

## スキルへ入れる時の形

- SKILL.md には、工程として必要な短い指示だけを書く。
- 詳しい判断基準や比較表は references/ に分ける。
- 実例や実ログは examples/ または knowledge/ に置く。
- 固定のローカルパスや固有スキル名を標準手順として書かない。
- 参照先が必要な時は、ユーザー提供、検索、実ファイル確認で見つかったものだけ使う。

## 不合格にする条件

- 元の実物を確認していない。
- 何が良かったかを説明できない。
- 適用条件がない。
- 使ってはいけない条件がない。
- A/Bや実レビューで悪化していないことを確認できない。
- 今回だけの注意文や検証者の作業メモを、成功法則として混ぜている。
