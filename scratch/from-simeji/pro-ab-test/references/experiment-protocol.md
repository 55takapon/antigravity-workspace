# A/B実験プロトコル

この資料は、A/Bテストを始める前に必ず埋める実行ルール。目的は「何を変えたから何が良くなったか」を後から説明できる状態にすること。
測定基準と合格ラインの詳細は [measurement-rubric.md](measurement-rubric.md) を正本にする。

## 1. 開始前に固定するもの

必ず以下を先に書く。1つでも空欄なら編集してはならない。

| 項目 | 書く内容 | 未達時の扱い |
|:---|:---|:---|
| 目的 | ユーザーが何を良くしたいのか | 曖昧なら開始不可 |
| A案 | 変更前のファイル、設定、実出力 | A案なしは無効 |
| 入力 | A案とB案に同じように渡す実データ | 同一入力なしは無効 |
| 変更点 | B案で1つだけ変える内容 | 複数変更は無効 |
| 仮説 | その1点で、どの指標が、どこまで良くなるか | 測れない仮説は無効 |
| 主判定 | 勝ち負けを決める1つの基準、測り方、合格ライン | 未定義なら編集不可 |
| 補助判定 | 主判定を説明するための追加観点 | 主判定の代わりにしない |
| 悪化防止 | ここが悪くなったら勝ちにしない基準と許容ライン | 1つでも重大悪化なら戻す |
| 代表入力 | 代表、既知失敗、境界ケース | 実データ不足なら暫定/無効 |
| 戻し方 | 悪化、無効、未完了の時に戻す方法 | 戻し方なしは編集不可 |

## 1.5. 仮説の書き方

仮説は必ず次の形にする。

```text
[変更点] を [Aの状態] から [Bの状態] に変えると、
[代表入力セット] で、
[主判定] が [合格ライン] まで改善し、
[悪化防止] は [許容ライン] を超えて悪化しない。
```

「品質が上がる」「自然になる」「プロっぽくなる」だけの仮説は禁止。

## 2. 変更は必ず1点だけ

1回のA/Bで変えてよいのは1点だけ。

例:
- OK: 「外部高反応事例を、抜粋から全文生データに変える」だけ。
- NG: 「事例を全文にする」「比較審査プロンプトも変える」「読者役の出力形式も変える」を同時に行う。

複数の変更が必要な時は、A/Bを分ける。

変更点が1つに見えても、実際に別の工程、例、読者役、ゲート、出力形式を同時に変えるなら複数変更として扱う。

## 3. 実出力で比べる

スキルやプロンプトの改善は、ファイル差分だけでは判断しない。必ず実際の作成ルートを通して、A案とB案の成果物を並べる。

文章生成の場合は、最低限以下を出す。

| 項目 | 必須 |
|:---|:---|
| A案の本文 | 必須 |
| B案の本文 | 必須 |
| 良くなった点 | 必須 |
| 悪くなった点 | 必須 |
| 主判定の採点 | 必須 |
| 合格ラインとの差 | 必須 |
| 悪化防止の確認 | 必須 |
| ユーザー指定への一致 | 必須 |
| 口調、改行、自然さ | 該当時は必須 |
| AIっぽい表現の有無 | 該当時は必須 |

## 4. 判定ルール

判定は3つだけにする。

| 判定 | 条件 | 行動 |
|:---|:---|:---|
| 残す | 主判定が改善し、悪化防止基準にも引っかからない | 変更を残し、検証してコミットする |
| 戻す | 主判定が悪化、または悪化防止基準に引っかかる | 変更を戻す |
| 無効 | 入力、ルート、変更点が揃わず比較できない | 改善扱いにせず、原因を直してA/Bをやり直す |

「少し良さそう」「たぶん改善」は残す理由にならない。
主判定が良くても、悪化防止に重大違反があれば戻す。

## 5. スキル更新との接続

`skill-update` を使う場合でも、このA/Bプロトコルを省略してはならない。

出力品質に影響するスキル更新は、以下が終わるまで完了ではない。

1. A/B計画がある。
2. 変更前の実出力がある。
3. 変更後の実出力がある。
4. 横並びの目視比較がある。
5. 残す/戻す/無効の判定がある。
6. 残す場合は検証とコミットがある。

## 5.5. 旧版比較

スキル改善では、`skill-update` の原則に従い、旧版と改善版を同じ評価ケースで見る。改善版だけを見て良くなったとは言わない。

旧版比較で最低限見るもの:
- 旧版のA/B計画がどこまで書けるか。
- 改善版のA/B計画が、測定基準と合格ラインまで書けるか。
- 無効条件や戻し条件で止められるか。
- 実本文なしで完了扱いしないか。

## 6. 生データ指定時の扱い

ユーザーが「生データ」「全文」「引用ではなく」と指定した実例は、スキルが直接読む `examples/` や `knowledge/` に置く。抜粋、要約、別ファイル参照、後段の停止条件だけで代替してはならない。

この条件を満たさないA/Bは、そもそも入力条件がズレているため無効にする。
