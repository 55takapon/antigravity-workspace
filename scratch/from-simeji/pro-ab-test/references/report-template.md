# A/Bテスト報告テンプレート

報告は、ユーザーが「結局、良くなったのか」「何を変えたのか」「残していいのか」をすぐ判断できる形にする。

## 必須フォーマット

```markdown
## 結論

[残す / 戻す / 無効]。
理由: [主判定と悪化防止を1-2文で説明]

## 何を変えたか

- 変更対象:
- 変更した1点:
- 変更していないもの:

## A/B計画

- 仮説:
- 代表入力:
- 主判定:
- 主判定の測り方:
- 合格ライン:
- 補助判定:
- 悪化防止:
- 戻し条件:

## A案: 変更前

[実際の本文、または成果物の重要部分]

## B案: 変更後

[実際の本文、または成果物の重要部分]

## 横並び比較

| 観点 | A案 | B案 | 判定 |
|:---|:---|:---|:---|
| 主判定 | [点数/勝敗/合否] | [点数/勝敗/合否] | [合格ラインとの差] |
| 補助判定 | [根拠] | [根拠] | [説明] |
| 悪化防止 | [違反有無] | [違反有無] | [1つでも重大違反なら戻す] |

## レビュー担当に渡した材料

- A/B本文:
- 変更した1点:
- 主判定、測り方、合格ライン:
- 悪化防止:
- 実入力:
- 根拠データ:
- 本人実例または良例:
- 材料不足の有無:
- 材料不足がある場合の扱い:

## 入力ケース別の結果

| ケース | 種類 | A案 | B案 | 主判定 | 悪化防止 | 判定 |
|:---|:---|:---|:---|:---|:---|:---|
| 1 | 代表 |  |  |  |  |  |
| 2 | 代表 |  |  |  |  |  |
| 3 | 代表 |  |  |  |  |  |
| 4 | 既知失敗 |  |  |  |  |  |
| 5 | 境界 |  |  |  |  |  |

## 良くなった点

- [実本文を見て確認できた改善]

## 悪くなった点

- [実本文を見て確認できた悪化]

## 未確認

- [まだ確認できていないこと]

## 無効条件チェック

- A案あり:
- B案あり:
- 同一入力:
- 同一ルート:
- 変更点1つ:
- 合格ラインあり:
- 実本文提示:

## 最終状態

- 残した変更:
- 戻した変更:
- 検証:
- コミット:

## 次の1テスト

- 次に試す1点:
- なぜ次はこれか:
```

## 判定時の言い方

| NG | OK |
|:---|:---|
| 良さそうです | B案は主判定が改善しました。ただし悪化防止に引っかからないことも確認しました |
| チェックは通りました | チェックは通りました。実本文の比較では、改行は改善、口調は維持でした |
| いったん残します | 根拠がないため戻します。次は1点だけ変えて再テストします |
| A/Bは途中です | A/Bは未完了です。改善扱いにせず、エラー原因を先に直します |

## 文章生成で追加する観点

文章や投稿のA/Bでは、最低限以下を見る。

- その人らしさが残っているか。
- 改行、間、読みやすさが改善したか。
- AIっぽい決まり文句が増えていないか。
- 実例や生データが正しく使われているか。
- 指示されていない余計な要素が入っていないか。
