# 測定基準と合格ライン

プロ品質のA/Bは、「何を良くするか」を気分で決めない。編集前に、測る対象、測り方、合格ライン、悪化防止を文章で固定する。

## 1. プロ仕様の基本形

A/B計画は必ず次の形で書く。

```text
[変更点] を [Aの状態] から [Bの状態] に変えると、
[代表入力セット] に対して、
[主判定] が [合格ライン] まで改善し、
[悪化防止] が [許容ライン] を超えて悪化しない。
```

この形にできない場合、そのA/Bは開始しない。

## 2. 「何を良くするか」の定義

| 欄 | 必ず書く内容 | NG |
|:---|:---|:---|
| 現状の不具合 | A案のどこが、どの実物で悪いか | なんとなく弱い |
| 望む状態 | B案がどうなればユーザーにとって良いか | 良い感じにする |
| 主判定 | 勝ち負けを決める1つの観点 | 複数観点を同列に並べる |
| 測り方 | 数値、合否、5段階、横並び勝敗のどれで見るか | 基準なしで目視する |
| 合格ライン | 何点以上、何件中何件、どの差分なら勝ちか | 改善していればOK |
| 根拠データ | A/B本文、本人実例、外部実例、ログ、テスト結果 | 感覚 |

## 3. 入力セットの基準

代表入力は、実運用に近いものだけを使う。作り物の都合のよい例で代用しない。

| 種類 | 最低数 | 内容 |
|:---|:---|:---|
| 代表ケース | 3件 | 普段よく来る依頼や素材 |
| 既知の失敗ケース | 1件 | 今回問題になった実例 |
| 境界ケース | 1件 | 長文、素材不足、文体変更など崩れやすい条件 |

合計5件を基本にする。実データが足りず3件未満の場合は、結果を「改善確定」にしてはならない。3〜4件の場合は、全件で主判定が改善し、悪化防止が全て通った時だけ暫定採用にする。

## 4. 判定軸の作り方

| 種類 | 役割 | 数 | 合格ライン |
|:---|:---|:---|:---|
| 主判定 | 勝ち負けを決める | 1つ | 事前に決めた値を超える |
| 補助判定 | なぜ勝った/負けたか説明する | 1〜3つ | 判断材料。主判定の代わりにしない |
| 悪化防止 | ここが悪くなったら勝ちにしない | 2〜5つ | 1つでも重大悪化なら戻す |

主判定を複数にしない。複数ある場合は、A/Bを分ける。

## 5. 文章生成の初期基準

ユーザーが別の基準を指定していない時は、Hermesの文章生成A/Bでは次を初期基準にする。

| 観点 | 測り方 | 合格ライン |
|:---|:---|:---|
| 主判定 | A/B本文の横並び勝敗 | 5件中4件以上でB案が勝つ。3〜4件しかない時は全件でB案が勝つ |
| 5段階採点を使う場合 | 1=不可、3=最低限、5=実運用に残せる | 平均+1.0以上、かつ3点未満のケースなし |
| 本人らしさ | 本人実例3〜5件との比較 | B案がA案より近い。口癖だけの一致は無効 |
| 改行・余白 | 本人実例3〜5件とA/B本文の比較 | 意味の切れ目、段落量、空行の使い方がA案より近い |
| AI臭さ | 禁止表現、説明調、締めの定型化を見る | 新しいAI臭さが1件でも増えたら戻す |
| 生データ使用 | 指定された実例本文や一次情報を確認 | 抜粋、要約、別参照だけなら無効 |
| 余計な追加 | 指示外の設定変更、投稿、DM、リスクある外部共有、推測を確認 | 1件でも入ったら戻す |
| 実行ルート | 対象エージェントが実際の利用時と同じ入口から対象スキルを自立実行したログを見る | 検証者の手入力、工程ごとの修正指示、差し戻し文の注入で作った出力は無効 |

## 6. 合否の決め方

| 判定 | 条件 |
|:---|:---|
| 残す | 入力セットが有効、変更点が1つ、主判定が合格ライン以上、悪化防止が全て合格、実本文を提示済み |
| 戻す | 主判定が未達、A案より悪化、悪化防止に1つでも重大違反、AI臭さや本人らしさが悪化 |
| 無効 | A案なし、B案なし、同一入力なし、同一ルートなし、合格ラインなし、複数変更、実本文なし |

「主判定は良いが悪化防止が悪い」は勝ちではない。戻す。

## 7. 採点者とレビュー

本文作成者の自己判定だけで `ready` にしない。本文作成者は最大でも「暫定採用候補」まで。別担当、読者役、または独立レビューがある場合だけ最終採用にできる。

独立レビューが使えない時も、A/B本文、基準、本人実例、悪い例を横並びで出し、判断根拠を残す。

レビュー担当を使う時は、必ず次の材料を渡す。

| 材料 | 必須内容 | 足りない時 |
|:---|:---|:---|
| A/B本文 | 変更前と変更後の実本文 | 無効 |
| 変更した1点 | B案で何だけを変えたか | 無効 |
| 判定基準 | 主判定、測り方、合格ライン、悪化防止 | 無効 |
| 実入力 | A案とB案に渡した同じ入力 | 無効 |
| 根拠データ | 本人実例、外部良例、生データ、ログなど今回の判断材料 | 材料取得へ戻す |
| 実行ログ | 対象エージェントが対象スキル入口、必要工程、実例参照、品質判定を通った記録 | 無効 |
| 既知の失敗 | 今回直したい悪い実例 | 代表性不足として暫定または無効 |

レビュー担当は、材料不足を本文の言い換えで埋めてはいけない。
材料不足なら「無効」または「前工程へ戻す」と判定する。
レビュー担当が出せるのは、`残す / 戻す / 無効` とその根拠だけ。
新しい本文案を作る場合は、別のA/Bとして扱い、変更点を1つに固定し直す。
